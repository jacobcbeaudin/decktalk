How it works

One line, from the script to the film.

A markdown script, plain HTML slides and your voice, built into one mp4. A cue names a word or a phrase of the script, not a second on a timeline, so every picture lands where the voice says it, and an edit voices and records only its own section again. Five chapters show it on one line of Halfway, then one number changes in three files.

Install

Three lines to a first film.

The first line brings its own Python, so there is nothing to install before it, and nothing to sign up for. Chromium and ffmpeg arrive on the first build, which says so before it downloads them. The last line writes an mp4.

Once per machine

  1. $ curl -LsSf https://decktalk.ai/install.sh | sh
    Installs uv, then DeckTalk. It never runs sudo, and it is served from a URL so you can read it first. If the command is not found afterwards, open a new shell.

For each film

  1. $ decktalk init my-pitch
    Writes a whole working project rather than a stub: a three-section script, the cues, the slide page, decktalk.toml, .env.example, a .gitignore, the runtime and the KaTeX the page loads, an AGENTS.md, and six skills linked into .claude/skills so a coding agent can drive all of it. Nothing in it has to be deleted first.
  2. $ cd my-pitch && decktalk build --no-voice
    Recording runs in real time, so the build takes about as long as the film and a little more: 70 seconds on one M5 Pro, for the starter's 50 second video. It ends on the path of build/final/my-pitch.mp4, with placeholder narration and no key.

For your own voice, copy .env.example to .env, add an ElevenLabs key and a voice id, and build again. Any ElevenLabs voice works, including a clone of your own. ElevenLabs bills narration by the character, and the how page shows what one rebuild cost.

Chromium and ffmpeg are fetched by the build that needs them, one time per machine. decktalk install fetches them up front instead, for a Docker layer, a CI cache or a machine about to go offline, and on Linux it installs Chromium's system libraries, which is the one thing here that asks for sudo.

If you already have uv, uv tool install decktalk is the same install. Every project carries six skills, in twelve files, one skill each for the script, the slides, the cues, the build, the fixes and a revision, so a coding agent can write the files, read the JSON every command prints, and fix what it finds.
