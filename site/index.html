Every picture lands on its word, and you edit the video like a doc.

Before this, one wrong word meant editing, rendering and recording the whole thing again. DeckTalk builds one mp4 from a markdown script, plain HTML slides, and your cloned voice, so a video stays as correct as the text behind it. Change a sentence, and only that section is voiced again.

How it works

Update your video the way you update a doc.

Narration comes back with a time for every word, so a reveal follows a phrase rather than a second. DeckTalk builds the video from text you keep, so a changed sentence changes the video. Change a sentence, and only that section is voiced again. Follow one cue from the script to the frame.

01 WRITE
script.md
## 1. Open
A bowl. [beat] A ball. [beat]
Watch it step down on my
count. [beat] One. [beat]
Two, three. [beat]

A script in markdown

One heading starts one section. Bracketed directions are not spoken.

02 NARRATE
build/narration/01-open.words.json
{ "word": "One",
  "start": 4.485 }
cues.json
{ "cue": "1.1one",
  "on": "One" }

Your voice reads it

The voice comes back with the audio and a timestamp for every word. A cue names a spoken phrase, and DeckTalk resolves it to the second the word starts.

03 RECORD
deck/index.html
<g data-cue="1.1one"
   data-reveal="instant">
  <rect class="box full"/>
  <text>one</text>
</g>

Slides reveal on cue

Chromium records the plain HTML, and the page runtime shows each slide when its word is spoken.

04 ASSEMBLE
$ decktalk build
[cut ] 01 -> sections/01.mp4
[caps] 35 cue(s) -> srt, vtt
$ decktalk verify
cue         at  offset
1:1.1one  4.49  -10ms

Cut to the frame

ffmpeg cuts every section to the frame, so the box fills at 4.49 s, and mixes the sound. Then verify measures each reveal against its word, and in a build of the scaffold every measured reveal landed within one frame of it.

What you get

Built for the tenth edit, not the first take.

Every reveal is cut to the spoken word, and a build of the scaffold measured each one within one frame of its word. A changed sentence voices only its own section again. The whole video is text you keep in a repository, so you and your agent update it the way you update code. Six skills install with the project, so the agent already knows how.

[lead] 01 trim 1.440s

The cut is measured, not timed.

Each recording opens on a magenta cover until narration starts. The cut is measured from the frames, not from a timer.

[skip] 01-open.mp3 unchanged

An edit voices only what changed.

Each section's narration is cached by a hash of its text, voice, model, and settings. An edit synthesizes only the sections that changed, so you pay per change, not per build.

[mix ] 3 audio input(s)

The soundscape is optional.

Music ducks under speech, ambience beds and effects land on cues, and the mix meets streaming loudness. Every part is optional.

1:1.1one -10ms changed

Every reveal is checked.

Black or truncated recordings stop before assembly. A cue that cannot be found stops the build. A check proves each cue moved pixels.

.agents/skills/decktalk-cues

Your coding agent already knows it.

Six skills install with every project, one each for the script, the slides, the cues, the build, the fixes and a revision. Every command prints one JSON envelope an agent reads.

Who it is for

Videos that must stay correct when their source changes.

DeckTalk is not a video editor, a slide designer, or an avatar. You write the slides as HTML, DeckTalk draws none of the pictures, and the video it makes is an ordinary mp4 you can upload anywhere.

a developer educator

Technical tutorials

A viewer watches a walkthrough whose commands and screenshots match the version she just installed. When the library changes, you change the sentence and build again.

a founder

Product demos

A viewer sees the feature narrated over the screen it runs on, with every callout landing on the word that names it.

a teacher

Lessons

A viewer follows an explanation in which each idea appears as it is spoken, so nothing is read ahead.

a team

Also fits

Internal presentations and estimation walkthroughs run the same pipeline. Neither has a shipped example yet.

From install to a first video.

You need Python 3.12 or later. A build without voice is free, needs no account, and takes about a minute for the starter, because recording runs in real time. A voiced build needs an ElevenLabs API key and a voice id, and a full build of the starter spends about 400 characters of voice. Build it without voice first, and add your voice when you are ready.

$ uv tool install decktalk && decktalk install
$ decktalk init my-lesson && cd my-lesson
$ decktalk build --no-voice   # no key needed
$ decktalk build            # your voice
