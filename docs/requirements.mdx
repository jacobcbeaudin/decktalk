---
title: Requirements and costs
description: What DeckTalk needs on a machine, what it downloads, which commands spend money, and how the price is worked out.
---

Read this before you set up a machine, a container or a CI runner, and before your first voiced
build. It answers two questions: what has to be on the machine, and what a run costs.

## Platforms

DeckTalk runs on Linux, macOS and Windows, and records with headless Chromium on all three.

| Platform | How to install | Notes |
|---|---|---|
| macOS | `curl -LsSf https://decktalk.ai/install.sh \| sh` | The installer brings uv, and uv brings its own Python. |
| Linux with glibc | `curl -LsSf https://decktalk.ai/install.sh \| sh` | `decktalk install` also adds Chromium's system libraries, which is the one step that asks for a password. |
| Windows | `uv tool install decktalk` or `pipx install decktalk` | The one-line installer stops on Windows and points at uv. |
| Linux with musl | Unsupported | Playwright, which records the slides, publishes no musl wheels, so DeckTalk cannot resolve at all. |

On a musl system such as Alpine the installer stops before it installs anything and says why, rather
than leaving a page of resolver output to read. Build in a container from a Debian-based image, such
as `debian`, `ubuntu` or `python:3.13-slim`, and never from `python:3.13-alpine`. Debian is also
where Chromium's system libraries can be installed, because Playwright installs them with `apt-get`.

## Python

DeckTalk needs Python 3.12 or later.

The one-line installer never asks you to supply one. It installs uv if the machine has none and then
runs `uv tool install decktalk`, and uv fetches a Python of its own. `uv tool install decktalk` does
the same thing without the script. `pipx install decktalk` uses a Python that is already on the
machine, so that one is where the floor bites.

Seven packages come with DeckTalk: blake3, filelock, Playwright, Pydantic, Rich, tomlkit and Typer. Playwright ships
its own browser driver, so Node is not needed. KaTeX is not a dependency at all: the pinned release
ships inside the wheel, and `decktalk init` copies it into `deck/katex/`, so a project typesets its
equations with no network and no content delivery network.

## What DeckTalk downloads

Two tools, one time per machine, fetched by DeckTalk itself: headless Chromium to record the slides,
and ffmpeg with ffprobe to cut, mix and encode them.

The first command that opens a page fetches Chromium, and the first command that encodes fetches
ffmpeg. Each download is announced before it starts and reports its bytes as they arrive, and under
`--events` it is one `fetch` line per step on stderr. `decktalk doctor` reports on both and fetches
neither, and `decktalk doctor --fix` runs `decktalk install` to fetch what is absent.

| Download | Where it comes from | How it is checked |
|---|---|---|
| Chromium | Playwright's own download host, through `playwright install chromium`. The revision is the one this Playwright release expects, so nothing is pinned twice. | Playwright's own check. |
| ffmpeg and ffprobe | One pinned GPL build per platform, from a fixed URL. | Every archive is checked against a SHA-256 that DeckTalk records for it, before anything is unpacked. An archive whose digest does not match is discarded, and DeckTalk never falls back to it. |

DeckTalk pins no ffmpeg build for every platform. Where it pins none, it uses the `ffmpeg` and
`ffprobe` on PATH, and it refuses with a `TOOL` error naming both when there is no pinned build and
nothing on PATH either.

### Roughly how large

The browser is the large one. DeckTalk announces it as about 200 MB, which is what Playwright fetches
for the browser and its headless shell together. On macOS on Apple silicon that unpacked to 554 MB in
the cache. The pinned ffmpeg arrives as two archives of about 28 MB each on that platform
and unpacks to 125 MB. Budget a gigabyte of cache for a machine that records, and a few minutes on a
home connection for the first run.

### Where they land

Both land in one directory, Chromium in its `ms-playwright` folder and ffmpeg in its `ffmpeg` folder.

| Linux | macOS | Windows |
|---|---|---|
| `$XDG_CACHE_HOME/decktalk`, else `~/.cache/decktalk` | `~/Library/Caches/decktalk` | `%LOCALAPPDATA%\decktalk` |

It is per user, so a second project on the same machine downloads nothing. `tools.cache_dir` moves
the whole directory, browser and encoder together, and `decktalk doctor` names it as `cache`.
DeckTalk tells Playwright where the browser folder is on the download and on every launch, so a
`PLAYWRIGHT_BROWSERS_PATH` set in the shell is not used: set `tools.cache_dir` instead.

### What `decktalk install` is for

`decktalk install` makes both downloads up front and does nothing else. A second run names what was
already there and fetches nothing.

```console
decktalk install
```

No command needs it to have been run. It is worth running when you want the download to happen at a
time you choose:

- **A container image.** A `RUN decktalk install` layer is cached, so the download is not in every build.
- **A CI job.** One step to cache, and one place to read when a download fails.
- **A machine that will be offline.** Fetch everything while there is a network. After that, a build without voice needs no network at all.
- **Linux.** It is the one command that installs Chromium's system libraries, and therefore the one command that may ask for a password.

### The sudo step on Linux

On Linux, `decktalk install` passes `--with-deps` to Playwright, and Playwright installs Chromium's
system libraries with `apt-get`. It runs `apt-get` through sudo, or through `su root -c` when sudo is
missing, or directly when `install` is already running as root. If the distribution has no `apt-get`,
that step fails and `install` stops before it fetches ffmpeg.

Nothing else passes `--with-deps`. A build fetches Chromium without it, and therefore without sudo,
because a build runs unattended in a script or in CI, where a password prompt is a hang rather than a
question. On a Linux machine whose libraries are missing, the browser downloads and then will not
start, and the error says to run `decktalk install`.

### A machine that supplies its own tools

A machine with no admin rights, an index mirror or an intercepting proxy can still record. Each case
is one setting, and none of them changes the project.

| What the machine blocks | What to set |
|---|---|
| The package index | Point uv, pipx or pip at your mirror the way you already do. |
| The Chromium download host | `PLAYWRIGHT_DOWNLOAD_HOST`, as Playwright documents it. |
| The ffmpeg download | `[tools] ffmpeg` and `[tools] ffprobe`, naming two executables from one build. They override every other source, so nothing downloads a build. |
| A write to the per-user cache | `[tools] cache_dir`, which moves Chromium and ffmpeg together. |

The `[tools]` keys and `record.browser_path` are
[machine keys](/reference/configuration#keys-only-a-machine-may-set). They describe this machine, so
they go in its own settings file through `decktalk config set KEY VALUE --where machine`, and a
`decktalk.toml` that sets one is refused by name.

Every setting has an environment variable of its own, spelled `DECKTALK_<TABLE>_<KEY>`, so
`[tools] ffmpeg` is `DECKTALK_TOOLS_FFMPEG` and `[tools] cache_dir` is `DECKTALK_TOOLS_CACHE_DIR`.
`decktalk config explain tools.ffmpeg` prints the value that wins and the layer that set it, and its
`--json` lists every layer that sets the key.

If the machine already has an approved Chrome or Chromium, record with that one instead.

```console
decktalk config set record.browser_path "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --where machine
```

The pinned Playwright build is the reference build, and DeckTalk's timing limits are measured against
it. A browser of your own is supported and unverified, so measure a first film with `decktalk verify`
before you trust those limits on it.

`decktalk doctor` prints the Chromium revision and the ffmpeg build a run would use, so a machine's
owner can read what a recording will launch before it launches. [What leaves your
machine](/reference/what-leaves-your-machine) is the whole list of hosts DeckTalk contacts.

### How hard a machine is driven

Four keys say how much work this machine takes on at once and how long it waits. They describe the
machine rather than the film, so they are machine keys like the ones above.

| Key | Default | What it decides |
|---|---|---|
| `record.concurrency` | `0` | How many page sections `record` records at once. Zero chooses from the CPU this process may use: one recording per two CPUs, at most four, and one on Windows. Inside a container that is the container's CPU quota, not the host's core count. |
| `narration.concurrency` | `2` | How many sections `narrate` voices at once. |
| `narration.retries` | `3` | How many more times `narrate` asks when the voice answers that it is busy or failed, which is an HTTP 429 or a 5xx. A busy answer is retried and never paid twice. |
| `tools.timeout_seconds` | `600` | The longest one ffmpeg or ffprobe call may run before DeckTalk stops it. |

A recording needs its CPU on time, because a frame drawn late lands its reveal late. So
`record.concurrency` set above this machine's share costs correctness rather than only speed: a
starved recording stalls, or reports reveals that land after their words.

```console
decktalk config set record.concurrency 2 --where machine
```

A `decktalk.toml` that sets any of the four is refused by name, because a project travels and a
limit that suits one machine is wrong on the next:

```text
error[INPUT]: decktalk.toml: 'record.concurrency' is machine-scoped, so it belongs in this machine's file, where the machine that runs the build states what it runs.
  hint: Remove it from decktalk.toml and run `decktalk config set record.concurrency <value> --where machine`.
  docs: https://docs.decktalk.ai/reference/errors/INPUT
```

Each also has its environment variable, such as `DECKTALK_RECORD_CONCURRENCY`, which is how a job
sets one for a container it does not keep.

## A page someone else wrote

A deck is a web page, and its script runs in the Chromium that records it. On your own machine that
page is your own work, so by default it is trusted: it reaches the network the way it would in your
browser, and a font or a library it loads from another origin is reported as
[`PAGE_CDN_ASSET`](/reference/findings/PAGE_CDN_ASSET) rather than stopped.

A service that renders pages other people wrote cannot extend that trust, because a trusted page
reaches anything the machine can reach, a cloud metadata endpoint included. `[record] page_policy`
says how far a page is trusted. It is the machine's to set, so a project file that names it is
refused and a project someone else wrote cannot trust its own page.

| Value | What the page may do |
|---|---|
| `trusted` | The default. The page reaches the network as a browser would, through the machine's own proxy. |
| `untrusted` | Chromium runs with its sandbox on, and every request that is not for the project's own origin is refused, through every channel a page can open. |

```console
decktalk config set record.page_policy untrusted --where machine
```

Under `untrusted`, three things hold at once.

- **The sandbox is on, or nothing runs.** A Chromium that cannot start its sandbox is refused with a
  `TOOL` error. The run never falls back to a browser without one.
- **No request leaves the origin.** The page is served at the project's own origin, and a request for
  any other one is aborted before it reaches the network, whatever its scheme. The browser is also
  pointed at a proxy that answers nothing, and WebRTC may not send UDP past it, which closes the
  channels request routing never sees: a WebSocket, a DNS lookup and a WebRTC probe. The recording
  still names every host the page reached for, as `PAGE_CDN_ASSET`.
- **The browser environment is scrubbed.** Chromium is handed only the variables that say where a
  file, a display, a locale or a proxy is, so a key the host holds never reaches the process that runs
  a page's script. ffmpeg and ffprobe are handed the same set. This holds under `trusted` too.

The policy is read by every launch that opens a project's page, which is `record`, `check`,
`storyboard` and the poster `assemble` draws.

### The sandbox in a Linux container

Chromium's sandbox needs user namespaces. In a Linux container that takes two things, and a container
missing either one refuses an untrusted run.

- **A user other than root.** Chromium refuses its sandbox to root, so run the render as an ordinary
  user.
- **A seccomp profile that allows user namespaces.** Docker's default profile blocks the calls the
  sandbox makes. A render running as an ordinary user under the default profile is still refused, and
  the same render under a profile that allows those calls launches.

The refusal names both:

```text
error[TOOL]: could not launch Chromium with its sandbox on (...).
  hint: An untrusted page runs only inside Chromium's sandbox. In a container that means a user other than root and a seccomp profile that allows user namespaces.
  docs: https://docs.decktalk.ai/reference/errors/TOOL
```

The engine's refusal is defence in depth. A service that renders strangers' pages still runs each
render in a network namespace with no egress of its own, because the machine is where the boundary
belongs.

## What a voiced run needs

A build without voice needs no account, no API key and no network once the tools are on the machine.
A build voiced by ElevenLabs, the cloud voice, needs two values from ElevenLabs. The local voice,
`dtsp`, needs only `[voice] id` and a server on this machine, and no key.

| Value | What it is | Read by |
|---|---|---|
| `ELEVENLABS_API_KEY` | Your API key. This is the credential. | a voiced build, `decktalk narrate`, `decktalk soundscape` |
| `[voice] id` | The id of the voice to speak in. It is a published name rather than a secret. | a voiced build, `decktalk narrate` |

Put the key in `.env` beside `decktalk.toml`, or export it. A variable already in the environment
wins over the file, and a value that still starts with `<`, such as `<your-elevenlabs-key>`, counts
as unset, so `.env.example` as it ships approves nothing.

The voice id is `[voice] id` in `decktalk.toml`, and `DECKTALK_VOICE_ID` in the environment overrides
it for anyone who keeps it out of the file. It is committed with the project because it grants
nothing: a voice cloned on an ElevenLabs account is usable only with that account's key.

DeckTalk never prints the key. No value read from `.env` or from the environment reaches a `--json`
payload, a log line or an error message, and an error that quotes a reply from the service has every
credential in it replaced before the quote is cut to length. `decktalk doctor` reports whether the
key is set and never what it is.

## What spends and what does not

Two things call ElevenLabs. The `narrate` stage sends each section's text and gets speech back, and
`decktalk soundscape` generates the music, the ambience bed and the effects.

| Command | When it spends |
|---|---|
| `decktalk build` | When the run is voiced. It voices each section whose text or voice settings changed, and every section when the cache is empty. |
| `decktalk narrate` | The same sections as a build, for that stage alone. |
| `decktalk soundscape` | For each part whose request changed or whose file is missing. |

No library or command call spends without approval. On the command line the flags are `--no-spend`, which plays every take on disk, writes
placeholder narration where a take is missing and calls nothing, `--spend`, which approves the spend,
and `--max-cost N`, which puts a ceiling on it. With neither flag, a build with something to buy
prices the run and asks on a terminal. Without a terminal it refuses and names the two flags that
answer, so a script or a CI job cannot spend by accident. A build whose takes are all on disk buys
nothing, so it asks nothing and reads no key.

Everything else spends nothing: `init`, `install`, `doctor`, `status`, `check`, `words`,
`storyboard`, `serve`, `config`, `schema`, `cue`, `record`, `assemble`, `verify`, `clip`, and any
`build` with `--no-spend`.

A voiced section costs the characters of its whole text, so an edit costs every changed section in
full rather than the changed sentence. The starter's three sections are 476 characters and make 50
seconds of film, which is the order of magnitude to expect: a script is cheap and a long film is a
few thousand characters. `decktalk check --json` gives the exact figure for your own script. A take
is named by the hash of its text and its voice settings, so an unchanged section is read from the
cache and a new voice id voices every section again.

<Warning>`--replace-voiced` with `--spend` voices a section again and plays the new take in place of
the one you paid for. It is the one flag on `build` that buys words you already own.</Warning>

## How the price is worked out

One key sets the rate, and one command reports the price.

```toml decktalk.toml
[elevenlabs]
price_per_1000_characters = 0.30
```

ElevenLabs declares that it bills per character, so `elevenlabs.price_per_1000_characters` is what your
plan charges per thousand characters. Its default is `0.0`, because DeckTalk does not know your plan
and will not invent it. Each voice declares how it bills, per character, per second of audio, or
free, and the key its rate is set under, and the price is worked out the way it declares.

`decktalk check` prices a voiced run without calling anything, and its result carries a `Spend`.

```console
decktalk check --json
```

```json
{
  "state": "estimate",
  "sections": [1, 2, 3],
  "characters": 476,
  "seconds": 31.2,
  "dollars": 0.14,
  "ceiling_dollars": 0.14,
  "billing": "per_character",
  "price_per_1000_characters": 0.3,
  "price_per_second": 0.0,
  "price_key": "elevenlabs.price_per_1000_characters",
  "averaged": false,
  "price_layer": "project"
}
```

- `state` is `estimate` for what a run would cost and `charged` for what one did cost.
- `sections` are the sections the price covers, in script order.
- `characters` is what would be sent, and `seconds` is how long the takes are expected to run.
- `billing` is how the voice declares it bills: `per_character`, `per_second`, `free`, or
  `undeclared` for a voice a host registered itself. A build's total is `mixed` when it adds
  characters of speech to seconds of sound, and then carries both rates.
- `dollars` is the characters or the seconds the bill counts, at the stated rate.
- `ceiling_dollars` is the most the run can reach.
- `price_per_1000_characters` or `price_per_second` is the rate, whichever the bill is counted in.
- `price_key` is the key that states the rate, or null for a voice with no rate to state.
- `averaged` is true when the price is several rates together, such as a soundscape's music and
  effects, so the rate is their average and `price_key` names the one least surely stated.
- `price_layer` names which of the five settings layers set the rate, where `default` means nobody did.

`dollars` and `ceiling_dollars` differ when a section's cache cannot be checked. A take is named by
its text and its voice, so with no `[voice] id` named no take on disk can be matched to the
voice that made it: each unmatched section's characters go into the ceiling and none of them into
the price. The key is not needed to price a run, because the price never asks the voice anything.

Every surface that states a price states one sentence, which keeps the certain part and the ceiling
apart.

| When | The sentence |
|---|---|
| Every section is priced for certain | `This run costs $0.14 for 476 characters at $0.30 per 1,000 characters.` |
| Some sections could not be matched | `This run costs $X for the sections that certainly need a take, and up to $Y if the takes that could not be matched to a voice need one too, at $0.30 per 1,000 characters.` |
| No section could be matched | `The takes on disk could not be matched to a voice, so this run costs up to $0.14 at $0.30 per 1,000 characters.` |
| Nothing needs a take | `This run buys nothing.` |
| The voice declares itself free | `This run voices 476 characters for nothing, because the voice is free.` |
| After a voiced run | `This run spent $0.14 on 476 characters at $0.30 per 1,000 characters.` |

### The ceiling

`--max-cost N` is compared against `ceiling_dollars` and never against `dollars`, because credits are
consumed one request at a time and a cap that claimed to stop a run halfway would be a lie. It is
checked before the first paid call, so a run it refuses has bought nothing.

```text
error[APPROVAL]: This run costs $0.14 for 476 characters at $0.30 per 1,000 characters. The most it can cost, $0.14, is over the $0.05 ceiling --max-cost set.
  hint: Raise the ceiling to --max-cost 0.14, or narrow the run with --section.
  docs: https://docs.decktalk.ai/reference/errors/APPROVAL
```

`--max-cost` also refuses while the price is still the default, before it compares anything.

```text
error[APPROVAL]: --max-cost was given and nothing states the rate this run buys at, so the cap would guard a made-up price.
  hint: Set elevenlabs.price_per_1000_characters to what your plan charges, then run it again.
  docs: https://docs.decktalk.ai/reference/errors/APPROVAL
```

A default is an assumption rather than what your plan charges, and a cap worked out from an
assumption would let a run through at a price nobody stated. State the rate and the cap means
something. [Error codes](/reference/errors/APPROVAL) covers every refusal of this kind.

### ElevenLabs plans

Every ElevenLabs plan can call the API, including the free one, so DeckTalk works on any of them.
What differs is what you may do with the audio: ElevenLabs' free tier carries no commercial license
and attaches attribution and voice-library conditions to anything you publish. Those are their terms
rather than DeckTalk's, so read the plan page before you publish a film, and start on a paid plan if
you intend to.

## Time

Recording runs in real time, so a section takes as long to record as it plays. Several page
sections record at once, as many as `record.concurrency` allows, so a film of several sections
records in about the time of its longest few rather than of all of them end to end. The starter's
build without voice took about 27 seconds in all on a MacBook Pro with an Apple M5 Pro and 64 GB of
memory, on a machine that already had Chromium and ffmpeg, and the film it made is 50 seconds long.
Most of that is the recording.

[Rebuild one section](/guides/rebuild-one-section) shows how to record only what changed.

## The ffmpeg license

The ffmpeg builds DeckTalk downloads are GPL builds. DeckTalk runs ffmpeg as a separate process and
does not link against it.
[THIRD_PARTY_NOTICES.md](https://github.com/jacobcbeaudin/decktalk/blob/main/THIRD_PARTY_NOTICES.md)
names each build and its license. To use a build of your own, set `[tools] ffmpeg` and
`[tools] ffprobe` to its two executables.
