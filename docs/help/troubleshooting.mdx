DeckTalk answers in codes. Every error code and every finding code carries its own page, and this
page is the map from what you saw to which code it was.

Each code's page carries its sentence, its severity and the settings keys that move it. They are
generated from the same enums the tool prints from, so they are the authority on what a code means.
This page is the other half: what the symptom looks like, which command to run to make the code
appear as data, and what to change.

## The two kinds of answer

An **error** means DeckTalk could not run, so nothing was judged. It prints one block and the command
stops.

{/* sample: words-not-built, decktalk words, on a fresh decktalk init my-lesson, which exits 3 */}
```text
error[NOT_BUILT]: takes.json has not been built.
  hint: Run `decktalk narrate` first, or `decktalk narrate --no-spend` to spend nothing.
  docs: https://docs.decktalk.ai/reference/errors/NOT_BUILT
```

A **finding** is a judgement DeckTalk made about your files or your film. The command ran, and this
is what it measured. It prints its own sentences, then one line per judgement, then one count line.

{/* sample: cues-file-missing, decktalk check, on a fresh decktalk init my-lesson with cues.json deleted, which exits 1 */}
```text
No voice is named, so no take on disk can be matched, because [voice] id is empty and DECKTALK_VOICE_ID is not set.
Checking script.md, deck/index.html.
This run costs $0.15 for 476 characters at $0.30 per 1,000 characters.
cues.json: CUE_UNLISTED the deck declares 12 moment(s) and there is no cues.json, so nothing gives any of them a second.
  fix (safe): Write cues.json with a row for each of the 12 moment(s) the deck declares, each waiting for the words you write in its `phrase`.
Found 1 finding, 1 error. 1 fixable with --fix.
```

The line opens with the file and the line number when the finding knows them, and with the object it
judges when it does not. The `fix` line under it appears only when the finding carries one.

Under `--json`, `error` is filled for the first and null for the second, and `findings` carries the
second as an array of objects.

An error exits 2 or 3, or 130 when the run was interrupted, and a finding at or above the threshold
exits 1.
[Exit codes](/reference/cli#exit-codes), [Error codes](/reference/cli#error-codes) and
[Finding codes](/reference/cli#finding-codes) list all of them in one place.

## The three commands to run first

| Command | What it answers |
|---|---|
| `decktalk doctor` | Whether this machine has Chromium, ffmpeg, ffprobe and KaTeX, and whether an API key is set. |
| `decktalk status` | What is written, what is built and what is stale in this project. |
| `decktalk check` | Whether `script.md`, `cues.json` and the pages hold together, and what the narration of a voiced run would cost. |

None of the three produces a film and none of them spends. `decktalk check --no-pages` goes further
and opens no browser at all, which makes it the one to run on a machine with no Chromium and inside a
commit hook. It names every judgement it could not reach rather than passing quietly.

{/* sample: check-no-pages-skipped, decktalk check --no-pages, on a fresh decktalk init my-lesson, the line about what it skipped */}
```text
no page was opened, so these judgements were not reached: CUE_UNLISTED, CUE_UNKNOWN, CUE_OVERLAP, PAGE_MOTION_OVERRUN, PAGE_STAGGER_OVERRUN, PAGE_NO_DESCRIPTION, PAGE_SWAP_APART, PAGE_CDN_ASSET, CUE_NO_CHANGE, CUE_THIN_CHANGE, PAGE_THIN_DRAW, CUT_POP.
```

`decktalk check --no-frames` keeps the browser and drops the freeze comparison, which is the faster
half when you only want the reading of the files and the page.

## Apply the fix a finding carries

A finding may carry a `fix`. It is one of three kinds, and it declares how far it may be trusted.

| Kind | What it is |
|---|---|
| `edit` | One or more changes to files, each naming exactly one of a JSON pointer, a TOML key or a line. |
| `setting` | A settings key and the value that clears the judgement. |
| `command` | The whole command line to run, one argument per element. |

| Applicability | What happens |
|---|---|
| `safe` | `--fix` applies it. It cannot lose your work. |
| `unsafe` | It is printed and never applied by `--fix`, because applying it could lose your work. |
| `display` | Only a person can make this change, so it is printed for you to make by hand. |

`decktalk check --fix`, `decktalk doctor --fix` and `decktalk build --fix` apply every safe fix and
print every other one. `--no-fix` applies none. In the library it is
`Project.apply(finding, unsafe=False)`, and passing `unsafe=True` is the only way an unsafe fix is
ever written.

The count line tells you before you run it: `Found 1 finding, 1 error. 1 fixable with --fix.`

A safe fix does the boring part and leaves the judgement to you. `check --fix` on a project with no
cue file writes every row the deck declares with an empty `phrase`, so the next `check` reports a
`CUE_UNRESOLVED` for each empty phrase and a build stops at `cue` on them. That is the fix working.
Fill in the phrases and run it again.

## Carry on past a code, or change what fails a run

`--allow CODE` carries on past one code, and `--fail-on` chooses which severity fails a run.
[Which findings fail a run](/agents/json#which-findings-fail-a-run) is the table of both.

`build` also stops on what fails it. When a stage inside a build judges something at the `--fail-on`
threshold, the build stops after that stage rather than carry the finding into the film, because a
film that is wrong in a way nobody has to watch it to discover is not worth recording. The stages it
did not reach are reported as skipped, and the run still returns everything it knows: it exits 1,
its findings are printed and in the JSON, the money narrate already spent is in `cost`, and
`stopped_at` names the stage it stopped after.

{/* sample: build-stopped, decktalk build --no-spend, on a fresh decktalk init my-lesson whose cue 3.1:idea waits for "a phrase nobody says", which exits 1 */}
```text
run 9227734468d0, events build/events/9227734468d0.jsonl
     Narrate    0:00
         Cue    0:00
Cue made 1 finding that the build stops on, so the build stopped before record rather than carry it into the film.
      Record    0:00   skipped
       Score    0:00   skipped
    Assemble    0:00   skipped
      Verify    0:00   skipped
     Stopped at cue, $0.00, 4 findings
script.md: TAKE_MISSING Section 1 plays a placeholder, because it has no voiced take yet. Run decktalk narrate --section 1 --spend to buy its take.
script.md: TAKE_MISSING Section 2 plays a placeholder, because it has no voiced take yet. Run decktalk narrate --section 2 --spend to buy its take.
script.md: TAKE_MISSING Section 3 plays a placeholder, because it has no voiced take yet. Run decktalk narrate --section 3 --spend to buy its take.
cues.json:30: CUE_UNRESOLVED the cue 3.1:idea waits for 'a phrase nobody says' and section 3 speaks 25 words, none of which is that phrase.
Found 4 findings, 1 error.
```

The three `TAKE_MISSING` lines are warnings, so they do not stop the build. The one error does.

The two flags that decide what fails a run decide what stops a build, because a build that carried
on past a finding its exit fails on would spend on a film already called wrong.

- `--allow CODE` carries the build past that code, and it works for every code. The finding is still
  printed and still in the JSON, and it no longer stops the build or counts toward the exit.
- `--fail-on warning` stops on a warning as well, and `--fail-on never` runs every stage
  whatever it finds.

`verify` is the last stage, so its findings end a build rather than stop it. Reach for `--allow` only
for a code you mean to keep, and say why, because the film it lets through carries that finding.
A cue a deck under construction has not drawn yet is the usual case:

```console
decktalk build --no-spend --allow CUE_UNKNOWN
```

## A missing toolchain

DeckTalk needs Chromium to record a page and ffmpeg with ffprobe to measure, cut and encode. It
fetches both the first time a command needs them and keeps them in a per-user cache.

**What you see.** `error[TOOL]` when a command needed one of them and could not run it, or a
`FILE_MISSING` finding from `doctor` for each component this machine has not got.

**What to do.**

1. Run `decktalk doctor`. It prints a row per component with its version and where it came from. On
   a terminal it then offers once to fetch what is missing, and with `--no-input` it fetches nothing.
2. Run `decktalk install`, or `decktalk doctor --fix`, which applies the safe `command` fix that
   each `FILE_MISSING` carries. Both fetch the toolchain up front rather than in the middle of a
   build.
3. On Linux, `decktalk install` also asks Playwright for Chromium's system libraries, which it
   installs through sudo, so it may ask for a password. A build never does that, because a build
   runs unattended and a password prompt is a hang rather than a question. That is why a Chromium
   that will not launch says to run `decktalk install`.

**The settings.** `[tools] ffmpeg` and `[tools] ffprobe` name binaries the machine already has.
`[tools] cache_dir` moves what DeckTalk fetches, Chromium and ffmpeg together. `[tools] chromium` records with a browser the
machine already has and skips the Chromium download entirely. All four are machine keys, so set them
with `decktalk config set KEY VALUE --scope machine`, because a `decktalk.toml` that sets one is
refused. Set
`PLAYWRIGHT_DOWNLOAD_HOST` to a mirror when a proxy blocks Playwright's own host, and set
`[tools] cache_dir` when the home directory is read-only or the browser is shared.

`FILE_MISSING` is also what a stage raises when a file the project names is not on disk, such as an
audio file of your own that a `[[mix.effect]]` row cues or a clip a section names. There the fix is
to write the file or correct the path. A sound the score describes and has not bought yet is
[`SOUND_MISSING`](/reference/findings/SOUND_MISSING) instead, a warning that plays silence in its
place, and `decktalk score --spend` buys it.

## A refused command line

Exit 2 means DeckTalk refused before doing anything, and a retry of the same line is refused again.

**`USAGE`.** The parser refused the line. The message names what is wrong with it. Run
`decktalk <command> --help`, or `decktalk schema` for the whole instruction set as one JSON object.

**`APPROVAL`.** A run that would spend money was not approved. `narrate` and `score` are the two
stages that spend. A run with nothing to buy is never asked, so a project whose takes are all on disk
builds with no flag and no key.

| What you want | What to pass |
|---|---|
| No buying at all | `--no-spend`, which plays every take on disk and a placeholder with real word times wherever a take is missing |
| Spend without being asked | `--spend` |
| Spend up to a ceiling | `--max-cost N`, which refuses before the first call when the most the run could cost is over N US dollars |
| Know the price first | `decktalk check`, which prices the narration and buys nothing, and `decktalk score --no-spend` for the sound |

`--no-input` never prompts. It takes the safe default, or it refuses and names the flag that would
have answered, which is what makes a non-interactive run deterministic.

In the library there is no terminal to ask, so nothing spends without `spend=True`, and
`ApprovalRequired` is raised rather than money being spent.

## A stage run before the one it reads

**What you see.** `error[NOT_BUILT]`, naming the file that is not there and the command that writes it.

{/* sample: words-not-built-again, decktalk words, on a fresh decktalk init my-lesson, which exits 3 */}
```text
error[NOT_BUILT]: takes.json has not been built.
  hint: Run `decktalk narrate` first, or `decktalk narrate --no-spend` to spend nothing.
  docs: https://docs.decktalk.ai/reference/errors/NOT_BUILT
```

Each stage reads what an earlier stage wrote, so a stage run on its own before that one fails here.
Run the command the hint names, or run `decktalk build`, which runs every stage in order.
`decktalk narrate --no-spend` writes the takes without buying anything, with a placeholder wherever a take is missing. `decktalk status` names the
next command to run.

## A voice that did not answer

**What you see.** `error[PROVIDER]`, with the HTTP status and the host when ElevenLabs answered, or
the reason when it could not be reached.

**What to do.**

1. Read the status in the message. A 401 is a key ElevenLabs does not accept, and a 429 or a 5xx is
   ElevenLabs being busy, which a later run usually gets past.
2. Run the same command again. Each take is written to the takes directory as soon as it is voiced,
   so the sections already voiced are found on disk and the run pays only for the rest. When the
   message says the request was possibly charged, its reply broke after it was sent, so check the
   account's usage first: running again buys that take once more.
3. A key that is not set at all is not this code. It is an `INPUT` error naming
   `ELEVENLABS_API_KEY`, raised before any request is sent.

## A locked project

**What you see.** `error[LOCKED]`, naming the process and the run that holds the directory, with the
hint to wait for that run or stop it.

One writing run at a time holds an operating system lock on `build/.lock`. While it holds it,
`build/.lock.owner` names its process id and its run id. A second writing run is refused rather
than allowed to overwrite the first one's work.

**What to do.**

1. Find the run named in the message. It is usually a `--watch` build in another terminal.
2. Let it finish, or stop it. The system releases the lock the moment the run ends, including when
   it is killed. The empty file stays in `build/`, and that is expected.
3. A lock is never left behind by a process that is gone, because the lock belongs to the process
   and not to the file. When a killed run left `build/.lock.owner` behind, the next run takes the
   lock, prints a warning saying so, and carries on. Deleting the file is never needed.
4. To read the project while a build is running, use `decktalk status` or
   `decktalk check --no-pages`. Neither writes, so neither takes the lock.

The same code names the take store when the message says another run has been voicing a take into
it. Two projects on one machine that need the same take buy it once: the second waits for the
first, and is refused when the wait passes `narration.store_wait_seconds`. Let the other run finish,
then run this again, and it copies the take in rather than buying it.

## An unresolved cue

A cue is one thing written in two files. The page declares a moment with a cue name, and `cues.json`
carries its [cue id](/concepts/cues#the-cue-id), such as `4.1:expand`, in its `id` field. Four codes
say which half is missing.

| Code | Which half is missing | Where the change goes |
|---|---|---|
| [CUE_UNLISTED](/reference/findings/CUE_UNLISTED) | The page's half exists and the file's does not. | Add the row to `cues.json`, or let `--fix` add it. |
| [CUE_UNKNOWN](/reference/findings/CUE_UNKNOWN) | The file's half exists and the page's does not. | Draw the element, correct the id, or delete the row. |
| [CUE_UNRESOLVED](/reference/findings/CUE_UNRESOLVED) | Both halves exist and the narration has no such phrase. | Change the row's `phrase`, or change the script. |
| [PAGE_CUE_UNKNOWN](/reference/findings/PAGE_CUE_UNKNOWN) | The deck declares no such cue at all. | Name the cue in a moment attribute on the slide, or take it out. |

**Reading `CUE_UNRESOLVED`.** The message names the phrase and how many words the section actually
speaks.

{/* sample: cue-unresolved, decktalk check --no-pages, on a fresh decktalk init my-lesson whose cue 1.1:title waits for "a phrase nobody says", the finding line */}
```text
cues.json:13: CUE_UNRESOLVED the cue 1.1:title waits for 'a phrase nobody says' and section 1 speaks 38 words, none of which is that phrase.
```

Run `decktalk words --section 1` to see every spoken word with its start and its end, which is the
clock a phrase is written against. Match the phrase to words that are really there. A phrase is
matched without case by default, and the row's own keys narrow it: `occurrence` picks which of
several matches to take, `case_sensitive` makes the match exact, `offset_seconds` moves the second the cue
fires, and `verify` set to false leaves the cue out of the measurement.

**Reading `CUE_STALE`.** `verify` measures the film on disk against the cue times the last build
placed. Edit `cues.json` and run `verify` alone, and the times no longer match the file:

{/* sample: cue-stale, decktalk verify, on a built starter rebuilt with 3.1:idea on "Change a word" and then set back to "the whole idea", the finding line */}
```text
cues.json: CUE_STALE cues.json asks for 3.1:idea on 'the whole idea' and the cue times hold a second placed for 'Change a word', so the cue times are older than cues.json and the film was cut to moments nobody asks for now. Run `decktalk build` to place them again.
```

The phrase is not the problem, so leave it alone. Run `decktalk build`. It places every cue again,
records only the sections whose cue times moved, and keeps the rest. `decktalk status` names `build`
as the next step for the same reason.

**Reading `CUE_UNLISTED`.** This one carries a safe `edit` fix that writes a row per declared moment
with an empty `phrase` for you to fill. On a `cues.json` laid out in a way DeckTalk cannot place a row
into, the fix is `display` instead and prints the rows for you to paste.

**Reading `CUE_UNKNOWN`.** When DeckTalk can see which cue the row was probably meant to be, it
offers an `unsafe` rename fix, which is unsafe because renaming an id the author typed is a reading
rather than a fact. `--allow CUE_UNKNOWN` carries a build past it, which is the usual choice for a
deck under construction that lists the cues of slides nobody has drawn yet.

**Which command sees what.** The `cue` stage compares `cues.json` against the catalog the page
published into its recordings, so a section whose page has never been recorded is left unjudged
rather than guessed at. `decktalk check` makes the same comparison against a page it opens live,
which is why a fresh project shows `CUE_UNLISTED` and `CUE_UNKNOWN` from `check` and not from `cue`.

`CUE_OVERLAP` is the neighbouring warning. It fires when two cues resolve close enough
together that one motion is still playing when the next begins, and the message says how far apart
they landed and how long the first was still running.

## A picture that does not change

A cue that resolves to a second means nothing if nothing on screen moves at that second. Three codes
measure that, all of them by comparing frames.

| Code | Severity | What it usually means |
|---|---|---|
| [CUE_NO_CHANGE](/reference/findings/CUE_NO_CHANGE) | error | The element never arrived, or it was already on screen before its cue. |
| [CUE_THIN_CHANGE](/reference/findings/CUE_THIN_CHANGE) | warning | The element arrived and it is too small for a viewer to notice. |
| [PAGE_THIN_DRAW](/reference/findings/PAGE_THIN_DRAW) | warning | A stroke that draws itself covers too little ground to be read as a change. |

**What you see.** The message carries the measured share of the frame and the floor it is under.

{/* sample: cue-no-change, decktalk check, on a fresh decktalk init my-lesson whose 1.1:title element is styled visibility: hidden, the finding line */}
```text
build/frames/01/freeze-1.1-after-1.1_title.png: CUE_NO_CHANGE freezing the slide either side of 1.1:title changes 0.00 percent of the frame, which is under the 0.10 percent floor, so the reveal would not be measured at all.
```

**What to do.**

1. Look at the two frames the message names. `decktalk check` writes a frame either side of every
   cue under `build/frames/`, and draws them all onto `build/storyboard.html`.
2. `decktalk storyboard --before 1.1:title --after 1.1:title` freezes just that pair, which is the
   fastest way to see what the reveal actually did.
3. Make the reveal bigger. A reveal that changes a few pixels is a reveal a viewer misses too, so
   the usual fix is on the page rather than in the settings.
4. Check the element really has a moment attribute and that its cue is the one that fired. An
   element that only changes class needs `data-class`, and a class change that animates needs the
   page's own stylesheet to do the animating.

**The settings.** `verify.changed_share_min_percent` is the floor, as a percentage of the frame.
`verify.thin_change_factor` is how many times that floor a change must cross to stop being thin.
`verify.probe_diff_luma` is the per-pixel luma difference that counts a pixel as changed, and
`verify.probe_delays_seconds` is when after the cue the frames are compared. `video.crf` moves all
three, because a harder compression smooths away small changes before anything measures them. Read
any of them whole with `decktalk config explain verify.changed_share_min_percent`.

## A recording that opens black or stalls

These three are measured against a recording rather than against a file you wrote. `record` measures
all three on the file it has just written, and `verify` measures `RECORD_BLACK` again on the finished
film.

| Code | Look at | The setting that decides it |
|---|---|---|
| [RECORD_BLACK](/reference/findings/RECORD_BLACK) | Whether the page had drawn anything by that second. | `verify.black_max_luma`, `verify.after_dip_seconds` |
| [RECORD_STALLED](/reference/findings/RECORD_STALLED) | Whether something on the page threw and stopped the drawing. | `record.frame_gap_max_ms` |
| [RECORD_TRUNCATED](/reference/findings/RECORD_TRUNCATED) | Whether the section's page was still working when its narration ended. | `record.truncated_slack_seconds` |

**Where the black usually comes from.** The recorder covers the page in magenta from its first paint
until the section clock starts, and takes the first clean frame after that run of cover frames as
the start of the section clock. When the scan finds no cover frames, the run falls back to the first painted frame plus the
settle, and failing that to `record.fallback_first_paint_seconds` plus the settle. It says so when it
does:

{/* sample: no-cover, decktalk record --section 2 --force --set record.cover_min_chroma=255, on a starter after narrate --no-spend and cue, the warning line */}
```text
Section 2 shows no cover, so the start of the section clock is a guess at 1.434s (the first painted frame and the settle), and every reveal in the section moves with it.
```

Treat that warning as the first thing to fix, because a guessed start moves every reveal in the
section together and every later code in that section is measuring against the wrong zero.

**Where a stall usually comes from.** Something on the page threw, so nothing drew after it. The page
reports that itself, through the probe, as one of these:

| Code | Which of your own code to open |
|---|---|
| [PAGE_RENDER_THREW](/reference/findings/PAGE_RENDER_THREW) | The slide's render. |
| [PAGE_ENTER_THREW](/reference/findings/PAGE_ENTER_THREW) | The slide's enter. |
| [PAGE_SLIDE_HANDLER_THREW](/reference/findings/PAGE_SLIDE_HANDLER_THREW) | That slide's own handler for the cue named in the message. |
| [PAGE_HANDLER_THREW](/reference/findings/PAGE_HANDLER_THREW) | The handler registered for the cue named in the message. |
| [PAGE_WAIT_REJECTED](/reference/findings/PAGE_WAIT_REJECTED) | Whatever the page asked the runtime to wait for, which rejected. |
| [PAGE_WAIT_UNSETTLED](/reference/findings/PAGE_WAIT_UNSETTLED) | The same wait, which never settled at all. |

**What to do.**

1. Run `decktalk serve` and open the page in your own browser. It serves the deck directory and the
   files `decktalk.toml` declares, and nothing else, so what you see is what the recorder sees. A
   declared file is reached only by the spelling `decktalk.toml` gives it, on every platform, so a
   page that asks for it with other capitals is refused.
   [Browser preview and recording](/concepts/page-contract#browser-preview-and-recording) says what
   the origin serves.
2. Read the browser console. These six codes are the page's own report from the browser, so the
   detail behind each one is there.
3. Run `decktalk check`, which opens the same page through the same probe without recording
   anything.
4. For a truncation, look at whether the section's page is still doing work when its narration ends.
   `record_margin_seconds` on a `[[section]]` records past the narration so the cut never lands on a
   frame that was never drawn.

## A late landing

The whole point of DeckTalk is that a picture arrives on its word. These codes are how it says a
picture did not.

| Code | Severity | What a viewer would notice |
|---|---|---|
| [CUE_OFF](/reference/findings/CUE_OFF) | error | The picture arrives on the wrong word, or visibly after the right one. |
| [CUE_NO_ONSET](/reference/findings/CUE_NO_ONSET) | warning | Nothing, yet. The measurement had no onset to work from, so the number is not trustworthy. |
| [CUT_SPEECH](/reference/findings/CUT_SPEECH) | error | A word is cut in half at a section boundary. |
| [CUT_POP](/reference/findings/CUT_POP) | error | The picture jumps at a boundary that promised to be seamless. |

**What to do about `CUE_OFF`.**

1. Read the number in the message. It says how far off the change landed and what the limit is.
2. A whole section that is late by the same amount is a machine bias rather than a deck problem. Run
   `decktalk doctor --measure`, which drives a browser to measure this host's presentation bias, and
   read the offsets the message names against that number.
3. One cue that is late on its own is usually a phrase that resolves to the wrong word. Run
   `decktalk words` and read what the section really says around it. Set `occurrence` on the row
   when the phrase repeats.
4. `offset_seconds` on a `cues.json` row moves one cue by a fixed number of seconds. Use it when the picture
   genuinely belongs slightly before or after its phrase, and not to paper over a phrase that
   matched the wrong place.
5. `verify.cue_offset_max_ms` is the limit, and `verify.av_offset_max_ms` is the audio against video
   limit beside it. Widening a limit hides the measurement rather than fixing the film.

**When the motion itself is the problem.** A cue can only be measured if the motion it starts is over
quickly enough to be read as a step. The ceiling is half a second, and three codes report going past
it.

| Code | What to shorten |
|---|---|
| [PAGE_MOTION_OVERRUN](/reference/findings/PAGE_MOTION_OVERRUN) | `data-in-seconds` on the element, or `motion.scale` for the whole render. |
| [PAGE_STAGGER_OVERRUN](/reference/findings/PAGE_STAGGER_OVERRUN) | `data-stagger`, or the number of children the container staggers. |
| [PAGE_APPEAR_TOO_LONG](/reference/findings/PAGE_APPEAR_TOO_LONG) | The line itself, or swap `data-words` from `appear` to `highlight`. |

[How long a moment may move](/concepts/page-contract#how-long-a-moment-may-move) gives the range of
`data-in-seconds` and `data-stagger` and the stagger's arithmetic, and `decktalk schema page` prints
every attribute with its range. `motion.scale` multiplies every declared length, so a value above one
is what pushes a deck that was fine over the ceiling.

**`CUT_SPEECH` and `CUT_POP`** are about the cuts rather than the reveals. A cut that slices a word
means the section's narration did not have room to finish, and `[narration] tail_seconds` is the
silence kept after the last word of a section so that a cut breathes.
`verify.cut_max_dbfs` and `verify.cut_window_seconds` are how quiet, and for how long, a cut has to
be to pass.

`CUT_POP` is measured only where a section declares `seamless = true`, which is the promise that its
picture continues the one before it. The last frame of the previous section and the first frame of
this one are compared, and more than `verify.cut_change_max_percent` of the frame differing means the
promise was not kept. Either make the two pictures actually continue, or drop the promise and let the
boundary be an ordinary cut, which `[transition]` dips through.

## A loudness miss

**What you see.** `MIX_LOUDNESS`, which is a warning, with the measured numbers in the message.

The mix is mastered to `audio.target_lufs`, with `audio.true_peak_max_dbtp` as the peak ceiling. The
defaults are -16 LUFS and -1.5 dBTP, which are ordinary values for video on the web.
`audio.range_max_lu` is the loudness range the measurement is made against, and no mix fails
on it. [Sound](/concepts/sound#loudness) says exactly when `MIX_LOUDNESS` is raised.

**What to do.**

1. Check whether the loudness pass ran at all. On a build with placeholder narration it does not,
   and the run says so.

   {/* sample: build-assemble-line, decktalk build --no-spend, on a fresh decktalk init my-lesson, the assemble line */}
   ```text
   The loudness pass is skipped because a take is a placeholder, so the soundtrack is encoded as it was mixed.
   ```

   Judge loudness on a voiced build.
2. A film that misses the target by a lot usually has a bed fighting the voice. `[mix] music_db`,
   `[mix] music_duck_db` and `[mix] ambience_db` are where that is settled.
3. Change the target only when you are mastering for a platform that asks for a different one. Read
   it whole first with `decktalk config explain audio.target_lufs`, which prints its range and
   the layer that set the value in force, and whose `--json` lists every layer that stated it.

## A page that loads an asset from a network origin

**What you see.** `PAGE_CDN_ASSET`, once per other origin the page reached for, naming that origin.

{/* sample: decktalk check, on a fresh decktalk init my-lesson whose page links https://fonts.example.com/inter.css, the finding line */}
```text
deck/index.html: PAGE_CDN_ASSET the page loaded an asset from https://fonts.example.com, which the project does not own, so the film depends on a host that may change or stop answering.
```

It is an error and it carries no fix, because only you can decide what the local copy should be.

**What to do.**

1. Download the asset into `deck/` and point the page at the local copy. A font, a stylesheet, a
   script and an image are all the same answer.
2. For equations there is nothing to download. DeckTalk serves the packaged KaTeX at
   `/__decktalk/katex/` on the page's own origin, so a page that links those two files loads nothing
   from a network.
3. Run `decktalk serve` and open the page. That origin serves the deck directory and the files
   `decktalk.toml` declares and nothing else, so anything the page still fetches from elsewhere is
   visible in the browser's network panel.
4. Keep the code if you mean it. `--allow PAGE_CDN_ASSET` carries a run past it, and it is worth
   writing down why, because a film that cannot be rebuilt in a year is what the code is warning
   about.

## A sandbox that will not start

**What you see.** `error[TOOL]: could not launch Chromium with its sandbox on`, on a machine whose
`[record] page_policy` is `untrusted`.

An untrusted page runs only inside Chromium's sandbox, and a machine that cannot start it is refused
rather than given a browser without one. The sandbox is a property of the machine, so no edit to the
project clears this.

**What to do.**

1. In a Linux container, run the render as a user other than root, because Chromium refuses its
   sandbox to root.
2. Give that container a seccomp profile that allows user namespaces. Docker's default profile does
   not, and a render as an ordinary user under it is still refused.
3. If the pages are your own work, the machine does not need the policy. `trusted` is the default,
   and `decktalk config unset record.page_policy --scope machine` returns to it.

Under `untrusted`, a request for another origin is refused rather than sent, so a page that loads a
font or a library from a CDN renders without it. The run still names that host as `PAGE_CDN_ASSET`,
and the fix is the one above: put the file beside the page.
[A page someone else wrote](/requirements#a-page-someone-else-wrote) says what the policy does.

## A page the contract refuses

These come out when `check` opens the page, and all but `PAGE_NO_DESCRIPTION` and
`PAGE_SWAP_APART` also when `record` does and again when `verify` reads the recording log. Most of
them the page reports about itself, through the probe, and the rest DeckTalk reads off the catalog
the page published. All of
them are about markup rather than about timing, so all of them can be cleared before a single credit
is spent. One of them, `PAGE_SWAP_APART`, is a warning, and the rest are errors because the
contract either declares a thing or it does not.

| Code | The change that clears it |
|---|---|
| [PAGE_ATTR_UNKNOWN](/reference/findings/PAGE_ATTR_UNKNOWN) | Spell the attribute the way `decktalk schema page` spells it, or take it off. |
| [PAGE_BAD_VALUE](/reference/findings/PAGE_BAD_VALUE) | Put the value back inside the published range, which the message quotes. |
| [PAGE_MOMENT_UNKNOWN](/reference/findings/PAGE_MOMENT_UNKNOWN) | Declare that cue on the slide the element sits in, or correct the name. |
| [PAGE_MOMENT_ORDER](/reference/findings/PAGE_MOMENT_ORDER) | Give the exit a cue that fires later than the entrance on the same element. |
| [PAGE_NO_OWNER](/reference/findings/PAGE_NO_OWNER) | Name the cue in a moment attribute, or list it in the slide's `data-owns`. |
| [PAGE_SCENE_EMPTY](/reference/findings/PAGE_SCENE_EMPTY) | Add a `<template data-slide>` to the scene, or remove the scene. |
| [PAGE_SLIDE_NO_ID](/reference/findings/PAGE_SLIDE_NO_ID) | Give the template a `data-slide` value. |
| [PAGE_SLIDE_DOUBLED](/reference/findings/PAGE_SLIDE_DOUBLED) | Rename one of the two, and rename its cues in `cues.json` with it. |
| [PAGE_SLIDE_UNUSED](/reference/findings/PAGE_SLIDE_UNUSED) | Have a section play its scene, or delete the slide. Pass `--allow PAGE_SLIDE_UNUSED` while a slide is still being wired up. |
| [PAGE_TEMPLATE_IGNORED](/reference/findings/PAGE_TEMPLATE_IGNORED) | Give the nested template its own `data-slide`, or take it out of the slide. |
| [PAGE_SWAP_AMBIGUOUS](/reference/findings/PAGE_SWAP_AMBIGUOUS) | Give the arriving element and the one it replaces a cue they share. |
| [PAGE_PREVIEW_AMBIGUOUS](/reference/findings/PAGE_PREVIEW_AMBIGUOUS) | Give the two sections different scenes. |
| [PAGE_STAGGER_EMPTY](/reference/findings/PAGE_STAGGER_EMPTY) | Give the container children, or take `data-stagger` off it. |
| [PAGE_SPOTLIGHT_EMPTY](/reference/findings/PAGE_SPOTLIGHT_EMPTY) | Give a child of the container a cue, or take `data-spotlight` off it. |
| [PAGE_WORDS_NOT_FOUND](/reference/findings/PAGE_WORDS_NOT_FOUND) | Make the element's text words the script really speaks in that section. |
| [PAGE_KATEX_MISSING](/reference/findings/PAGE_KATEX_MISSING) | Link `/__decktalk/katex/katex.min.css` and `/__decktalk/katex/katex.min.js`, which DeckTalk serves on the page's origin. |
| [PAGE_KATEX_ERROR](/reference/findings/PAGE_KATEX_ERROR) | Correct the TeX the message quotes. The element's own text is the fallback a reader sees meanwhile. |
| [PAGE_FREEZE_CUE_UNKNOWN](/reference/findings/PAGE_FREEZE_CUE_UNKNOWN) | Name a cue the slide declares in `--after` or `--before`. |
| [PAGE_CLASS_UNDESCRIBED](/reference/findings/PAGE_CLASS_UNDESCRIBED) | Add the matching pair to `data-describe-class`. |
| [PAGE_CLASS_NOT_REDUCED](/reference/findings/PAGE_CLASS_NOT_REDUCED) | Make your stylesheet honour `prefers-reduced-motion` for that class. |
| [PAGE_NO_DESCRIPTION](/reference/findings/PAGE_NO_DESCRIPTION) | Add `data-describe`, or add it empty to say the element is decorative. |
| [PAGE_SWAP_APART](/reference/findings/PAGE_SWAP_APART) | Move the two halves of the swap closer together. This one is a warning, because a deliberate jump is possible. |

**What to do.** Run `decktalk schema page`, which prints every attribute with their
values, their defaults, their ranges and their spans. It is generated from `contract.ts`, the one
home of every attribute, so it cannot disagree with what the runtime does. Then fix the markup.

Two of these are about the transcript rather than the picture. `PAGE_NO_DESCRIPTION` and
`PAGE_CLASS_UNDESCRIBED` mean a reader of the transcript loses a step the viewer saw, and
`data-describe` with an empty value is how you say an element is decorative and meant it.

`PAGE_CLASS_NOT_REDUCED` is about reduced motion. No flag duplicates a settings key, so reduced
motion is `--set motion.reduce=true` on any command that runs against the project, and it asks
Chromium for `prefers-reduced-motion`. The page's own stylesheet is what has to honour that query,
and this code says a class it adds still animates when nobody asked it to.

`PAGE_CLASS_UNDESCRIBED` is the other half of `data-class`. A class change is a change to the
picture, so `data-describe-class` gives each one a description, written as cue and description pairs
separated by a vertical bar, and the transcript prints it.

## A script that is not ready to be voiced

| Code | Severity | The change that clears it |
|---|---|---|
| [SCRIPT_UNFINISHED](/reference/findings/SCRIPT_UNFINISHED) | error | Fill in the unfinished text on the line the message names with the words you mean. |
| [SCRIPT_SPOKEN_SYMBOL](/reference/findings/SCRIPT_SPOKEN_SYMBOL) | warning | Write the symbol out as the voice must say it. |
| [SCRIPT_PAUSE_DROPPED](/reference/findings/SCRIPT_PAUSE_DROPPED) | error | Set `[elevenlabs] model` to one that renders `[pause N]`, such as `eleven_multilingual_v2`, or take the timed pauses out of the section. |

All three come from `decktalk check` reading `script.md`, so all three are free to find and all
three are found before a credit is spent. This is the cheapest check there is, and running it in a
commit hook with `--no-pages` costs nothing.

Run it before you voice anything. `narrate` refuses a comment, a brace or a bracket inside a
paragraph, and it lists every such line at once. It does not refuse an unfilled blank such as
`[NUMBER]`, so a voiced run reads it out. Only `check` reports that.

`SCRIPT_SPOKEN_SYMBOL` is a warning because sometimes you do mean the symbol. Write out what the voice
must say, and [Writing for the ear](/guides/writing-for-the-ear) is the guide for it.

`SCRIPT_PAUSE_DROPPED` names a section with a `[pause N]` on a model that renders no timed pause,
and `narrate` refuses to buy a take that would lose the pause. Move to a model that renders one, or
write a `[beat]`, which every model reads. [script.md](/reference/script-md#directions-and-placeholders) names the
models.

## A take that is missing

| Code | Severity | The change that clears it |
|---|---|---|
| [TAKE_MISSING](/reference/findings/TAKE_MISSING) | warning | Run the command the message names. For a provider that bills it is `decktalk narrate --section N --spend`. For a free provider that could not be reached, start its server, then run `decktalk narrate --section N`. |

A run with `--no-spend` plays every take on disk and puts a placeholder in each section whose take is
missing, which is one `TAKE_MISSING` per section. It is a warning because the film is still whole and
only that section's timing is estimated, so a draft build exits 0. Pass `--fail-on warning` to make a
missing take fail a run.

A take is found by its text, its voice, its model and its voice settings, so a section reports it after any of
those changed, and on a fresh clone whose takes were never committed. Without a voice id no voiced take
can be matched at all, and the run says so in one line before the findings. Set `[voice] id` in
`decktalk.toml`, which is a published name rather than a secret and is committed with the project,
and the takes on disk play again.

## When the answer is not a code

Some things are not judgements. Use the stream.

- `--events` prints one JSON line per event on stderr as it happens, and every run also appends
  `build/events/<run>.jsonl` whether you passed it or not. [The event stream](/agents/json#the-event-stream)
  names every line and its fields.
- `stage.done` and `section.done` carry an `outcome`, so a run that stopped early still says what it
  did not reach rather than leaving you to infer it from a shorter list.
- `events.keep_runs` prunes the oldest files, and its default is 20.
- `-v` puts debug lines on stderr and prints the traceback of a bug. `error[INTERNAL]` means a bug in
  DeckTalk, and `-v` is what turns it into something worth reporting.
- `decktalk status` reports where the project stands and what to run next.
