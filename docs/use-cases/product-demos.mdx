A viewer sees the feature narrated over the screen it runs on, with every callout landing on the
word that names it.

A demo ages faster than anything else a company publishes, because the product moves every week. In
DeckTalk the demo is text and code, so a renamed button is a one-line edit and a rebuild of the
section that shows it. Nothing else is recorded again, and nothing else is voiced again.

## What a viewer gets

- Each callout, arrow and highlight arrives on the word that names it, so the eye is never hunting
  for what the voice is talking about.
- Real product footage, because a section can be a video file of your own rather than a page.
- A cut with no dead air, because the film is cut to the narration rather than the narration fitted
  to the film.
- Captions, chapters, a transcript page and a poster frame, which a demo needs on a site where most
  viewers watch with the sound off.

## What the author writes

| File | What it holds |
|---|---|
| `script.md` | The pitch, one `## N. Title` heading per section. |
| `decktalk.toml` | The sections, the voice, and the `clip` key on any section that plays a video file of your own. |
| `cues.json` | The phrase each callout waits for. |
| `deck/index.html` | The title cards, the callouts and the closing card. |

A section is either a page section, which names a `page` and a `scene`, or a clip section, which
names a `clip` file instead. A clip section may also name a `words` file of the speech inside it, so
the captions carry those words too, and `seamless = true` says the clip continues the previous
section's picture, which `verify` then measures at the seam.

An effect lands on a cue through a `[[mix.effects]]` row, which names a `file`, a `section`, a `cue`
and an optional `caption` and `db`. `decktalk soundscape` is what generates those files, along with
the music bed and the ambience, from the prompts in `[soundscape.music]`,
`[soundscape.ambience]` and `[soundscape.effects.<name>]`. That stage spends, so it runs last and a
draft loop that stops at `record` never reaches it.

## The workflow

<Steps>
  <Step title="Write the pitch first">
    Write `script.md` before the slides, because the words decide the cuts. Read each section aloud
    once and keep it to one idea.
  </Step>
  <Step title="Draft it with no voice">
    `decktalk build --no-voice` gives a complete film on placeholder narration, which is enough to
    judge the pacing before anyone spends a credit.
  </Step>
  <Step title="Drop the product footage in">
    Add a clip section for each screen recording, then run `decktalk verify` to measure every seam
    between a page section and a clip section. `decktalk clip --section 3 --start 4 --end 9 --out
    build/callout.mp4` cuts a span of a built section into its own file when you need a short one
    on its own.
  </Step>
  <Step title="Look at the storyboard, then buy the voice">
    `decktalk storyboard` freezes every slide at every cue onto `build/storyboard.html`, and
    `decktalk check` prices the run. Then `decktalk build --spend` voices what needs it, with
    `--max-cost N` as the ceiling that refuses the run before the first call.
  </Step>
  <Step title="Rebuild the section the product change touched">
    Edit the sentence or the callout, then run `decktalk build --section 3`. Every other section
    keeps its take and its recording.
  </Step>
</Steps>
