The page declares a moment that cues.json does not list, so nothing gives it a second.

This finding is an error, and DeckTalk judges it itself. `decktalk check` reports it when it judges the project's files before a build, and `decktalk cue` when it resolves each cue phrase against the takes.
Pass `--allow CUE_UNLISTED` to carry on past it, and `--fail-on` to choose which severity fails a run.

## What to do

Add the row to `cues.json`, or run `decktalk check --fix`, which writes it with an empty `phrase` for you to fill.

Troubleshooting says more under [An unresolved cue](/help/troubleshooting#an-unresolved-cue).
