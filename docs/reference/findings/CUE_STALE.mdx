The cue times on disk were placed from a different cues.json than the project's, so the film is judged against moments nobody asked for until the project is built again.

This finding is an error, and DeckTalk judges it itself. `decktalk verify` reports it when it measures the finished film and reads back each recording log.
Pass `--allow CUE_STALE` to carry on past it, and `--fail-on` to choose which severity fails a run.

## What to do

Run `decktalk build`, which places every cue again and records only the sections whose cue times moved.

Troubleshooting says more under [An unresolved cue](/help/troubleshooting#an-unresolved-cue).
