A DeckTalk deck is an ordinary web page that includes one script.

```html deck/index.html
<script src="decktalk-runtime.js"></script>
```

`decktalk-runtime.js` is that script. It reads the markup, mounts the slides of a scene, and makes
each element arrive on the second its cue was given. `decktalk init` writes a copy of it into the
project's `deck/` directory, so a project carries the runtime it was made with and a build needs no
network to draw a page.

The runtime is written in TypeScript under `src/decktalk/runtime/src/` and compiled by esbuild into
one bundle. The page contract it is written against lives in exactly one file, and Python reads that
same contract, so what an author may write is one list rather than two that can disagree.

## The modules

Eleven modules make the runtime. Each owns one thing, and nothing imports the facade.

| Module | What it owns |
|---|---|
| `contract.ts` | The grammar: every attribute, every page code, every query key, the report field list and the two units. Nothing here touches the DOM. |
| `index.ts` | The facade. It reads the probe's telemetry sink once, hands it to the seam, and publishes `window.DeckTalk` and `window.__decktalk`. |
| `scene.ts` | Scenes, slides, the markup reader and the cue order every check is written against. It is the only module that reads markup. |
| `modes.ts` | The four things a page can be doing, and the one URL that decides which. It is the only module that touches the URL. |
| `reveal.ts` | The four moments, the class moment, the swap, and the sentence each of them writes into the transcript. |
| `stage.ts` | The stage a deck is drawn on, the fit into the window, the heads-up display and the one generated stylesheet. |
| `clock.ts` | The narration origin, the queue of work sorted by the second it is due, and the animation frame loop that drains it. It holds no DOM. |
| `text.ts` | The two effects that rewrite an element's own text, which are the count up and the line shown on the voice. |
| `katex.ts` | Typesetting, the wait for the typesetter, and the readable text an equation falls back to. |
| `telemetry.ts` | The seam between the page and the recorder, which is one interface, one no-op default and one setter. |
| `warn.ts` | Everything the page could not honour, recorded once each and echoed to the console. |

A twelfth file, `src/decktalk/runtime/src/probe/probe.ts`, is a bundle of its own. It imports the
contract and the telemetry seam and nothing else, which is what keeps the runtime free of everything
only a command needs.

## `contract.ts` is the one home

Every attribute an author may write lives in `contract.ts` with its values, its safe range, its
default, the code that is raised when it is wrong, and the seconds of motion it puts between its cue
and the next one. Every other runtime module reads its attribute names from there rather than
spelling a `data-` literal of its own.

Two rules decide what may live there. An attribute survives only when its value can change a
judgement or be named by a finding, and the five rows that do neither are listed in `EXEMPT` with
the sentence that says why. No span a page can declare may reach `MEASURABLE_SPAN_SECONDS`, because
an effect still moving half a second after its cue makes its own cue unmeasurable.

`src/decktalk/page.py` is generated from `contract.ts`, so Python and the page cannot disagree about
what an attribute means. It is vocabulary and arithmetic and nothing else: it opens no file, reads
no settings and imports nothing from the rest of DeckTalk, so every layer above it can read the
contract without a browser and without a project.

```bash
uv run decktalk schema page
uv run python -c "from decktalk import page; print(sorted(a.value for a in page.ATTRS))"
```

### Building the bundle

```bash
npm ci                                   # once, for the pinned esbuild, tsc and Biome
uv run scripts/build_runtime.py --write  # type check, bundle, and write every artifact
uv run scripts/build_runtime.py --check  # exit 1 if any committed artifact would change
```

The script is the only thing that reads the contract. esbuild builds `contract.ts` as a CommonJS
module, node prints `CONTRACT` as JSON, and every artifact is written from that JSON, so no regular
expression ever reads TypeScript. Each artifact is written through the formatter that owns its
language, the pinned Biome for JavaScript and the project's ruff for Python, so `--check` compares
two files that were made the same way.

Four artifacts are committed and held to their source by `--check`.

| Artifact | What it is |
|---|---|
| `src/decktalk/runtime/decktalk-runtime.js` | The bundle a deck loads. |
| `src/decktalk/runtime/decktalk-probe.js` | The bundle a command injects into every page it opens. |
| `src/decktalk/runtime/contract.json` | The intermediate, committed so everything after it is pure Python. |
| `src/decktalk/page.py` | The vocabulary the library and the command line read. |

A module reaches a bundle only by being imported from one of the two entry points, which is what
keeps the probe out of the runtime and the runtime out of the probe.

## What a page declares

A `[data-scene]` element declares a scene, and every `<template data-slide>` inside it declares one
slide, in document order. The wrapper never draws, and the runtime clones a template's content each
time its slide mounts.

An element has four moments, each naming a cue local to its slide. It arrives, it steps back, it
comes to the front, and it leaves. The runtime qualifies a local name into the wire id `cues.json`
carries, which is the slide id, a colon and the local name.

```html deck/index.html
<div data-scene="2" data-name="How it works">
  <template data-slide="2.1" data-hold="16">
    <h1 data-in="average" data-describe="the heading, the average of n numbers">The average of n numbers.</h1>
    <p data-in="formula" data-tex="\bar{x}=\frac{1}{n}\sum_{i=1}^{n} x_i" data-tex-display>
      the mean of n numbers
    </p>
  </template>
</div>
```

`data-in="formula"` inside `<template data-slide="2.1">` is the wire id `2.1:formula`, and that is
what `cues.json` gives a second to. No attribute writes a second: `cues.json` owns seconds and the
page owns what a thing looks like and what it means.

The twenty-four attributes, each with its values, its default, its range, its code and its motion
span, are published by `decktalk schema page`. Read that and write from it.

| Written on | Attributes |
|---|---|
| An element or a container | `data-in`, `data-describe`, `data-tex`, `data-tex-display`, `data-in-style`, `data-back`, `data-front`, `data-out`, `data-words`, `data-count`, `data-class`, `data-describe-class`, `data-stagger`, `data-steps`, `data-in-seconds`, `data-out-style`, `data-swaps`, `data-describe-out` |
| The scene wrapper | `data-scene`, `data-name` |
| A slide template | `data-slide`, `data-hold`, `data-owns`, `data-enter`, `data-describe` |

Three numbers bound every span a page may declare.

| Number | Value | What it is |
|---|---|---|
| `MEASURABLE_SPAN_SECONDS` | 0.5 | The one ceiling above which a cue cannot be measured, which is also the reduced-motion clamp and the stagger ceiling. |
| `CAPTURE_FPS` | 25 | The rate the recorder captures at, which is the rate Chromium paints a deck at. |
| `FRAME_STEP_MS` | 40 | One captured frame, which is the finest interval any range may name. |

`data-in-seconds` runs from 0.12 to 0.48 in steps of 0.04, which is three to twelve frames.
`data-stagger` runs from 0.04 to 0.2 in steps of 0.04, and a staggered container's whole span is the
step times the children less one, plus the entrance, which must stay under half a second.
[The page contract](/concepts/page-contract) explains how the parts work together.

## The query keys

Every key a DeckTalk page reads is published by the contract, and each is read once, in `modes.ts`,
so no other module ever touches the URL.

```bash
uv run python -c "from decktalk import page; print(page.QUERY)"
```

| Key | What it does |
|---|---|
| `scene` | Play this scene from its first slide. |
| `slide` | Freeze this slide with its cues already fired, which is what a still opens. |
| `cues` | The cue times to fire at, as `id@seconds` pairs separated by a comma. |
| `words` | The spoken words to sync a line against, as `word@seconds` pairs separated by a comma. |
| `t0` | The narration second the page starts at, or the word `signal` when the recorder starts the clock. |
| `speed` | Multiply the preview clock, so a long section is reviewed quickly. |
| `hud` | Draw the on-page clock and cue list, which is for an author and never for a recording. |
| `after` | Freeze after this cue, so the cues up to and including it fire and later ones stay hidden. |
| `before` | Freeze just before this cue, so it and every later cue stay hidden. |

`after` and `before` are read by the probe alone, so a page opened by hand at `?slide=2.1` shows
every reveal and ignores both.

## Modes

The URL picks one, and `window.__decktalk.mode` reports it.

| Mode | URL | What happens |
|---|---|---|
| `index` | No `scene`, `cues` or `slide`. | The page lists its scenes and slides. Every slide is laid out once in a hidden layer and measured, which is the catalog a judgement without a recording is read from. |
| `preview` | `?scene=N` | The scene plays at the speed a person reads it. The page asks the origin for the cue times the last run resolved and uses them, and falls back to one second per cue when there are none. |
| `cue` | `?cues=…` | The scene plays against the narration clock, which is the mode a recording is made in. |
| `freeze` | `?slide=ID` | One slide is drawn with its cues already fired and nothing in motion, which is what makes two frozen frames comparable. |

`slide` wins over `scene` and `cues`. With `cues` and no `scene`, the scene that owns the earliest
cue plays. `speed` divides preview time and its floor is 0.05. With `t0=signal` the clock waits for
`DeckTalk.startClock()`, which is what the recorder calls once its cover has come off.

## The `DeckTalk` object

A scene is markup, and a page that needs no behaviour needs no JavaScript at all. A page that wants
behaviour of its own drives this object.

| Member | What it does |
|---|---|
| `DeckTalk.version` | The runtime version this page carries. |
| `DeckTalk.scene(id, input)` | Declare one scene from script, for a deck that would rather build its slides than write them. It returns `DeckTalk`. |
| `DeckTalk.on(cue, fn)` | Run a function at one cue, wherever in the deck that cue belongs. It returns `DeckTalk`. |
| `DeckTalk.start()` | Read the page and start it, which a page that loads the runtime late may need to call itself. |
| `DeckTalk.startClock()` | Start the narration clock, which is what the recorder sends once its cover has come off. |
| `DeckTalk.waitFor(promise)` | Hold readiness until a promise of the page's own has settled. It returns `DeckTalk`. |
| `DeckTalk.scenes` | Every scene the page declared, which a deck reads to walk its own slides. |
| `DeckTalk.params` | The page's own query, for anything the contract does not answer. |
| `DeckTalk.findSlide(id)` | The scene and the slide with this id, or null when no slide carries it. |
| `DeckTalk.buildSlide(scene, slide)` | Build one slide's element without mounting it. |

```html deck/index.html
<script>
  DeckTalk.on("2.1:formula", (slide) => slide.querySelector(".rule").classList.add("run"));
</script>
```

A promise handed to `waitFor` never fails the page. One that rejects raises `PAGE_WAIT_REJECTED` and
one that has not settled after five seconds raises `PAGE_WAIT_UNSETTLED`, and the page is drawn
either way, because a deck that stopped at its first broken promise would cost a recording rather
than save one.

`window.__decktalk` is the live view whoever is reading the page back uses. Every field is a getter,
so a reader sees the page as it stands: `version`, `ready`, `mode`, `scene`, `slide`, `cues`,
`fired`, `warnings`, `catalog`, `frozen` and `signalled`. `now()` and `started()` are the clock's own
two functions, which say the narration second and whether the clock has begun.

## The probe

`decktalk-probe.js` is the instrumentation every command that opens a page needs and no deck
carries: a cover over the first paint so a recording starts on a known frame, a helper that says
when the page has settled, a measured catalog that says where every reveal sits, a freeze that stops
at one cue, and a record of how the page behaved while it was captured.

Playwright adds it with an init script, so it runs before the page's own scripts and no page ever
references it. It is never a `<script>` tag, and `decktalk init` never writes it. A page opened
without it plays, previews, freezes and lists its scenes exactly the same, and keeps nothing. Once
it is on the window it is frozen and made read-only, so a deck cannot take its name.

The recorder holds it as `window.__dtprobe`.

| Call | What it does |
|---|---|
| `cover()` | Draw the magenta cover and the keep-alive from the first paint. |
| `lift()` | Remove the cover and start the page clock on the next animation frame, resolving to the moment of that frame, which is the recording's narration t=0. |
| `ready()` | The page's fonts and `window.__decktalk.ready`, whichever exist. |
| `report()` | Everything the recorder reads back off the page, in one call. |

Three more are read by the runtime, and only when the probe is there: `recorder` is the telemetry
sink, read once at startup, `freezeCues(order, slide, warn)` narrows a frozen slide's cues to the
stop the URL names, and `measure(catalog, stage)` adds one measured box per element onto the
catalog.

### One `report()` call

`record` and `check` read what a page says about itself through this one call rather than through a
handful of evaluations, so what a command knows about a page is one snapshot taken at one moment.
Its fields are exactly `page.REPORT`.

```bash
uv run python -c "from decktalk import page; print(page.REPORT)"
```

| Field | What it carries |
|---|---|
| `version` | The runtime version the page carries. |
| `mode` | Which of index, preview, cue and freeze the page is in. |
| `scene` | The scene the page is playing, or null on the index page. |
| `slide` | The slide on screen, or null when none is mounted. |
| `warnings` | Every distinct warning the page reported, as code, message, slide, cue and attr. |
| `catalog` | One entry per scene, with its slides, its cues and the measured box of every element. |
| `cues` | When each cue was due, when it ran, and when the frames around it began. |
| `words` | Each synced line, when its cue ran, when the voice reaches it and when its first word showed. |
| `frameGaps` | Every gap between two animation frames longer than the recorder can absorb. |
| `longFrames` | Every animation frame that took longer than a captured frame, with when it was presented. |

The telemetry the probe keeps is what only the runtime can describe. A cue row carries the second it
was due, the second it ran, the frame that ran it and the sentence its reveals describe themselves
as, and it grows two more stamps afterwards, the frame after the one that ran the cue and the one
after that, because a cue that ran on time but whose next frame began late was held up by the frame
that drew it rather than before it. A word row carries the line, the second its cue ran, the second
the voice reaches it and the second its first word was drawn, which is what `PAGE_WORD_LATE`
compares. Frame gaps and long frames say how well the compositor kept up, because a recording is
only as good as the frames it was given. Each list is capped at five thousand rows, so a long
recording cannot grow without a bound.

A deck in a browser tab pays nothing for any of this. The runtime reports through the seam in
`telemetry.ts`, and a page opened without the probe keeps the no-op default and allocates nothing.

Python reads the answer once, at the boundary where the page stops being trusted. Every row is
validated into a model before anything above uses it, and a row that cannot be read is dropped with
the reason rather than carried into an artifact.

## The twenty-seven codes the page raises

The page never throws at its author. It records what it could not honour, echoes the sentence to the
console with a `decktalk:` prefix, and carries on drawing. A row is recorded once per code, slide,
cue and attribute, so a repeat adds nothing.

```bash
uv run decktalk schema finding
```

A warning travels as five fields: `code`, `message`, `slide`, `cue` and `attr`. The sentence belongs
to the contract and never to the module that raises it, so a code's wording changes in one file and
reaches the console, the finding and this documentation at once.

`record` and `check` read those rows and turn each into a finding under the same code, with the
slide or the cue as its location and the page as its file. Python refuses a code the page has no
business raising, because ten of the thirty-seven page codes are measured from the frames or from
the catalog after the run, and a page that reported one of those would be a deck judging itself.

| Code | What the page could not honour |
|---|---|
| `PAGE_UNKNOWN_ATTR` | An element carries a data attribute the contract does not declare. |
| `PAGE_BAD_VALUE` | An attribute's value is outside the range the contract publishes for it. |
| `PAGE_MOMENT_UNKNOWN` | An element outside every slide template names a moment, which no slide can own. |
| `PAGE_MOMENT_ORDER` | An element's exit is declared at or before its own entrance, so it never plays. |
| `PAGE_CUE_UNKNOWN` | A cue fired that no reveal, no handler and no slide in the deck declares. |
| `PAGE_NO_OWNER` | A cue the scene plays is owned by none of its slides, so nothing mounts for it. |
| `PAGE_SCENE_EMPTY` | A scene declares no slide template. |
| `PAGE_SLIDE_NO_ID` | A slide template carries no id. |
| `PAGE_SLIDE_DOUBLED` | Two slide templates carry the same id. |
| `PAGE_SLIDE_UNUSED` | No section plays this slide. |
| `PAGE_TEMPLATE_IGNORED` | A template inside a slide declares no slide of its own, so nothing mounts it. |
| `PAGE_WORDS_NOT_FOUND` | An element syncs to words the transcript does not hold. |
| `PAGE_KATEX_MISSING` | The page asks for KaTeX and the library is not loaded. |
| `PAGE_KATEX_ERROR` | KaTeX refused a formula, so the element shows its readable fallback text. |
| `PAGE_FREEZE_CUE_UNKNOWN` | A freeze was asked for a cue the slide does not declare. |
| `PAGE_RENDER_THREW` | A slide's render threw, so the slide is drawn as its markup stands. |
| `PAGE_ENTER_THREW` | A slide's enter threw. |
| `PAGE_SLIDE_HANDLER_THREW` | A slide's own moment handler threw. |
| `PAGE_HANDLER_THREW` | A moment handler threw. |
| `PAGE_WAIT_REJECTED` | A wait the page declared was rejected. |
| `PAGE_WAIT_UNSETTLED` | A wait the page declared never settled inside its budget. |
| `PAGE_CLASS_UNDESCRIBED` | An element changes class with no description. |
| `PAGE_CLASS_NOT_REDUCED` | A class change declares no reduced form. |
| `PAGE_SWAP_AMBIGUOUS` | A swap finds no element or several elements leaving at its cue, so it cannot tell which one it replaces. |
| `PAGE_PREVIEW_AMBIGUOUS` | Two sections name one scene, so a preview cannot choose whose cue times to play. |
| `PAGE_APPEAR_TOO_LONG` | A line shown with `data-words=appear` runs longer than eight words. |
| `PAGE_STAGGER_EMPTY` | An element staggers its children and has none. |

Each has its own page under `/reference/findings/`, and `code.url` on the Python member points at it.

## Reduced motion

Reduced motion is a render rather than an attribute, so the same page produces both films and an
author writes neither twice.

`motion.reduce` asks Chromium for a page that prefers reduced motion, and the runtime reads
`prefers-reduced-motion: reduce` through `matchMedia`. A person who has asked their own machine for
it gets the same render in a preview. When it is on, the runtime adds the class `dt-reduced` to the
root element, which the page's own stylesheet must honour. A class change that declares no reduced
form raises `PAGE_CLASS_NOT_REDUCED`, because a reduced render would otherwise animate anyway.

`motion.scale` reaches the page as one declaration on `:root`, which the recorder adds and an author
may write for themselves.

```css deck/style.css
:root { --dt-motion-scale: 1.5; }
```

The runtime reads that custom property, and every declared span and duration is multiplied by it and
then clamped, so a project that slows its motion down cannot slow it past the point where its own
cues stop being measurable. A value that is not a positive number reads as 1. `motion.scale` runs
from 0.25 to 4.0, and a span it pushes past the ceiling raises `PAGE_MOTION_OVERRUN`.

Neither is a flag. Both are settings keys, so `--set motion.reduce=true` and
`--set motion.scale=1.5` are how a run asks for them.

## CSS hooks

The runtime prepends one generated stylesheet as `#dt-style`, before anything the page declares.
Every selector in it sits inside `:where()`, which gives it no specificity at all, so a page rule of
equal weight wins on document order and an author never reaches for `!important`.

A deck is drawn into a stage of 1920 by 1080, scaled and centred in whatever window the page is
opened in, so an element measured on a laptop is at the pixel a recording will put it at.

| Selector | What it is |
|---|---|
| `#dt-stage` | The stage every deck is laid out on, which is the frame a recording captures. |
| `#dt-camera` | The layer the stage moves inside. |
| `#dt-pan` | The layer slides are mounted into, which is where every reveal is drawn. |
| `#dt-hud` | The heads-up display, drawn only under `?hud=1`. |
| `#dt-style` | The runtime's own stylesheet. |
| `--dt-motion-scale` | The custom property on `:root` that slows every length down. |
| `--dt-span` | The custom property each element's own motion length is written into. |

The classes the runtime puts on what it draws are `dt-slide`, `dt-leaving`, `dt-arriving`,
`dt-hidden`, `dt-shown`, `dt-back`, `dt-front`, `dt-word`, `dt-frozen` and `dt-reduced`.
