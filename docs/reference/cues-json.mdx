title: cues.json
description: Every key of the cue file, which names the spoken phrase each moment on the page lands on.
---

`cues.json` is the cue file. It says which spoken phrase each moment the deck declares lands on,
section by section. The file owns seconds and the page owns moments: the page says what a thing
looks like and what it means, this file says when it happens, and neither ever writes the other's
half. That is why no attribute in the markup carries a second and no row here carries a class or a
style.

{/* input: src/decktalk/template/starter/cues.json, sections 1 and 2 */}

```json cues.json
{
  "sections": {
    "1": {
      "cues": [
        { "id": "1.1:title", "phrase": "This is DeckTalk", "occurrence": 1 },
        { "id": "1.1:files", "phrase": "Four files", "occurrence": 1 },
        { "id": "1.2:script", "phrase": "what you will say", "occurrence": 1 },
        { "id": "1.2:deck", "phrase": "the slides", "occurrence": 1 },
        { "id": "1.2:word", "phrase": "its own word", "occurrence": 1 }
      ]
    },
    "2": {
      "cues": [
        { "id": "2.1:average", "phrase": "the average", "occurrence": 1 },
        { "id": "2.1:formula", "phrase": "the formula", "occurrence": 1 },
        { "id": "2.1:code", "phrase": "in code", "occurrence": 1 },
        { "id": "2.1:waited", "phrase": "waited", "occurrence": 1 }
      ]
    }
  }
}
```

## Shape

The file is one JSON object with a `sections` key. Every other key at the top level is read by
nothing, which is where the starter keeps its `_comment`. Each key of `sections` is a section number
written as a string, and it must name a `[[section]]` in `decktalk.toml`. Each section is an object
with a `cues` array and an optional `min_seconds`.

The file is optional. A project without it resolves no cues at all, and the deck earns one
`CUE_UNLISTED` finding counting every moment it declares, whose fix writes the whole file with a row
for each of them.

| Section key | Type | Default | Meaning |
|---|---|---|---|
| `cues` | array | `[]` | Every cue of this section, in any order. |
| `min_seconds` | number | none | How many seconds of speech this section's visuals need. A section that speaks for less earns no finding: `cue` says so on its stream, because the code list holds no code for it. |

The load refuses a file that is not valid JSON, a file with no top-level `sections` object, a section
key that is not a number, a section number that `decktalk.toml` does not declare, a section whose
value is not an object, a row with a key no cue reads, a row with no `id` or no `phrase`, and a row
whose `id` is empty. Each refusal names the file, and a JSON syntax error names the line as well. A
row whose `phrase` is empty loads, and `CUE_UNRESOLVED` says it has no phrase yet.

## The keys of one row

| Key | Type | Default | Meaning |
|---|---|---|---|
| `id` | string | required | The cue id of the moment this row times. |
| `phrase` | string | required | A word or a short phrase from that section of `script.md`, or the anchor `$start` or `$end`. |
| `occurrence` | integer | `1` | Which match of the phrase to take, counting from 1. |
| `case_sensitive` | boolean | `false` | Compare the phrase with the case as written. |
| `offset_seconds` | number | `0` | Seconds added to the matched moment. It may be negative. |
| `verify` | boolean | `true` | `false` leaves this cue out of `decktalk verify`, for a reveal too small or too slow for a frame difference to see. |
| `_comment` | any | none | The one key a row may carry that DeckTalk reads nothing from. |

Any other key is refused by name, so a typo can never move a cue in silence.

### `id`, the cue id

`id` is the [cue id](/concepts/cues#the-cue-id) of one moment the page declares, such as
`4.1:expand`. `decktalk schema page` prints every attribute that declares a moment.

### `phrase`

The phrase is matched against the words of that section and nothing else. `narrate` wrote them
beside the take as `<digest>.words.json`, in seconds after the take starts. `cue` moves them onto the
section's own clock, which begins at its lead. `decktalk words` prints them on that clock. [Matching rules](/concepts/cues#matching-rules) says how a phrase
meets a spoken word: case, punctuation, a hyphenated word and a word the voice spells out.

`occurrence` picks which match, counting from 1, and with no `occurrence` the cue takes the first and
`cue` names every second the phrase occurs at.

### `offset_seconds`

`offset_seconds` is added to the matched moment, and it may be negative. The result is never allowed before
the section's own start: a cue that would resolve earlier than zero lands at zero instead, which is
the case `CUE_NO_ONSET` names, because a second that is the section's start rather than a word's has
nothing to measure an onset against.

`offset_seconds` here is not the one of a sound effect. A `[[mix.effect]]` row in `decktalk.toml`
carries its own `offset_seconds`, which shifts the sound and not the picture.

### The two anchors

| `phrase` | Resolves to |
|---|---|
| `$start` | 0.0 seconds, which is where the section's own clock begins. With no offset this earns `CUE_NO_ONSET`. |
| `$end` | The end of the last word the section speaks, which is not the end of the section's audio. The tail of silence after it belongs to the section, not to the words. |

Both anchors are literal strings, so a phrase is never mistaken for one. Neither is affected by
`occurrence` or `case_sensitive`.

A second counts from the start of its own section, and the section starts where its silence starts.
A section's `lead_seconds` therefore moves every word, and so every phrase cue and `$end`, that much
later, while `$start` stays at zero.

## What resolves a cue

`decktalk cue` reads the words each section speaks off the take index and writes
`build/cue-times.json`, one row per cue with the cue id, the phrase it matched, the second it fires
and the offset that was added. That file is what `record`, `assemble` and `verify` read, and no stage
works a second out from `cues.json` again.

Three findings come out of that pass.

| Code | Severity | Cause |
|---|---|---|
| `CUE_UNRESOLVED` | error | The row has no phrase yet, the phrase is not spoken in that section, or the section has no take at all, so there is no second to place the cue at and the film never plays it. A section that plays a clip is skipped in silence instead, because the voice never reads one. |
| `CUE_NO_ONSET` | warning | The cue resolved to the section's own start rather than to a word. |
| `CUE_OVERLAP` | warning | One cue fires while the moment before it is still playing, measured against the span that moment's own effect declares. |

## The two files read against each other

A cue and the moment it fires are one thing written in two places, so each is read against the other.
The page's side is the catalog its runtime publishes, which names every slide of a scene and every
moment its elements declare, already qualified into a cue id. It is read from that catalog and never
from a scan of the markup, because `data-spotlight`, `data-class` and `data-owns` all declare moments no
text scan can see.

`decktalk check` makes the comparison against a catalog it reads live, and names every moment that
this file has no row for.

{/* sample: cue-row-missing, decktalk check --no-frames, on a fresh decktalk init my-lesson with the 2.1:formula row deleted, which exits 1 */}
```text
No voice is named, so no take on disk can be matched, because [voice] id is empty and DECKTALK_VOICE_ID is not set.
Checking script.md, cues.json, deck/index.html.
This run costs $0.15 for 476 characters at $0.30 per 1,000 characters.
cues.json: CUE_UNLISTED section 2 declares 1 moment(s) that cues.json does not list, which is 2.1:formula, so nothing gives them a second.
  fix (safe): Add 1 row to section 2 of cues.json, each waiting for the words you write in its `phrase`.
Found 1 finding, 1 error. 1 fixable with --fix.
```

`decktalk check --fix` applies that fix, and `Project.apply(finding)` applies it from the library.
The fix only ever adds: it writes one row per moment nothing lists, it never rewrites a phrase you
wrote and it never deletes a row, so applying it a second time adds nothing, because by then every
moment of that section is listed. The row it writes leaves `phrase` empty, because the phrase a cue
lands on is your line and not DeckTalk's. The file still loads with an empty `phrase`, and the row raises
`CUE_UNRESOLVED` until you write the phrase.

A row whose cue id no page declares is the mirror of it, `CUE_UNKNOWN`. It is named rather than
deleted. When exactly one unlisted row sits beside exactly one undeclared moment in the same section,
the two are read as a rename, because the phrase is what survives a rename, and the fix changes the
id alone.
