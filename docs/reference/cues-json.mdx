The cue file names the spoken phrase that each visual lands on. It is optional, and a
project without one plays every page with its built-in timing. This is an example in
the scaffold's shape.

```json cues.json
{
  "_comment": "Which spoken phrase each visual lands on.",
  "sections": {
    "2": {
      "cues": [
        { "cue": "2.1a", "on": "First" },
        { "cue": "2.1b", "on": "Second" },
        { "cue": "2.2", "on": "one take" }
      ]
    },
    "3": {
      "min_seconds": 30,
      "cues": [
        { "cue": "3.1", "on": "$start" },
        { "cue": "3.1eq", "on": "learning rate" },
        { "cue": "3.1min", "on": "settle", "offset": 0.2 }
      ]
    }
  }
}
```

<Note>A cue on `$start` with no offset fires at 0.0, which is fine for the page. It leaves
no frame before it for `decktalk verify` to compare against, so the check reports it as
`skipped` with `REFERENCE_CLAMPED` rather than measuring it. Verify cues that sit on
words.</Note>

## Shape

The file is one object with a `sections` key. Every other top-level key, such as
`_comment`, is ignored. Each key of `sections` is a section number as a string, and it
must name a `[[section]]` in `decktalk.toml`. Each section is an object with an optional
`min_seconds` and a `cues` list.

Every cue id must appear in the section's page as a quoted literal, such as
`data-cue="3.1eq"` or a key of a step's `cues` object. `beats` reports an id it cannot
find, and `build` stops on it unless `--allow-unknown` is given.

## Keys of a cue

| Key | Required | Meaning |
|---|---|---|
| `cue` | yes | A cue id the page understands. `step` is accepted as a synonym, and `step` wins when both are present. The id may not contain `@` or a comma. |
| `on` | yes | A word or short phrase from that section's narration, or `$start`, or `$end`. |
| `offset` | no | Seconds added to the match. It may be negative. `$start` plus a negative offset is written as is, and the page fires it at t=0. A `$start` cue whose time does not clear the section's fade-in by at least one frame has no frame before it, so `verify` reports it as `skipped` with `REFERENCE_CLAMPED`. |
| `occurrence` | no | Which repeat of the phrase to use. The default is 1, the first. |
| `case_sensitive` | no | Match case as written. The default is false. |
| `verify` | no | `false` leaves the cue out of a plain `decktalk verify`, for a reveal too small or too slow for a frame difference to measure. The row reads `skipped` with `OPTED_OUT`. Naming the cue as `SECTION:CUE` measures it anyway. The default is `true`. |

## Keys of a section

| Key | Required | Meaning |
|---|---|---|
| `cues` | no | The list above. A section may have none. |
| `min_seconds` | no | `beats` warns when the section's speech is shorter than this, so you learn early that the visuals will not fit. |

## What beats writes

`decktalk beats` resolves every cue and writes `build/audio/beats.json`, one string per
section in the form the page receives as `?beats=`. It also writes
`build/audio/beats.anchors.json`, each cue's word start without its `offset`, which
`verify` uses to find the click at the cued word in a silent build.

```json build/audio/beats.json
{
  "01": "1.1curve@1.18,1.1number@3.09,1.1mark@4.34,1.1md@7.87,1.1times@12.17,1.1cap@15.99",
  "03": "3.1weights@2.81,3.1loss@5.16,3.1preview@25.31,3.1p0@27.65,3.1height@29.99,3.1up@32.8,3.1neg@37.96,3.1p1@39.37,3.1eq@41.71,3.1scale@43.11,3.1shrink@44.52,3.1rule@47.8,3.1eqA@49.67,3.1eqA2@51.08,3.1eqB@52.49,3.1eqC@53.42,3.1over@55.3,3.1diverge@57.64,3.1crawl@60.45,3.1min@63.0"
}
```
