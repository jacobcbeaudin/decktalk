title: cues.json
description: Every key of the cue file, which names the spoken phrase each moment on the page lands on.
---

`cues.json` is the cue file. It says which spoken phrase each moment the deck declares lands on,
section by section. The file owns seconds and the page owns moments: the page says what a thing
looks like and what it means, this file says when it happens, and neither ever writes the other's
half. That is why no attribute in the markup carries a second and no row here carries a class or a
style.

{/* input: src/decktalk/template/starter/cues.json, sections 1 and 2 */}

```json cues.json
{
  "sections": {
    "1": {
      "cues": [
        { "cue": "1.1:title", "on": "This is DeckTalk", "occurrence": 1 },
        { "cue": "1.1:files", "on": "Four files", "occurrence": 1 },
        { "cue": "1.2:script", "on": "what you will say", "occurrence": 1 },
        { "cue": "1.2:deck", "on": "the slides", "occurrence": 1 },
        { "cue": "1.2:word", "on": "its own word", "occurrence": 1 }
      ]
    },
    "2": {
      "cues": [
        { "cue": "2.1:average", "on": "the average", "occurrence": 1 },
        { "cue": "2.1:formula", "on": "the formula", "occurrence": 1 },
        { "cue": "2.1:code", "on": "in code", "occurrence": 1 },
        { "cue": "2.1:waited", "on": "waited", "occurrence": 1 }
      ]
    }
  }
}
```

## Shape

The file is one JSON object with a `sections` key. Every other key at the top level is read by
nothing, which is where the starter keeps its `_comment`. Each key of `sections` is a section number
written as a string, and it must name a `[[section]]` in `decktalk.toml`. Each section is an object
with a `cues` array and an optional `min_seconds`.

The file is optional. A project without it resolves no cues at all, and the deck earns one
`CUE_MISSING` finding counting every moment it declares, whose fix writes the whole file with a row
for each of them.

| Section key | Type | Default | Meaning |
|---|---|---|---|
| `cues` | array | `[]` | Every cue of this section, in any order. |
| `min_seconds` | number | none | How many seconds of speech this section's visuals need. A section that speaks for less earns no finding: `cue` says so on its stream, because the code list holds no code for it. |

The load refuses a file that is not valid JSON, a file with no top-level `sections` object, a section
key that is not a number, a section number that `decktalk.toml` does not declare, a section whose
value is not an object, a row with a key no cue reads, and a row whose `cue` or `on` is empty. Each
refusal names the file, and a JSON syntax error names the line as well.

## The keys of one row

| Key | Type | Default | Meaning |
|---|---|---|---|
| `cue` | string | required | The wire id of the moment this row times. |
| `on` | string | required | A word or a short phrase from that section of `script.md`, or the anchor `$start` or `$end`. |
| `occurrence` | integer | `1` | Which match of the phrase to take, counting from 1. |
| `case_sensitive` | boolean | `false` | Compare the phrase with the case as written. |
| `offset` | number | `0` | Seconds added to the matched moment. It may be negative. |
| `verify` | boolean | `true` | `false` leaves this cue out of `decktalk verify`, for a reveal too small or too slow for a frame difference to see. |
| `_comment` | any | none | The one key a row may carry that DeckTalk reads nothing from. |

Any other key is refused by name, so a typo can never move a cue in silence.

### `cue`, the wire id

A wire id is the slide id, a colon, and the local name the page wrote. An element on the page names
its moments locally, and the runtime qualifies each local name with the slide it is written in, so
`data-in="expand"` inside `<template data-slide="4.1">` is the wire id `4.1:expand`, and that is
what this file carries.

The slide id, not the section number, is the first half. A section can play a scene whose slides are
numbered differently, and the wire id follows the slide. Section 1 of the starter plays scene 1,
whose two slides are `1.1` and `1.2`, which is why its rows begin with both.

Each of the four moments an element declares is a wire id of its own: `data-in` when it arrives,
`data-back` when it steps back, `data-front` when it comes forward, and `data-out` when it leaves.
`decktalk schema page` prints every attribute that declares a moment.

### `on`, the phrase

The phrase is matched against the words of that section and nothing else, which `narrate` wrote
beside the take as `<hash>.words.json`, each with its start and its end in seconds
after the section starts. `decktalk words` prints them. Matching normalises each word by dropping every
character that is not a letter, a digit or an apostrophe, and then lowercasing it unless the row sets
`case_sensitive`. The phrase matches where its normalised words equal a run of normalised spoken
words.

Two consequences are worth writing down. A phrase with punctuation in it matches the same words the
plain phrase does, because the punctuation is dropped from both sides. A phrase that normalises to
one token can only ever match one spoken word, which is why a cue on `decktalk.ai` matches nothing
when the script says "decktalk dot AI".

`occurrence` picks which match, counting from 1. When a phrase occurs more than once and the row
names no occurrence, the cue takes the first and `cue` says so on its stream, naming every second the
phrase occurs at.

### `offset`, in seconds

`offset` is added to the matched moment, and it may be negative. The result is never allowed before
the section's own start: a cue that would resolve earlier than zero lands at zero instead, which is
the case `CUE_NO_ONSET` names, because a second that is the section's start rather than a word's has
nothing to measure an onset against.

`offset` is not the offset of a sound effect. A `[[mix.effects]]` row in `decktalk.toml` carries its
own `offset`, which shifts the sound and not the picture.

### The two anchors

| `on` | Resolves to |
|---|---|
| `$start` | 0.0 seconds, which is where the section's own clock begins. With no offset this earns `CUE_NO_ONSET`. |
| `$end` | The end of the last word the section speaks, which is not the end of the section's audio. The tail of silence after it belongs to the section, not to the words. |

Both anchors are literal strings, so a phrase is never mistaken for one. Neither is affected by
`occurrence` or `case_sensitive`.

A second counts from the start of its own section, and the section starts where its silence starts.
A section's `lead_seconds` therefore moves every word, and so every phrase cue and `$end`, that much
later, while `$start` stays at zero.

## What resolves a cue

`decktalk cue` reads the words each section speaks off the take index and writes
`build/cue-times.json`, one row per cue with the wire id, the phrase it matched, the second it fires
and the offset that was added. That file is what `record`, `assemble` and `verify` read, and no stage
works a second out from `cues.json` again.

Three findings come out of that pass.

| Code | Certainty | Cause |
|---|---|---|
| `CUE_UNRESOLVED` | certain | The phrase is not spoken in that section, or the section has no take at all, so there is no second to place the cue at and the film never plays it. A section that plays a clip is skipped in silence instead, because the voice never reads one. |
| `CUE_NO_ONSET` | uncertain | The cue resolved to the section's own start rather than to a word. |
| `CUE_OVERLAP` | uncertain | One cue fires while the moment before it is still playing, measured against the span that moment's own effect declares. |

## The two files read against each other

A cue and the moment it fires are one thing written in two places, so each is read against the other.
The page's side is the catalog its runtime publishes, which names every slide of a scene and every
moment its elements declare, already qualified into a wire id. It is read from that catalog and never
from a scan of the markup, because `data-steps`, `data-class` and `data-owns` all declare moments no
text scan can see.

`decktalk check` makes the comparison against a catalog it reads live, and names every moment that
this file has no row for.

{/* sample: decktalk check --no-frames, starter with the 2.1:formula row deleted */}

```text
cues.json: CUE_MISSING section 2 declares 1 moment(s) that cues.json does not list, which is 2.1:formula, so nothing gives them a second.
  fix (safe): Add 1 row(s) to section 2 of cues.json, each waiting for the phrase you write in its `on`.
Found 1 finding, 1 certain. 1 fixable with --fix.
```

`decktalk check --fix` applies that fix, and `Project.apply(finding)` applies it from the library.
The fix only ever adds: it writes one row per moment nothing lists, it never rewrites a phrase you
wrote and it never deletes a row, so applying it a second time adds nothing, because by then every
moment of that section is listed. The row it writes leaves `on` empty, because the phrase a cue
lands on is your line and not DeckTalk's, and an empty `on` is refused at load, so write the phrase
before the next command reads the file.

A row whose wire id no page declares is the mirror of it, `CUE_UNKNOWN`. It is named rather than
deleted. When exactly one unlisted row sits beside exactly one undeclared moment in the same section,
the two are read as a rename, because the phrase is what survives a rename, and the fix changes the
id alone.
