description: Every table of the DeckTalk project file, split into the document it owns and the settings it may also carry.

`decktalk.toml` sits in the project root, and every path in it is relative to that directory. It has
two halves, and knowing which half a key is in tells you everything else about it.

The **document** is the content this project is: what it is called, which section plays which page or
clip, which voice reads it, what the sound is made of and how the cuts behave. Every value in it
changes from presentation to presentation, it has no default worth publishing, and this page is its
reference.

The **settings** are the knobs. Every settings key publishes its default, its safe range, its unit,
its scope and what a value at the edge risks, all from one declaration in the code, so
`decktalk schema settings`, the JSON Schema, `decktalk config explain` and
[Configuration](/reference/configuration) are four renderings of one row. This page names the tables
and sends you there rather than copying the numbers.

## The first line

```toml decktalk.toml
#:schema https://raw.githubusercontent.com/jacobcbeaudin/decktalk/main/schemas/v1/decktalk.json
```

That comment binds the file to the published JSON Schema. An editor that understands it completes
every table and every key as you type, offers each key's own sentence, and marks a value outside a
key's safe range before you save. `decktalk init` writes the line, and it costs nothing to keep.

## Which value wins

Five layers can set a settings key. Each overrides the ones before it.

1. The default the key publishes.
2. The same table in the per-machine settings file.
3. The same table in this project's `decktalk.toml`.
4. The environment variable the key publishes, such as `DECKTALK_VIDEO_PRESET`.
5. `--set table.key=value`, on any command that builds or reports on the project, for one run.

The fifth layer writes nothing. `--set` overrides a key for exactly the run it is given to, and the
file on disk is untouched, which is what makes it the right way to try a value. It takes the same
spelling an environment variable takes, so a value cannot get in through one route that the other
would refuse. No flag on any command duplicates a settings key, so reduced motion is
`--set motion.reduce=true` and never a flag of its own.

`decktalk config explain KEY` prints the value that wins and the layer that set it, along with what
the key changes, what may be written into it and which findings it moves. Its `--json` lists every
layer that sets the key.

`decktalk config set KEY VALUE` is how you write one into a file. It reads the value under the same
range the loader enforces, edits the document in place rather than rewriting it, so the comments you
wrote around the key survive, and loads the would-be file whole before a byte lands, so a file no run
could use never reaches the disk. `--where project` writes `decktalk.toml` and `--where machine`
writes the per-machine file. `--dry-run` reports the change and writes nothing.
`decktalk config unset KEY` takes a key out again so the layer below it wins.

A value outside a key's safe range is refused at load, by the dotted key that wrote it, with the
range it missed and the sentence saying what goes wrong at the edge.

{/* sample: decktalk status in a starter project with crf = 99 added under [video] */}

```text
error[INPUT]: video.crf: must be between 0 and 32, got 99
  hint: Above about 32 the encoder's own ringing is larger than a small reveal, so a cue that played reads as no change and the check that would have caught it passes instead.
  docs: https://docs.decktalk.ai/reference/errors/INPUT
```

## Load rules

Every project command loads this file first. The load fails when any of these is true, and the
refusal names what it read and would not accept.

- A top-level table is neither a document table nor a settings table.
- The file has no `[[section]]` table.
- A required key is missing, such as a `[[section]]` with no `number`.
- A value has the wrong type. `seconds = 120.5` under `[soundscape.music]` fails, because that key is
  an integer and a mapping carries the type its author wrote.
- Two `[[section]]` tables share a `number`.
- A section has both `page` and `clip`, or neither.
- `record_margin_seconds`, `hold_seconds`, `lead_seconds` or `tail_seconds` is below 0.
- `seamless` is set on the first section, which has no previous section.
- A `[transition] dips` pair or a `[[mix.effects]]` row names a section that does not exist.
- A settings value is outside its safe range.
- A `page` sits at the project root. The origin serves a page's whole directory, and the root holds
  the script, the cue file and the build directory.
- A path the project names resolves outside the project, which includes a symbolic link inside the
  project that points out of it. The refusal names the path and never the place it resolved to.
- A settings key only a machine may set is written here, such as `record.concurrency` or
  `tools.ffmpeg`. The refusal names the key and the `config set` line that puts it in the machine's
  file.

An unknown key inside a known table does not fail the load. DeckTalk warns, names the closest key it
does read, ignores the key and carries on.

{/* sample: decktalk status in a starter project with stability misspelled under [elevenlabs] */}

```text
decktalk.toml: [elevenlabs]: ignoring unknown key 'stabilty' (did you mean 'stability'?).
```

A key spelled under a table it does not live in is warned about the same way, and the closest key is
named with its own table, because no key is read under any name but its own.

```text
decktalk.toml: [voice]: ignoring unknown key 'stability' (did you mean 'elevenlabs.stability'?).
```

A page section key written on a clip section, or the reverse, gets a warning of its own that names
the kind of section the key belongs to.

## The smallest file that loads

```toml decktalk.toml
[[section]]
number = 1
page = "deck/index.html"
```

`decktalk init` writes a three-section file with comments and every section a page section.
`decktalk init --example NAME` writes a finished project instead.

## The document

The tables below are the content this project is. Every one of them is read by `Document`, none of
them has a settings key in it except where this page says a table is shared, and none of them
publishes an environment variable or answers to `--set`.

## `[project]`

| Key | Type | Default | Meaning |
|---|---|---|---|
| `name` | string | the project directory's name | What the film is called. The film is `build/final/<name>.mp4`, and the captions, the chapters, the transcript and the poster are named from it too. |
| `script` | path | `script.md` | The narration script. |
| `cues` | path | `cues.json` | The cue file. |
| `build` | path | `build` | Where everything generated goes. |
| `language` | string | `en` | The BCP 47 tag of the language the film is narrated in. It labels the mp4's streams, which is what a player names the audio from, and it is the transcript page's own language. |

## `[[section]]`

Write one `[[section]]` per section of the film. Sections are sorted by `number`, so the order in the
file does not matter. A section is a **page section**, which records one scene of an HTML page, or a
**clip section**, which plays a video file you already have. It is a clip section when it has a
`clip` key and a page section when it has a `page` key, and having both or neither fails the load.

### Every section

| Key | Type | Default | Meaning |
|---|---|---|---|
| `number` | integer | required | The section number. A page section's number must match a `## N.` heading in the script. |
| `chapter` | string | the script heading, then `Section N` | The chapter title, which names this section in the chapter markers, in the transcript and on the slate a missing clip plays. Consecutive sections with the same title share one marker. |
| `seamless` | boolean | `false` | This section opens on the picture the section before it ended on. `verify` compares the two frames across the cut and raises `CUT_POP` when the join shows. It may not be set on the first section. |

### A page section

| Key | Type | Default | Meaning |
|---|---|---|---|
| `page` | path | required | The HTML file to record, such as `deck/index.html`. It sits in a directory of its own, never at the project root. |
| `scene` | integer or string | the section's `number` | Which `data-scene` of that page to play. It reaches the page as a string. |
| `record_margin_seconds` | number | `0.3` | How long the recording runs past the section's span. |
| `hold_seconds` | number | `0` | How long the section's last frame holds after its narration. The narration waits for the hold, and the next section starts after it. |
| `lead_seconds` | number | `[narration] lead_seconds` | Silence before the section's first word. |
| `tail_seconds` | number | `[narration] tail_min_seconds` | Silence after the section's last word. |
| `ambience` | boolean | `false` | Play the ambience bed under this section. |
| `params` | table | none | Query parameters the page is opened with, written as `[section.params]`. Every key must be one of `scene`, `slide`, `cues`, `words`, `t0`, `speed`, `hud`, `after` and `before`, which is the whole vocabulary a DeckTalk page reads. Loading the project accepts any key, and a command that opens the page or works out whether its recording is current refuses any other key by name, as `INPUT`: `check` with pages, `storyboard`, `status`, `record` and `build`. `narrate`, `cue` and `check --no-pages` never read it. Every value reaches the page as a string. |

`lead_seconds` and `tail_seconds` are placed when the takes are joined and are never sent to the
voice, so changing either voices nothing. The section starts where its silence starts, so
`lead_seconds` moves every word and every phrase cue of the section later while a `$start` cue stays
at zero. [script.md](/reference/script-md) has the whole rule.

`record` sets `t0` itself so that the page starts its clock on the recorder's signal, and it fills
`cues` and `words` from what `cue` and `narrate` resolved unless the section names them. A frozen
frame, which `storyboard` and `check` draw, sets `cues`, `t0`, `slide`, `after` and `before` itself,
so those five are dropped from a section's `params` rather than passed through.

```toml decktalk.toml
[[section]]
number = 4
chapter = "The edit"
page = "deck/index.html"
lead_seconds = 1.5    # the page shows for 1.5 seconds before the first word
hold_seconds = 2      # the last frame stays 2 seconds before section 5
```

A page may load only what this file declares. Every page is opened at a local origin that answers
for the directory each `page` sits in and for the files the document names, which are each clip and
its `words`, every `[mix]` file, every `[[mix.effects]]` file and every `[soundscape]` `out`. Every
other file in the project is refused, so the script, the cue file, `build/` and `.env` stay out of a
page's reach. A declared file is reached by the spelling written here and by no other, so
`media/Theme.mp3` does not answer a request for `media/theme.mp3` on any platform. A declared
directory is a place, so every name under it is served however the page spells it.

### A clip section

| Key | Type | Default | Meaning |
|---|---|---|---|
| `clip` | path | required | Your own video file. It keeps its own audio. |
| `slate_seconds` | number | `5` | How long the titled slate plays when the file is not there. |
| `optional` | boolean | `false` | A missing file is expected here for now, so `decktalk status` raises no `FILE_MISSING` for it and `Project.assemble(strict=True)` plays the slate rather than refusing. Delete the line once the clip is there. |
| `words` | path | none | A words file of the speech inside the clip, in seconds after the clip starts, which the captions add. |

A clip whose file is not there plays a titled slate for `slate_seconds`, and `decktalk status`
raises `FILE_MISSING` unless the section sets `optional`. The voice never reads a clip section, so it
needs no heading in the script and it is never voiced. A clip between two page sections pauses the
narration, which resumes with the next page section. DeckTalk scales and pads the clip to the frame
size, and the chapters include it.
[Add a clip section](/guides/clip-section) shows the whole task.

Every media file a project names, which is a clip, the music, the ambience and each effect, is read
as one file by one of a closed set of formats: MP4, MOV and M4A, WebM and MKV, AVI, MP3, WAV, Ogg,
FLAC, AAC, PNG, JPEG and WebP. A file in any other format is refused, and so is a playlist, an HLS
or DASH manifest, an ffmpeg concat list or an image sequence, because each of those opens files or
hosts the project never named.

## `[voice]`

`[voice]` is a settings table of the four keys every voice has. Everything a provider is particular
about is in that provider's own table, `[elevenlabs]` for ElevenLabs and `[dtsp]` for the local
voice, so changing `provider` never sends one vendor's fields or model to another.

| Key | Type | Default | Meaning |
|---|---|---|---|
| `provider` | string | `elevenlabs` | The speech provider this project is read by. It is a name the machine's own map answers, and an unregistered name fails when `narrate` runs rather than at load. DeckTalk ships `elevenlabs` and `dtsp`. |
| `id` | string | empty | The voice that reads the script. It is a published name rather than a credential, so it is committed with the project, and `DECKTALK_VOICE_ID` in the environment overrides it for anyone who keeps it out of the file. |
| `model` | string | empty | The provider model this project is read by. Empty is the provider's own default, such as `[elevenlabs] model` or `[dtsp] model`. |
| `speed` | number | `1.0` | How fast the voice speaks, as a multiple of its natural pace. |

The ElevenLabs API key is the one secret, so it lives in `.env` as `ELEVENLABS_API_KEY`, or in the
environment. The local voice needs none.

`[elevenlabs]` holds `model`, `stability`, `similarity_boost`, `style`, `speaker_boost`,
`price_per_1000_characters`, `output_format` and `api_base`. ElevenLabs bills per character, so its
rate is stated per thousand characters. The soundscape buys from the same API with the same key and
`api_base`, and its own request settings and its rates per minute of audio are in `[soundscape]`.
[Configuration](/reference/configuration#elevenlabs) has each one with its range. The voice id, the
model, `speed`, the four voice fields and `output_format` are part of a take's content hash, so
changing one makes the next voiced build voice every section again. The price and the API base are
not.

`[dtsp]` holds `url` and `model` for the local voice, which speaks the DeckTalk speech protocol to
`decktalk-voice`, a separate local server that is not part of this repository. `url` must be http on
`127.0.0.1`, `localhost` or `[::1]`, and `decktalk check` refuses any other host unless the machine
sets `DECKTALK_ALLOW_ANY_API_BASE`. The local voice bills nothing, so buying its takes asks for no
`--spend`, and a build still asks about a soundscape it would buy. Its takes are named by `dtsp`, the voice id, the model and `speed`, so they never share a
name with an ElevenLabs take of the same words. [Configuration](/reference/configuration#dtsp) has
both keys.

## `[soundscape]`

`[soundscape]` holds the prompts that `decktalk soundscape` generates from. It is optional, and no
packaged project writes one. Every item writes to `build/soundscape/` unless the table names another
path, and a generated file that `[mix]` then names is what the film actually plays.

Each item's table is shared: its prompt and its file are the document, and beside them sit the
settings that size its request, spelled the same way in every table. [Configuration](/reference/configuration#soundscape)
has every setting with its range, and `[soundscape] timeout_seconds` is how long one request may take.

```toml decktalk.toml
[soundscape.ambience]
text = "a quiet room, distant traffic, no music"

[soundscape.effects.chime]
text = "one soft glass chime"

[soundscape.music]
prompt = "calm piano under a lesson, unhurried"
duration_seconds = 360
```

### `[soundscape.ambience]`

| Key | Type | Default | Meaning |
|---|---|---|---|
| `text` | string | required | The prompt. |
| `out` | path | `[mix] ambience`, else `build/soundscape/ambience.mp3` | Where to write it. |
| `duration_seconds` | number | `25` | A setting: how long a bed to ask for. The bed loops under every section that sets `ambience = true`. |
| `prompt_influence` | number | `0.3` | A setting: how closely the sound follows the prompt. |
| `model` | string | `eleven_text_to_sound_v2` | A setting: the sound model to ask. |

### `[soundscape.effects]` and `[soundscape.effects.<name>]`

`[soundscape.effects]` holds three settings for every effect: `duration_seconds`, which is `0.5`,
`prompt_influence`, which is `0.5`, and `model`. One `[soundscape.effects.<name>]` table per effect
names it, and `<name>` is the name the file is written under. It takes `text`, which is required, and
`out`, which is `build/soundscape/<name>.mp3` by default, and it may set any of the three settings for
itself. A `[[mix.effects]]` row is what places the finished sound in the film.

### `[soundscape.music]`

| Key | Type | Default | Meaning |
|---|---|---|---|
| `prompt` | string | required | The prompt. |
| `force_instrumental` | boolean | `true` | Ask for no vocals. |
| `out` | path | `[mix] music`, else `build/soundscape/music.mp3` | Where to write it. |
| `duration_seconds` | integer | `360` | A setting: how long a piece to ask for. It is an integer, so `120.5` fails the load. |
| `model` | string | `music_v2` | A setting: the music model to ask. |
| `bitrate` | string | `192k` | A setting: the bitrate of the file joined from the parts. |
| `max_chunk_seconds` | integer | `300` | A setting: the longest one request asks for. |
| `crossfade_seconds` | integer | `2` | A setting: the crossfade between two parts. |

A piece longer than `max_chunk_seconds` is asked for in parts and joined with a crossfade, because the
service will not write a long piece in one answer.

## `[mix]`

`[mix]` is shared too. The keys below are the document, naming the sound files the film plays and the
level each one plays at. The settings half is how each layer is ramped, and
[Configuration](/reference/configuration#mix) has its five keys. The loudness the final mix is
mastered to is `[audio]`.

Without `[mix]` the film carries the narration and the audio of any clip, and nothing else.

| Key | Type | Default | Meaning |
|---|---|---|---|
| `music` | path | none | Music under the whole film. It loops, and it ducks under speech and under clips. |
| `music_db` | number | `-24` | The music level. |
| `music_duck_db` | number | `-6` | The extra level change under each spoken span and each clip. |
| `music_fade_in_seconds` | number | `2` | The fade in. |
| `music_fade_out_seconds` | number | `3` | The fade out. |
| `music_markers` | path | none | A markers file that swells and mutes the music at spoken phrases. |
| `ambience` | path | none | The ambience bed for every section that sets `ambience = true`. |
| `ambience_db` | number | `-20` | The ambience level. |
| `slate` | path | a rendered slate | A PNG to show for a missing clip, instead of the titled slate DeckTalk renders. |

A missing music or ambience file does not fail the build. `assemble` warns and plays the film
without it.

### `[[mix.effects]]`

One table per sound effect, each of which plays at a cue.

| Key | Type | Default | Meaning |
|---|---|---|---|
| `file` | path | required | The audio file to play. |
| `section` | integer | required | The section whose cue places it. The section must exist. |
| `cue` | string | required | The wire id of the cue in that section, such as `3.2:expand`. |
| `db` | number | `-16` | The level. |
| `offset` | number | `0` | Seconds added to the cue time. This offset belongs to the sound and not to the cue. |
| `caption` | string | none | The line a viewer reads when the sound plays, such as `ball bounces`. `assemble` gives it a line of its own in the captions. |

A missing file or a cue that never resolved does not fail the build. `assemble` skips that effect and
says so.

### `markers.json`

`[mix] music_markers` names a JSON file that shapes the music under the film. No packaged project
writes one, so the block below is the shape rather than a starter's values.

```json media/markers.json
{
  "boost_db": 3,
  "boost_seconds": 2,
  "markers": [
    { "name": "turn", "section": 3, "on": "$start", "mute_seconds": 0.4 }
  ]
}
```

| Key | Type | Default | Meaning |
|---|---|---|---|
| `boost_db` | number | `3` | How far the music rises at each marker. |
| `boost_seconds` | number | `2` | How long each swell lasts. |
| `markers` | array | `[]` | The markers. |

A marker names a moment in the narration, and `section`, `on`, `offset`, `occurrence` and
`case_sensitive` resolve exactly as a cue's do. `name` is what a warning calls it, and `mute_seconds`
drops the music there before the swell. A marker whose phrase is not spoken is reported by `assemble`
and skipped.

## `[transition]`

| Key | Type | Default | Meaning |
|---|---|---|---|
| `dips` | array of two-integer arrays | every cut | Which boundaries dip to black, written as `[[from, to], ...]` of section numbers. Leave the key out to dip at every cut, and write `dips = []` for none. |
| `dip_seconds` | number | `0.15` | How long a dip lasts, rounded to whole frames so a fade never ends part way through one. |
| `page_fades_in` | boolean | `true` | Pages fade themselves in, so the cut into a page section adds no fade of its own. |

Audio never dips. A dip shows on screen, so leave a pair out of `dips` for a cut that should not
show, which is also what a `seamless` section needs.

## The settings

A settings table may be written here, and it then overrides the per-machine file for this project.
These are the tables, and every key of each one is published with its default, its safe range, its
unit, its scope and its hazard by `decktalk schema settings` and documented in full on
[Configuration](/reference/configuration).

| Table | What it sets |
|---|---|
| [`[narration]`](/reference/configuration#narration) | The pacing, the lead and the tail, the take cache and where a take's sound ends. |
| [`[voice]`](/reference/configuration#voice) | The four keys every voice has: its provider, its id, its model and its speed. |
| [`[elevenlabs]`](/reference/configuration#elevenlabs) | ElevenLabs's own keys: the fields its speech takes, its default model, what your plan charges and its API. |
| [`[record]`](/reference/configuration#record) | How the recorder drives Chromium, finds narration t=0 and judges a stalled or short recording. |
| [`[video]`](/reference/configuration#video) | The frame size, the frame rate and the video encoding of every recording and of the final mp4. |
| [`[audio]`](/reference/configuration#audio) | The final audio: its bitrate, its sample rate, its channels, and the loudness, the true peak and the range it is mastered to. |
| [`[mix]`](/reference/configuration#mix) | The ramps of the music duck, the ambience bed and each marker. |
| [`[soundscape]`](/reference/configuration#soundscape) | How each sound and the music are asked for: their models, their lengths and how the music is joined. |
| [`[verify]`](/reference/configuration#verify) | Every limit the finished film is measured against. |
| [`[motion]`](/reference/configuration#motion) | Reduced motion and the multiplier on every declared motion span. |
| [`[output]`](/reference/configuration#output) | The timestamped copy and how many runs of event files are kept. |
| [`[tools]`](/reference/configuration#tools) | Where ffmpeg, ffprobe and the fetched builds live on this machine. |

The per-machine file holds machine-scoped keys alone. A key about the film written there is refused
by name with the line it sits on, because the file that ships has to carry whatever the machine
running it believes. `decktalk config list` prints every key with the layer that set it.
