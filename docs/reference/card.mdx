The reference card states the whole contract in the fewest words, and every item links to
the guide or reference that explains it. Every page of these docs is also served as plain
text at [llms.txt](https://docs.decktalk.app/llms.txt), and the whole site is served as one
file at [llms-full.txt](https://docs.decktalk.app/llms-full.txt).

## Inputs

All four live in the project directory. [Your first deck](/guides/first-deck) writes them.

| File | Shape |
|---|---|
| `decktalk.toml` | `[project]` with `name`, an optional `[voice]`, one `[[section]]` per script section with `number`, `title`, and either `page` + `scene` or `clip`, then optional `[transition]`, `[mix]`, `[soundscape]`, and tuning tables. `hold_seconds` is allowed only on the last page section and clones its last frame. A clip sits before the first page section or after the last. [decktalk.toml](/reference/decktalk-toml). |
| `script.md` | `## N. Title` starts section `N`, and `## N. Title — 0:40 to 1:10` adds a time budget. `[bracketed]` text is a stage direction, not spoken. A plain direction and `[beat]` are beats: the voice reads a dash there and no break tag is sent. `[pause N]` sends a `<break time="Ns" />` tag and is the only direction that does. `[CAPITALS]` is a placeholder and fails `narrate`. `<break time="1s" />` passes through as written. Silence before the first section (`lead_break_seconds`) and after every section's last word (`min_tail_seconds`, 0.7 s) is added by ffmpeg. A `---` line or a heading without a number ends the section. Markdown formatting is stripped. Length is about 140 words per minute plus 0.7 s per beat. [script.md](/reference/script-md). |
| `cues.json` | `{"sections": {"N": {"min_seconds"?: s, "cues": [{"cue": id, "on": phrase \| "$start" \| "$end", "offset"?: s, "occurrence"?: n, "case_sensitive"?: bool, "verify"?: bool}]}}}`. Other top-level keys such as `_comment` are ignored. Tokens split on whitespace only, so a hyphenated word is one token, then lose every character outside A to Z, a to z, 0 to 9, and the straight apostrophe, and case is ignored. The cue lands on the first word of the first occurrence. A cue id may not contain `@` or a comma. [cues.json](/reference/cues-json), [Cues](/concepts/cues). |
| `deck/index.html` + `deck/decktalk-runtime.js` | `DeckTalk.scene(N, {name, camera?, steps: [{id, hold?, cues?, render, enter?, on?}]})`. `enter`, every `on[id]`, and `DeckTalk.on(id, fn)` are called as `(slide, {id, at, frozen, step})`. Reveals use `data-cue="id"`, `data-at="s"`, `data-fx`, `data-dur`, `data-count`, `data-type`, `data-sync` (one word at a time as the voice says it, text word for word as spoken, and no container animation unless `data-fx` is set), `data-tex` with `data-display`. `data-sync`, `data-count`, and `data-type` need `data-cue` or `data-at` on the same element. Inside the render backticks every backslash is doubled. The stage is 1920 by 1080. `decktalk runtime` writes `deck/decktalk-runtime.js` into a bare project. [Runtime](/reference/runtime), [Page contract](/concepts/page-contract). |
| `.env` | `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`. Exported variables work too. A silent build needs neither. |

The number `N` is the same in the script heading, the section table, the cues key, and
the scene. A cue belongs to the step with the same id, or the step whose `cues` names it,
or the step whose id is its longest prefix. `beats` notes a cue id that its page never
mentions as a quoted literal and exits 1, and `build` stops on it unless `--allow-unknown`
is given. The page records in `window.__decktalk.warnings` an id no step owns, a step that
owns no listed cue, and a `data-cue` that is not listed.

### A page from scratch

The runtime `<script>` comes before any `DeckTalk.scene` call. The runtime creates
`#dt-stage`, absolute at 1920 by 1080, and mounts each slide as a `.dt-slide` with
`position: absolute; inset: 0`, so the page sets its own background on `html, body` and
`#dt-stage`. For KaTeX, copy the cached `katex` directory that `decktalk doctor` prints,
with `katex.min.js`, `katex.min.css`, and `fonts/`, into `deck/katex/`, and put the link
and script tags before the runtime.

```html deck/index.html
<!doctype html>
<meta charset="utf-8">
<link rel="stylesheet" href="./katex/katex.min.css">
<script src="./katex/katex.min.js"></script>
<style>
  html, body, #dt-stage { margin: 0; background: #ffffff; color: #0a0a0a; }
  .slide { position: absolute; inset: 0; }
</style>
<script src="decktalk-runtime.js"></script>
<script>
DeckTalk.scene(1, { name: "Open", steps: [
  { id: "1.1", hold: 8, cues: { "1.1a": 1 }, render: () => `
    <div class="slide"><h1 data-cue="1.1a">Hello</h1></div>` },
]});
</script>
```

## Commands

```console
uv tool install decktalk                    # Python 3.12 or later, or pipx install decktalk
decktalk setup                              # once per machine: Chromium, ffmpeg, KaTeX
decktalk doctor                             # each tool and its path, exit 1 if one is missing
decktalk init DIR [--name NAME] [--force]   # scaffold, with KaTeX vendored into deck/katex/
decktalk build --silent                     # every stage with placeholder narration (a click per word), no key
decktalk build                              # the video, at build/out/<name>.mp4
decktalk build --only 3 --only 4 --preset veryfast   # record two sections again, fast encode
decktalk beats                              # where each cue phrase resolved, exit 1 if one is missing or unknown to the page
decktalk verify                             # measure every cue's offset in the final mp4
decktalk verify 3:3.1eq --cue 5:5.1cap      # measure only these cues
decktalk verify --json                      # the same result as one JSON object on stdout
decktalk shots [--step ID]                  # one PNG per step
decktalk shots --step 3.1 --cue 3.1eq       # one step frozen at the moment one cue fires
decktalk shots --section N --at S           # a frame from a playing section
decktalk status [--json]                    # timeline, what is built, captions and chapters
decktalk narrate --dry-run                  # what would be sent to the voice, without sending it
decktalk soundscape --dry-run               # same, for ambience, effects, and music
decktalk runtime                            # refresh deck/decktalk-runtime.js after an upgrade
```

Every project command takes `-p DIR` or `--project DIR`, and the default is
`DECKTALK_PROJECT`, then the current directory. `-v` and `-q` go before or after the
command name. `--only` repeats and does not take commas. `build` verifies section starts
and cuts. `verify` also measures every cue landing and its offset, except a cue that
`cues.json` marks `"verify": false`. With `SECTION:CUE` arguments or `--cue` it measures
only the cues named, even a marked one. Every cut must be quieter than -40 dBFS in its
last 150 ms, reported as `quiet` or `SPEECH AT CUT`, and clip sections are exempt. In a
silent build the placeholder track carries a click at every word start. The cue table
then gains an `a/v` column, which is the `offset` minus the click's distance from the cued
word's start, as [How it works](/concepts/how-it-works#definitions) defines it. The
`offset` column must sit within `max_offset_frames` of the cue time, and the `a/v` column
within `max_av_frames`. `status`, `beats`, `check`, `verify`,
and `doctor` take `--json` for one JSON object on stdout, `--strict` to also fail on an
uncertain finding, which is a verdict ending in a question mark or, in `beats`, a section
whose speech ends before its `min_seconds`, and `--no-fail` to always exit 0.
[CLI](/reference/cli) lists every flag.

### Reading a verify table

A `$start` cue with no offset leaves no frame before it, so `verify` reports it as
`skipped` with `REFERENCE_CLAMPED` and does not fail on it. A cue that `cues.json` marks
`"verify": false` is `skipped` with `OPTED_OUT` unless it is named on the command line.
A cue named on the command line that is not in `beats.json` is `UNRESOLVED`, which fails.
The `a/v` column shows `-` when no click lies within `click_search_seconds` of the cued
word's start, and the JSON row then carries the reason `NO_CLICK`. A silent build skips the
loudness pass, so it prints no loudness warning. `build` measures no cue and does not
stop on `TRUNCATED`, `STALLED`, or `NO COVER`, so its exit 0 says nothing about whether a
cue landed or a recording was cut short. A script that gates on the video runs
`decktalk build --silent && decktalk check && decktalk verify`.

The keyless order is `decktalk runtime` for a bare project, then `decktalk build --silent`,
then `decktalk verify`, then `decktalk shots`. `decktalk narrate --silent` followed by
`decktalk beats` shows the narration and cue tables before anything is recorded.

## Stages and artifacts

`build` runs `narrate`, `beats`, `record`, `measure`, `check`, `assemble`, and `verify` in
that order.

| Artifact | Written by | Holds |
|---|---|---|
| `build/audio/NN-slug.mp3`, `.words.json` | narrate | one section's audio and `[{word, start, end}]` |
| `build/audio/manifest.json` | narrate | one entry per section with its text hash and durations |
| `build/audio/narration.mp3`, `timeline.json` | narrate | the continuous track and each section's absolute span and words |
| `build/audio/beats.json` | beats | `{"NN": "cue@seconds,…"}` relative to the section start |
| `build/audio/beats.anchors.json` | beats | `{"NN": {"cue": seconds}}`, each cue's word start without its `offset`, which `verify` uses to find the click at the cued word in a silent build |
| `build/rec/NN-scene.webm`, `.json` | record, measure | the recording and its sidecar, with where narration t=0 sits, the page's warnings and page errors, its frame stalls, and what each `data-sync` element matched |
| `build/out/NN-section.mp4` | assemble | each section cut to its span, video only |
| `build/out/<name>.mp4` | assemble | the video with chapters muxed in, plus a timestamped copy |
| `build/out/<name>.srt`, `.vtt` | assemble | captions from the word timestamps |
| `build/out/<name>.chapters.txt` | assemble | an ffmetadata file with one chapter per section |
| `build/shots/*.png` | shots | review screenshots |

[Build artifacts](/reference/artifacts) gives every field.

## Settings

Defaults come first, then the per-machine file
(`~/Library/Application Support/decktalk/decktalk.toml` on macOS,
`%APPDATA%\decktalk\decktalk.toml` on Windows, `~/.config/decktalk/decktalk.toml` on
Linux, or the path in `DECKTALK_CONFIG`), then tables of the same name in
`decktalk.toml`, then `DECKTALK_<TABLE>_<FIELD>` variables, then the flags `--preset`,
`--crf`, `--settle`, and `--model`. The tables are `video`, `narration`, `record`,
`align`, `audio`, `verify`, and `elevenlabs`. `DECKTALK_CACHE_DIR` moves the KaTeX
cache. `DECKTALK_FFMPEG` and `DECKTALK_FFPROBE`, set together, are paths to your own
binaries, and they override the `static-ffmpeg` build and any ffmpeg on PATH.
[Configuration](/reference/configuration) lists every field.

## Exit codes and errors

| Code | When |
|---|---|
| 0 | The command succeeded. |
| 1 | The command raised a `DeckTalkError`, printed to stderr as `error: …`, which exits 1 even with `--no-fail`. A certain finding from `beats`, `check`, `verify`, or `doctor` also exits 1, such as an unmatched phrase, an unknown cue id, `TRUNCATED`, `PAGE ERROR`, `OFF CUE`, `NO CHANGE`, `UNRESOLVED`, or a missing tool, and so does an uncertain one such as `BLACK?` or `KATEX?` under `--strict`. `--no-fail` makes those four commands exit 0 on findings. `build` exits 1 on an error, on `PAGE ERROR`, on an unresolved or unknown cue unless the matching flag is given, and on `BLACK` or `SPEECH AT CUT`. |
| 2 | The command line has a usage error, such as an unknown flag or a missing command. |
| 130 | The command was interrupted. |

`ConfigError` means an input is bad or inconsistent. `MissingInputError` means an
earlier stage has not run. `ProviderError` means the speech provider refused or failed.
`ToolError` means ffmpeg or Chromium failed. Progress goes to stderr through the
`decktalk` logger. Keys are never printed.
