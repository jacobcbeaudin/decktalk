A setting is a number or a word a project could reasonably hold differently, and which some
judgement names when it fails. Every one below publishes the range that is safe to turn it through,
its true unit, the file it belongs in, and the findings its value moves. The range is the range the
loader enforces: a value outside it is refused by name, with the range it left, before any stage
runs, because a published bound you can cross into nonsense is worse than no bound at all.

Bind the schema to your project file and an editor completes every key as you type it.

```toml decktalk.toml
#:schema https://raw.githubusercontent.com/jacobcbeaudin/decktalk/main/schemas/v1/decktalk.json

[verify]
cue_offset_max_ms = 120
```

## Which value wins

Every key has a scope, in the Scope column below, and the scope names the one file that may set it.
A project key is set by these, each overriding the ones before it:

1. The default in the table below.
2. The same table in the project's `decktalk.toml`.
3. The environment variable each key publishes, such as `DECKTALK_VIDEO_PRESET`.
4. `--set table.key=value`, on any command, for one run.

A machine key is set the same way, with the per-machine settings file in place of `decktalk.toml`.

`decktalk config explain KEY` prints the value in force and the layer it comes from, so you never
have to work out which one that is.

Each file refuses a key of the other scope by name. A key about the film in the per-machine file is
refused because the file that ships has to carry whatever the machine running it believes.
`DECKTALK_MACHINE_FILE` names a different per-machine file.

| Linux | macOS | Windows |
|---|---|---|
| `$XDG_CONFIG_HOME/decktalk/machine.toml`, or `~/.config/decktalk/machine.toml` | `~/Library/Application Support/decktalk/machine.toml` | `%APPDATA%\decktalk\machine.toml` |

## Keys only a machine may set

These keys describe the machine rather than the film: where a tool or a cache lives, and how hard
this machine may be driven. A project file that sets one is refused by name, because a project
travels and a path or a limit that is right on one machine is wrong on the next. Write one into this
machine's file with `decktalk config set KEY VALUE --scope machine`, or set its environment variable.

`narration.concurrency`, `narration.retries`, `narration.store_dir`, `narration.store_wait_seconds`, `record.page_policy`, `record.concurrency`, `elevenlabs.base_url`, `dtsp.base_url`, `events.max_bytes`, `tools.chromium`, `tools.ffmpeg`, `tools.ffprobe`, `tools.timeout_seconds` and `tools.cache_dir`.

## `[video]`

These keys set the frame size and the encoding of every recording and of the final mp4.

| Key | Type | Default | Safe range | Unit | Scope | Decides | Meaning |
|---|---|---|---|---|---|---|---|
| `width` | integer | `1920` | must be between 320 and 7680 | pixels | project |  | Frame width in pixels, for every recording and the final mp4. |
| `height` | integer | `1080` | must be between 240 and 4320 | pixels | project |  | Frame height in pixels, for every recording and the final mp4. |
| `fps` | integer | `25` | must be one of 25, 30, 50, 60 | frames per second | project |  | Frame rate of the final mp4. The recorder's own rate is measured and is not a setting. |
| `preset` | string | `"medium"` | must be one of ultrafast, superfast, veryfast, faster, fast, medium, slow, slower, veryslow |  | project |  | x264 preset. Use veryfast for drafts. |
| `crf` | integer | `18` | must be between 0 and 32 |  | project | `CUE_NO_CHANGE`, `CUE_THIN_CHANGE`, `PAGE_THIN_DRAW` | x264 quality. A lower value gives higher quality and a larger file. |
| `slate_color` | string | `"0x0e1116"` | must match the pattern ^(#\|0[xX])[0-9A-Fa-f]{6}$ |  | project |  | Color of the plain frame that plays when a slate image cannot be rendered, as #RRGGBB or 0xRRGGBB. |

<Warning>
**`video.fps`** Encoding below the rate the recorder captured at drops presented frames, which both loses motion a viewer saw and corrupts the frames verify measures its own verdicts from.

**`video.crf`** Above about 32 the encoder's own ringing is larger than a small reveal, so a cue that played reads as no change and the check that would have caught it passes instead.

**`video.slate_color`** The colour is placed inside an ffmpeg filter graph and the slate page's stylesheet, so any other text could add a filter that opens a file or a rule that loads a URL.

</Warning>

## `[narration]`

These keys govern how the script is turned into audio.

| Key | Type | Default | Safe range | Unit | Scope | Decides | Meaning |
|---|---|---|---|---|---|---|---|
| `concurrency` | integer | `2` | must be between 1 and 8 |  | machine |  | How many sections `narrate` voices at once. |
| `retries` | integer | `3` | must be between 0 and 10 |  | machine |  | How many more times `narrate` asks again when the voice provider answers that it is busy or failed. |
| `mp3_bitrate` | string | `"128k"` | must be one of 64k, 96k, 128k, 160k, 192k, 256k |  | project |  | Bitrate of the mp3 files that DeckTalk writes, which are the placeholders and the joined narration. |
| `words_per_minute` | integer | `140` | must be between 60 and 300 | words per minute | project |  | Pacing of the estimated length in the narrate table. |
| `placeholder_words_per_minute` | integer | `150` | must be between 60 and 300 | words per minute | project |  | Pacing of a placeholder, the click audio a section plays until its take is voiced. |
| `lead_seconds` | number | `0.5` | must be between 0 and 5 | seconds | project |  | Silence before the first word of every spoken section, so the picture changes before the voice speaks. A section's own `lead_seconds` replaces it. |
| `placeholder_beat_seconds` | number | `0.7` | must be between 0 and 10 | seconds | project |  | Seconds each beat adds to the length of a placeholder take. |
| `tail_seconds` | number | `0.7` | must be between 0 and 10 | seconds | project | `CUT_SPEECH` | Silence after the last word of every spoken section, so a cut never falls on speech. The take is placed so that exactly this much follows its last sound. A section's own `tail_seconds` replaces it. |
| `takes_dir` | string | `"takes"` | must match the pattern ^.+$ | path | project |  | Directory inside the project that holds every take the film plays and the words its voice sent with each, which you commit so a fresh clone builds the film with no key. The take index stays under the build, because it is a cache built again from the takes. A take is looked for here first and in the machine's take store, `store_dir`, second, and a take this project voices or finds there is written here. |
| `store_dir` | string | `""` | takes any value of its type | path | machine |  | The take store: a folder outside every project where this machine keeps a second copy of every voiced take it makes and its provider words, each named by its digest. A take is looked for here after `takes_dir`, and one found here is checked and copied into `takes_dir`, so a deck with the same words as another plays it without buying it, and a take nobody committed yet survives a `git clean`. Each take is written here once, and a store that already holds a good copy keeps it. It is empty for the `takes` folder in the per-user data folder, such as `~/Library/Application Support/decktalk/takes` on macOS. |
| `context_characters` | integer | `1500` | must be between 0 and 5000 | characters | project |  | Characters of each neighbour section sent with a request, for continuous prosody. |
| `timeout_seconds` | integer | `180` | must be between 10 and 1800 | seconds | project |  | Seconds before a speech request times out. |
| `store_wait_seconds` | integer | `900` | must be between 1 and 36000 | seconds | machine |  | Seconds a run waits while another run on this machine voices the same take into the take store, before it is refused as locked. Keep it above one whole take request, `timeout_seconds` times `retries` plus one, with the waits between them. The default covers that at the default `timeout_seconds` and `retries`: four attempts of 180 seconds and three waits of at most 30 seconds, 810 seconds. |
| `sound_end_noise_dbfs` | number | `-35.0` | must be between -60 and -25 | dBFS | project | `CUT_SPEECH` | Level under which the tail of a take counts as silence, which is where the take's sound ends. |
| `sound_end_min_run_seconds` | number | `0.05` | must be between 0.02 and 0.5 | seconds | project | `CUT_SPEECH` | Shortest run under the noise level that counts as the end of a take's sound. |

<Warning>
**`narration.concurrency`** A voice provider limits requests per account, and a busy answer is retried rather than paid twice.

**`narration.takes_dir`** An empty value, a directory outside the project, an absolute path, the project directory itself, a directory inside the build directory or one that holds it is refused when the project loads, because a voiced take must land in a folder the project keeps, and a project someone else wrote would otherwise choose where this machine reads and writes its takes.

**`narration.store_dir`** It holds the spoken words of every script voiced on this machine, so keep it out of a synced or shared folder. A relative path, a folder inside the project or one inside the tool cache is refused when the project loads. Write an absolute path or one that starts with ~.

**`narration.store_wait_seconds`** Below the length of one take request, a run is refused while another run's healthy request is still being answered.

**`narration.sound_end_noise_dbfs`** Above about -25 dBFS the scan calls quiet speech silence, so the take is placed early and the cut that follows it lands on a word.

</Warning>

## `[record]`

These keys tune the headless Chromium recording and how the start of the section clock is found in it.

| Key | Type | Default | Safe range | Unit | Scope | Decides | Meaning |
|---|---|---|---|---|---|---|---|
| `settle_seconds` | number | `0.5` | must be between 0 and 30 | seconds | project |  | Shortest wait after the page is ready and before the start of the section clock. |
| `cover_min_seconds` | number | `1.5` | must be between 0 and 30 | seconds | project |  | Shortest time from the start of the recorder to the start of the section clock. |
| `color_scheme` | string | `"light"` | must be one of light, dark, no-preference |  | project |  | Color scheme that Chromium reports to the page. |
| `page_policy` | string | `"trusted"` | must be one of trusted, untrusted |  | machine |  | How far `record`, `check` and `storyboard` trust a page. `trusted` lets a page reach the network as a browser would. `untrusted` turns the Chromium sandbox on and refuses every request that is not for the project's own origin, through every channel a page can open. It is the machine's to set, so a project someone else wrote cannot trust its own page. |
| `concurrency` | integer | `0` | must be between 0 and 16 |  | machine |  | How many page sections `record` records at once. Zero chooses from the CPU this process may use, which inside a container is its quota rather than the host's core count. |
| `retries` | integer | `2` | must be between 0 and 10 |  | project |  | How many more times `record` records a section whose frames stalled. |
| `cover_scan_seconds` | number | `4.0` | must be between 0 and 30 | seconds | project |  | Seconds at the start of each recording that `record` scans for the magenta cover. |
| `fallback_first_paint_seconds` | number | `1.1` | must be between 0 and 10 | seconds | project |  | Guessed first paint when `record` finds no cover and no painted frame. `record` adds `settle_seconds` to it. |
| `cover_min_luma` | number | `70.0` | must be between 40 and 120 | luma | project |  | A cover frame has an average luma above this. |
| `cover_max_luma` | number | `140.0` | must be between 80 and 200 | luma | project |  | A cover frame has an average luma below this. |
| `cover_min_chroma` | number | `165.0` | must be between 128 and 255 | chroma | project |  | A cover frame has an average U and an average V above this. |
| `painted_peak_min_luma` | number | `60.0` | must be between 1 and 200 | luma | project |  | A painted frame has a brightest luma above this. |
| `painted_mean_max_luma` | number | `120.0` | must be between 20 and 240 | luma | project |  | A painted frame has an average luma below this, so a white flash does not count as the picture. |
| `truncated_slack_seconds` | number | `0.5` | must be between 0 and 5 | seconds | project | `RECORD_TRUNCATED` | Allowed shortfall of a recording against its requested length. |
| `frame_gap_max_ms` | integer | `150` | must be between 100 and 2000 | milliseconds | project | `RECORD_STALLED` | Longest gap between two presented frames after the start of the section clock. A longer gap makes `record` try again. |

<Warning>
**`record.page_policy`** A service that renders pages other people wrote sets `untrusted` on its machine, because a trusted page can reach anything the machine can, including a cloud metadata endpoint.

**`record.concurrency`** Each recording needs about two dedicated CPUs to present its frames on time, and a starved recording stalls or lands its reveals late, so a number above the machine's share costs correctness rather than only speed.

**`record.frame_gap_max_ms`** The runtime reports a gap no finer than its own reporting floor, so a limit under that floor makes every section stall and every retry spend the recording again.

</Warning>

## `[audio]`

These keys are the final audio: its encoding, and the loudness it is normalised to and judged against.

| Key | Type | Default | Safe range | Unit | Scope | Decides | Meaning |
|---|---|---|---|---|---|---|---|
| `bitrate` | string | `"192k"` | must be one of 96k, 128k, 160k, 192k, 256k, 320k |  | project |  | AAC bitrate of the final mp4. |
| `sample_rate` | integer | `48000` | must be one of 44100, 48000 | hertz | project |  | Audio sample rate of the final mp4. Every audio input is resampled to it once. |
| `channels` | integer | `2` | must be one of 1, 2 |  | project |  | Audio channels of the final mp4. |
| `target_lufs` | number | `-16.0` | must be between -30 and -9 | LUFS | project | `MIX_LOUDNESS` | Programme loudness the final mp4 is normalised to. |
| `true_peak_max_dbtp` | number | `-1.5` | must be between -9 and -0.1 | dBTP | project | `MIX_LOUDNESS` | Highest true peak the normalised mix may reach. |
| `range_max_lu` | number | `11.0` | must be between 1 and 20 | LU | project |  | The loudness range the measurement is made against. It is not a limit, and no mix fails on it. |

<Warning>
**`audio.true_peak_max_dbtp`** Four times oversampling under-reads a true peak and the AAC encode overshoots on top of that, so a ceiling above about -1 dBTP reports a clean mix that clips on a listener's decoder.

</Warning>

## `[verify]`

These keys are the limits `verify` judges the assembled mp4 against.

| Key | Type | Default | Safe range | Unit | Scope | Decides | Meaning |
|---|---|---|---|---|---|---|---|
| `after_dip_seconds` | number | `0.2` | must be between 0 and 2 | seconds | project | `RECORD_BLACK` | Seconds after a section start to the frame that the start check reads. |
| `reference_lead_extra_ms` | number | `0.0` | must be between 0 and 80 | milliseconds | project | `CUE_OFF` | Extra lead added to the reference frame beyond the one the offset limit implies. |
| `probe_delays_seconds` | array | `[0.7, 1.5]` | must hold at least 1 and must hold values that each must be above 0 and must be at most 10 | seconds | project | `CUE_NO_CHANGE` | Seconds after the cue time for each probe. The later probe catches a slow reveal. |
| `probe_diff_luma` | integer | `40` | must be between 4 and 200 | luma | project | `CUE_NO_CHANGE`, `CUE_THIN_CHANGE` | Luma difference a pixel must exceed to count as changed, for the probes and the control shares. |
| `changed_share_min_percent` | number | `0.1` | must be between 0.001 and 5 | percent | project | `CUE_NO_CHANGE`, `CUE_THIN_CHANGE`, `PAGE_THIN_DRAW` | Smallest share of the frame, in percent, that the reported probe must find changed. |
| `margin_min_points` | number | `0.1` | must be between 0.001 and 5 | percentage points | project | `CUE_NO_CHANGE`, `CUE_THIN_CHANGE` | Smallest margin, in percentage points, between the reported probe and its control. |
| `thin_change_factor` | number | `3.0` | must be between 1 and 10 |  | project | `CUE_THIN_CHANGE` | A passing cue whose changed share or margin is under this many times its floor is a warning rather than clean. A value of 1 turns that second opinion off. |
| `onset_rise_points` | number | `0.01` | must be between 0.001 and 1 | percentage points | project | `CUE_OFF`, `CUE_NO_ONSET` | Rise in the changed share from one frame to the next that marks the onset, in percentage points. |
| `onset_diff_luma` | integer | `12` | must be between 2 and 60 | luma | project | `CUE_OFF`, `CUE_NO_ONSET` | Luma difference a pixel must exceed to count as changed, for the onset scan alone. |
| `click_search_seconds` | number | `0.25` | must be between 0.02 and 2 | seconds | project | `CUE_OFF` | Seconds on each side of the cued word's start that the click search covers. |
| `click_floor_dbfs` | number | `-38.0` | must be between -60 and -24 | dBFS | project | `CUE_OFF` | Level a sample must exceed for the click search to call it the click. |
| `cue_offset_max_ms` | number | `80.0` | must be between 20 and 400 | milliseconds | project | `CUE_OFF` | How far the measured onset may sit from the cue time, early or late. |
| `av_offset_max_ms` | number | `120.0` | must be between 80 and 500 | milliseconds | project | `CUE_OFF` | How far the click may sit from the word it marks, early or late. It is wider than the cue limit because the click carries the encoder's own jitter as well. |
| `black_max_luma` | number | `60.0` | must be between 1 and 200 | luma | project | `RECORD_BLACK` | A frame whose brightest luma is at most this is black, whether `record` or `verify` reads it. |
| `cut_window_seconds` | number | `0.15` | must be between 0.01 and 2 | seconds | project | `CUT_SPEECH` | Seconds of narration before each cut that the cut check measures. |
| `cut_max_dbfs` | number | `-40.0` | must be between -90 and -20 | dBFS | project | `CUT_SPEECH` | Loudest level the cut window may reach before the cut counts as falling on speech. |
| `cut_change_max_percent` | number | `0.1` | must be between 0.001 and 10 | percent | project | `CUT_POP` | Largest share of the frame, in percent, that may change across a cut into a seamless section. |

<Warning>
**`verify.reference_lead_extra_ms`** The lead is already the offset limit plus the grid guard, so extra lead is only ever the escape hatch for a deck whose reference frame is still inside its own reveal. Above about 80 milliseconds the reference frame reaches back into the previous cue and the check compares two changes rather than one.

**`verify.probe_diff_luma`** A high value counts only a change that crosses most of the range, so a reveal that fades in or moves a light element on a light slide reads as no change at all.

**`verify.changed_share_min_percent`** Above about 5 percent only a change across most of the slide passes, so every small reveal in the deck reports a failure it cannot fix.

**`verify.onset_rise_points`** The rise is measured over a quarter-size frame, so one point is already tens of thousands of pixels. Above about one point no frame ever qualifies, every cue reports a null offset, and the check that names a late reveal stops running while the run still exits clean.

**`verify.click_floor_dbfs`** DeckTalk generates its own click at -24 dBFS, so a floor at or above that level finds no click at all and every a/v row measures nothing while reporting no failure.

**`verify.cue_offset_max_ms`** A viewer sees a reveal land late at about a fifth of a second, so above roughly 200 milliseconds the limit passes films whose pictures visibly miss their words.

**`verify.av_offset_max_ms`** An mp3 frame smears a transient across about 26 milliseconds and the encode adds its own, so a limit under 80 milliseconds reports a failure that no edit to the film can clear.

</Warning>

## `[voice]`

These keys are the three every voice has: which provider reads the script, in which voice and at what pace. Everything a provider is particular about, its own fields, its model and its rate, is in that provider's own table, so changing `provider` never sends one vendor's fields or model to another.

| Key | Type | Default | Safe range | Unit | Scope | Decides | Meaning |
|---|---|---|---|---|---|---|---|
| `provider` | string | `"elevenlabs"` | takes any value of its type |  | project |  | The speech provider that reads the script, which is a name the machine's own map answers. An unregistered name loads, and fails only when a run asks it for a take, which a run that does not spend never does. DeckTalk ships `elevenlabs`, the cloud voice whose own keys are `[elevenlabs]`, and `dtsp`, a provider served by a local server, whose own keys are `[dtsp]`. |
| `id` | string | `""` | must match the pattern ^[A-Za-z0-9_-]*$ |  | project |  | The voice that reads the script, as the provider names it. It is a published name rather than a credential, so it is committed with the project, and it is one of the inputs every take is named by. `DECKTALK_VOICE_ID` overrides it for anyone who keeps it out of the file. |
| `speed` | number | `1.0` | must be between 0.7 and 1.2 |  | project |  | How fast the voice speaks, as a multiple of its natural pace. |

<Warning>
**`voice.id`** The id is placed in the path of every speech request, so a value that could hold a slash, a dot or a query would let a project somebody else wrote send the key to another endpoint of the service.

**`voice.speed`** The provider refuses a multiple outside its own range, so a slower read is a script change rather than a setting.

</Warning>

|---|---|---|---|---|---|---|---|

|---|---|---|---|---|---|---|---|

| `stability` | number | `0.55` | must be between 0 and 1 |  | project |  | How closely the voice holds one delivery across takes. |
| `similarity_boost` | number | `0.75` | must be between 0 and 1 |  | project |  | How closely the voice holds to the original recording it was cloned from. |
| `style` | number | `0.0` | must be between 0 and 1 |  | project |  | How much expressive style the voice adds beyond the words. |

| `base_url` | string | `"https://api.elevenlabs.io/v1"` | takes any value of its type |  | machine |  | Base URL of the ElevenLabs API, which the voice and the score both send their requests and the key to. |

</Warning>

## The numbers that are not settings

These are the numbers that decide something and are still not settings. A derived number is written
as its expression, so it follows the keys it reads at every frame size and every rate. A constant is
a fact about a codec, a standard, or a tool DeckTalk drives, and it is fixed for the same reason a
sample rate is. Neither can be set, and both are here so that a setting you cannot find is a number you
can read.

| Number | Kind | Formula | At the defaults | Why |
|---|---|---|---|---|
| `verify.probe_width` | derived | `video.width // PROBE_SCALE` | 480 pixels | Derived: every share is measured over the frame scaled down by PROBE_SCALE, at every frame size. |
| `verify.probe_height` | derived | `video.height // PROBE_SCALE` | 270 pixels | Derived: every share is measured over the frame scaled down by PROBE_SCALE, at every frame size. |
| `verify.block_width` | derived | `video.width // BLOCK_PX` | 240 pixels | Derived: one pixel per H.264 transform block, so the block average cancels the encoder's ringing at every frame size rather than only at 1080p. |
| `verify.block_height` | derived | `video.height // BLOCK_PX` | 135 pixels | Derived: one pixel per H.264 transform block, so the block average cancels the encoder's ringing at every frame size rather than only at 1080p. |
| `verify.reference_lead_seconds` | derived | `verify.cue_offset_max_ms / 1000 + GUARD_FRAMES / CAPTURE_FPS + verify.reference_lead_extra_ms / 1000` | 0.14 seconds | Derived: the reference frame has to sit outside the window the offset limit allows, or the check compares a cue against a frame the same cue had already changed. |
| `CAPTURE_FPS` | constant | `25` | 25 frames per second | Truth: the rate the recorder captures at, which DeckTalk cannot set and so never asks for. |
| `PROBE_SCALE` | constant | `4` | 4 times | Calibration: a frame a quarter the film's size keeps every share a cue can move while comparing a sixteenth of the pixels. |
| `BLOCK_PX` | constant | `8` | 8 pixels | Truth: the H.264 transform block the block-averaged copy of a frame cancels ringing over. |
| `GUARD_FRAMES` | constant | `1.5` | 1.5 frames | Truth: half a frame of rounding guard on each side of the window the offset limit allows. |
| `REPORT_FRAME_GAP_MS` | constant | `100` | 100 milliseconds | Calibration: the runtime's own reporting floor, under which a frame gap cannot be seen. |
| `CLICK_LEVEL_DBFS` | constant | `-24.0` | -24.0 dBFS | Truth: the level DeckTalk generates its own click at, which every click floor sits under. |
| `MEASURABLE_SPAN_SECONDS` | constant | `0.5` | 0.5 seconds | Truth: the span at which an effect covers its own cue, which is the ceiling every declared span, every scaled span and every staggered total is held under. |
