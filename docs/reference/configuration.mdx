A setting is a number or a word a project could reasonably hold differently, and which some
judgement names when it fails. Every one below publishes the range that is safe to turn it through,
its true unit, the file it belongs in, and the findings its value moves. The range is the range the
loader enforces: a value outside it is refused with the file and the line that wrote it, because a
published bound you can cross into nonsense is worse than no bound at all.

Bind the schema to your project file and an editor completes every key as you type it.

```toml decktalk.toml
#:schema https://decktalk.ai/schema/decktalk-1.json

[verify]
cue_offset_max_ms = 120
```

## Which value wins

Five layers can set a key. Each one overrides the layers before it.

1. The default in the table below.
2. The same table in the per-machine settings file.
3. The same table in the project's `decktalk.toml`.
4. The environment variable each key publishes, such as `DECKTALK_VIDEO_PRESET`.
5. `--set table.key=value`, on any command, for one run.

`decktalk config explain KEY` prints those five layers with the winner marked, so you never have to
work out which one is in force.

The per-machine settings file holds machine keys alone. A key about the film in that file is
refused by name, because the file that ships has to carry whatever the machine running it believes.

| Linux | macOS | Windows |
|---|---|---|
| `$XDG_CONFIG_HOME/decktalk/decktalk.toml`, or `~/.config/decktalk/decktalk.toml` | `~/Library/Application Support/decktalk/decktalk.toml` | `%APPDATA%\decktalk\decktalk.toml` |

## `[video]`

These keys set the frame size and the encoding of every recording and of the final mp4.

| Key | Type | Default | Safe range | Unit | Decides | Meaning |
|---|---|---|---|---|---|---|
| `width` | integer | `1920` | must be between 320 and 7680 | pixels |  | Frame width in pixels, for every recording and the final mp4. |
| `height` | integer | `1080` | must be between 240 and 4320 | pixels |  | Frame height in pixels, for every recording and the final mp4. |
| `output_fps` | integer | `25` | must be one of 25, 30, 50, 60 | frames per second |  | Frame rate of the final mp4. The recorder's own rate is measured and is not a knob. |
| `preset` | string | `"medium"` | must be one of ultrafast, superfast, veryfast, faster, fast, medium, slow, slower, veryslow |  |  | x264 preset. Use veryfast for drafts. |
| `crf` | integer | `18` | must be between 0 and 32 |  | `CUE_NO_CHANGE`, `CUE_THIN_CHANGE`, `PAGE_THIN_DRAW` | x264 quality. A lower value gives higher quality and a larger file. |
| `audio_bitrate` | string | `"192k"` | must be one of 96k, 128k, 160k, 192k, 256k, 320k |  |  | AAC bitrate of the final mp4. |
| `sample_rate` | integer | `48000` | must be one of 44100, 48000 | hertz |  | Audio sample rate of the final mp4. Every audio input is resampled to it once. |
| `channels` | integer | `2` | must be one of 1, 2 |  |  | Audio channels of the final mp4. |
| `slate_color` | string | `"0x0e1116"` | takes any value of its type |  |  | Color of the plain frame that plays when a slate image cannot be rendered. |

<Warning>
**`video.output_fps`** Encoding below the rate the recorder captured at drops presented frames, which both loses motion a viewer saw and corrupts the frames verify measures its own verdicts from.

**`video.crf`** Above about 32 the encoder's own ringing is larger than a small reveal, so a cue that played reads as no change and the check that would have caught it passes instead.

</Warning>

## `[narration]`

These keys govern how the script is turned into audio.

| Key | Type | Default | Safe range | Unit | Decides | Meaning |
|---|---|---|---|---|---|---|
| `model` | string | `"eleven_multilingual_v2"` | takes any value of its type |  |  | Speech model. `[voice] model` and `narrate --model` override it. |
| `output_format` | string | `"mp3_44100_128"` | takes any value of its type |  |  | Audio format that the speech provider returns. It is part of the narration cache key. |
| `mp3_bitrate` | string | `"128k"` | must be one of 64k, 96k, 128k, 160k, 192k, 256k |  |  | Bitrate of the mp3 files that DeckTalk writes, which are the click tracks and the joined narration. |
| `words_per_minute` | integer | `140` | must be between 60 and 300 | words per minute |  | Pacing of the estimated length in the narrate table. |
| `silent_words_per_minute` | integer | `150` | must be between 60 and 300 | words per minute |  | Pacing of the click track in a build without voice. |
| `lead_seconds` | number | `0.5` | must be between 0 and 5 | seconds |  | Silence before the first word of every spoken section, so the picture changes before the voice speaks. A section's own `lead_seconds` replaces it. |
| `silent_beat_seconds` | number | `0.7` | must be between 0 and 10 | seconds |  | Seconds each beat adds to a section's length in a build without voice. |
| `tail_min_seconds` | number | `0.7` | must be between 0 and 10 | seconds | `CUT_SPEECH` | Silence after the last word of every spoken section, so a cut never falls on speech. The take is placed so that exactly this much follows its last sound. A section's own `tail_seconds` replaces it. |
| `cache_dir` | string | `""` | takes any value of its type | path |  | Directory that holds the take files and their words files, each named by its content hash. It is empty for `build/narrate/` inside the project, and a path here keeps the voiced takes when `build/` is deleted and lets many projects share one cache. |
| `context_chars` | integer | `1500` | must be between 0 and 5000 | characters |  | Characters of each neighbour section sent with a request, for continuous prosody. |
| `timeout_seconds` | integer | `180` | must be between 10 and 1800 | seconds |  | Seconds before a speech request times out. |
| `sound_end_noise_dbfs` | number | `-35.0` | must be between -60 and -25 | dBFS | `CUT_SPEECH` | Level under which the tail of a take counts as silence, which is where the take's sound ends. |
| `sound_end_min_run_seconds` | number | `0.05` | must be between 0.02 and 0.5 | seconds | `CUT_SPEECH` | Shortest run under the noise level that counts as the end of a take's sound. |

<Warning>
**`narration.sound_end_noise_dbfs`** Above about -25 dBFS the scan calls quiet speech silence, so the take is placed early and the cut that follows it lands on a word.

</Warning>

| `painted_peak_luma_min` | number | `60.0` | must be between 1 and 200 | luma |  | A painted frame has a brightest luma above this. |

| `truncated_slack_seconds` | number | `0.5` | must be between 0 and 5 | seconds | `PAGE_TRUNCATED` | Allowed shortfall of a recording against its requested length. |

**`record.frame_gap_max_ms`** The runtime reports a gap no finer than its own reporting floor, so a limit under that floor makes every section stall and every retry spend the recording again.

## `[verify]`

These keys are the limits `verify` judges the assembled mp4 against.

| Key | Type | Default | Safe range | Unit | Decides | Meaning |
|---|---|---|---|---|---|---|
| `after_dip_seconds` | number | `0.2` | must be between 0 and 2 | seconds | `PAGE_BLACK` | Seconds after a section start to the frame that the start check reads. |
| `reference_lead_extra_ms` | number | `0.0` | must be between 0 and 80 | milliseconds |  | Extra lead added to the reference frame beyond the one the offset limit implies. |
| `probe_delays_seconds` | array | `[0.7, 1.5]` | must hold at least 1 and must hold values that each must be above 0 and must be at most 10 | seconds | `CUE_NO_CHANGE` | Seconds after the cue time for each probe. The later probe catches a slow reveal. |
| `probe_diff_luma` | integer | `40` | must be between 4 and 200 | luma | `CUE_NO_CHANGE`, `CUE_THIN_CHANGE` | Luma difference a pixel must exceed to count as changed, for the probes and the control shares. |
| `changed_share_min_percent` | number | `0.1` | must be between 0.001 and 5 | percent | `CUE_NO_CHANGE`, `CUE_THIN_CHANGE` | Smallest share of the frame, in percent, that the reported probe must find changed. |
| `margin_min_points` | number | `0.1` | must be between 0.001 and 5 | percentage points | `CUE_NO_CHANGE`, `CUE_THIN_CHANGE` | Smallest margin, in percentage points, between the reported probe and its control. |
| `thin_change_factor` | number | `3.0` | must be between 1 and 10 |  | `CUE_THIN_CHANGE` | A passing cue whose changed share or margin is under this many times its floor is uncertain rather than clean. A value of 1 turns that second opinion off. |
| `onset_rise_points` | number | `0.01` | must be between 0.001 and 1 | percentage points | `CUE_OFF`, `CUE_NO_ONSET` | Rise in the changed share from one frame to the next that marks the onset, in percentage points. |
| `onset_diff_luma` | integer | `12` | must be between 2 and 60 | luma | `CUE_OFF`, `CUE_NO_ONSET` | Luma difference a pixel must exceed to count as changed, for the onset scan alone. |
| `click_search_seconds` | number | `0.25` | must be between 0.02 and 2 | seconds | `CUE_OFF` | Seconds on each side of the cued word's start that the click search covers. |
| `click_floor_dbfs` | number | `-38.0` | must be between -60 and -24 | dBFS | `CUE_OFF` | Level a sample must exceed for the click search to call it the click. |
| `cue_offset_max_ms` | number | `80.0` | must be between 20 and 400 | milliseconds | `CUE_OFF` | How far the measured onset may sit from the cue time, early or late. |
| `av_offset_max_ms` | number | `120.0` | must be between 80 and 500 | milliseconds | `CUE_OFF` | How far the click may sit from the word it marks, early or late. It is wider than the cue limit because the click carries the encoder's own jitter as well. |
| `black_max_luma` | number | `60.0` | must be between 1 and 200 | luma | `PAGE_BLACK` | A frame whose brightest luma is at most this is black, whether `record` or `verify` reads it. |
| `cut_window_seconds` | number | `0.15` | must be between 0.01 and 2 | seconds | `CUT_SPEECH` | Seconds of narration before each cut that the cut check measures. |
| `cut_max_dbfs` | number | `-40.0` | must be between -90 and -20 | dBFS | `CUT_SPEECH` | Loudest level the cut window may reach before the cut counts as falling on speech. |
| `cut_change_max_percent` | number | `0.1` | must be between 0.001 and 10 | percent | `CUT_POP` | Largest share of the frame, in percent, that may change across a cut into a seamless section. |

<Warning>
**`verify.reference_lead_extra_ms`** The lead is already the offset limit plus the grid guard, so extra lead is only ever the escape hatch for a deck whose reference frame is still inside its own reveal. Above about 80 milliseconds the reference frame reaches back into the previous cue and the check compares two changes rather than one.

**`verify.probe_diff_luma`** A high value counts only a change that crosses most of the range, so a reveal that fades in or moves a light element on a light slide reads as no change at all.

**`verify.changed_share_min_percent`** Above about 5 percent only a change across most of the slide passes, so every small reveal in the deck reports a failure it cannot fix.

**`verify.onset_rise_points`** The rise is measured over a quarter-size frame, so one point is already tens of thousands of pixels. Above about one point no frame ever qualifies, every cue reports a null offset, and the check that names a late reveal stops running while the run still exits clean.

**`verify.click_floor_dbfs`** DeckTalk generates its own click at -24 dBFS, so a floor at or above that level finds no click at all and every a/v row measures nothing while reporting no failure.

**`verify.cue_offset_max_ms`** A viewer sees a reveal land late at about a fifth of a second, so above roughly 200 milliseconds the limit passes films whose pictures visibly miss their words.

**`verify.av_offset_max_ms`** An mp3 frame smears a transient across about 26 milliseconds and the encode adds its own, so a limit under 80 milliseconds reports a failure that no edit to the film can clear.

</Warning>

## `[voice]`

These keys are what the speech provider is asked for and what its characters cost.

| Key | Type | Default | Safe range | Unit | Decides | Meaning |
|---|---|---|---|---|---|---|
| `stability` | number | `0.55` | must be between 0 and 1 |  |  | How closely the voice holds one delivery across takes. |
| `similarity_boost` | number | `0.75` | must be between 0 and 1 |  |  | How closely the voice holds to the original recording it was cloned from. |
| `style` | number | `0.0` | must be between 0 and 1 |  |  | How much expressive style the voice adds beyond the words. |
| `speaker_boost` | boolean | `true` | takes any value of its type |  |  | Whether the provider applies its own speaker boost to the take. |
| `speed` | number | `1.0` | must be between 0.7 and 1.2 |  |  | How fast the voice speaks, as a multiple of its natural pace. |
| `price_per_1000_characters` | number | `0.0` | must be between 0 and 100 | currency per 1000 characters |  | What this project's plan charges per thousand characters of speech. |

<Warning>
**`voice.stability`** The provider takes a share and refuses anything else, so a value read as a percentage fails the request rather than the load.

**`voice.speed`** The provider refuses a multiple outside its own range, so a slower read is a script change rather than a knob.

**`voice.price_per_1000_characters`** It is zero until somebody states it, and a spend cap refuses a run while the price is still the default, because DeckTalk would otherwise be capping a spend against a number it invented.

</Warning>

## The numbers that are not knobs

These are the numbers that decide something and are still not settings. A derived number is written
as its expression, so it follows the keys it reads at every frame size and every rate. A constant is
a fact about a codec, a standard, or a tool DeckTalk drives, and it is fixed for the same reason a
sample rate is. Neither can be set, and both are here so that a knob you cannot find is a number you
can read.

| Number | Kind | Formula | At the defaults | Why |
|---|---|---|---|---|
| `verify.probe_width` | derived | `video.width // 4` | 480 pixels | Derived: a quarter-size frame is what every share is measured over, at every frame size. |
| `verify.probe_height` | derived | `video.height // 4` | 270 pixels | Derived: a quarter-size frame is what every share is measured over, at every frame size. |
| `verify.block_width` | derived | `video.width // BLOCK_PX` | 240 pixels | Derived: one pixel per H.264 transform block, so the block average cancels the encoder's ringing at every frame size rather than only at 1080p. |
| `verify.block_height` | derived | `video.height // BLOCK_PX` | 135 pixels | Derived: one pixel per H.264 transform block, as the block width is. |
| `verify.reference_lead_seconds` | derived | `verify.cue_offset_max_ms / 1000 + GUARD_FRAMES / CAPTURE_FPS + verify.reference_lead_extra_ms / 1000` | 0.14 seconds | Derived: the reference frame has to sit outside the window the offset limit allows, or the check compares a cue against a frame the same cue had already changed. |
| `CAPTURE_FPS` | constant | `25` | 25 frames per second | Truth: the rate the recorder captures at, which DeckTalk cannot set and so never asks for. |
| `BLOCK_PX` | constant | `8` | 8 pixels | Truth: the H.264 transform block the block-averaged copy of a frame cancels ringing over. |
| `GUARD_FRAMES` | constant | `1.5` | 1.5 frames | Truth: half a frame of rounding guard on each side of the window the offset limit allows. |
| `REPORT_FRAME_GAP_MS` | constant | `100` | 100 milliseconds | Calibration: the runtime's own reporting floor, under which a frame gap cannot be seen. |
| `CLICK_LEVEL_DBFS` | constant | `-24.0` | -24.0 dBFS | Truth: the level DeckTalk generates its own click at, which every click floor sits under. |
| `MEASURABLE_SPAN_SECONDS` | constant | `0.5` | 0.5 seconds | Truth: the span at which an effect covers its own cue, which is the ceiling every declared span, every scaled span and every staggered total is held under. |
