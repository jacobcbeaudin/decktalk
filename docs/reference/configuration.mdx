A setting is a number or a word a project could reasonably hold differently, and which some
judgement names when it fails. Every one below publishes the range that is safe to turn it through,
its true unit, the file it belongs in, and the findings its value moves. The range is the range the
loader enforces: a value outside it is refused by name, with the range it left, before any stage
runs, because a published bound you can cross into nonsense is worse than no bound at all.

Bind the schema to your project file and an editor completes every key as you type it.

```toml decktalk.toml
#:schema https://raw.githubusercontent.com/jacobcbeaudin/decktalk/main/schemas/v1/decktalk.json

[verify]
cue_offset_max_ms = 120
```

## Which value wins

Every key has a scope, in the Scope column below, and the scope names the one file that may set it.
A project key is set by these, each overriding the ones before it:

1. The default in the table below.
2. The same table in the project's `decktalk.toml`.
3. The environment variable each key publishes, such as `DECKTALK_VIDEO_PRESET`.
4. `--set table.key=value`, for one run, on `status`, `check`, `words`, `storyboard`, `serve`, `narrate`, `cue`, `record`, `score`, `assemble`, `verify`, `build` and `clip`.

A machine key is set the same way, with the per-machine settings file in place of `decktalk.toml`.

`decktalk config explain KEY` prints the value in force and the layer it comes from, so you never
have to work out which one that is.

Each file refuses a key of the other scope by name. A key about the film in the per-machine file is
refused because the file that ships has to carry whatever the machine running it believes.
`DECKTALK_MACHINE_FILE` names a different per-machine file.

| Linux | macOS | Windows |
|---|---|---|
| `$XDG_CONFIG_HOME/decktalk/machine.toml`, or `~/.config/decktalk/machine.toml` | `~/Library/Application Support/decktalk/machine.toml` | `%APPDATA%\decktalk\machine.toml` |

## Keys only a machine may set

These keys describe the machine rather than the film: where a tool or a cache lives, and how hard
this machine may be driven. A project file that sets one is refused by name, because a project
travels and a path or a limit that is right on one machine is wrong on the next. Write one into this
machine's file with `decktalk config set KEY VALUE --scope machine`, or set its environment variable.

`narration.concurrency`, `narration.retries`, `narration.store_dir`, `record.page_policy`, `record.programs`, `record.concurrency`, `record.chunk_frames_min`, `record.chunk_startup_seconds`, `record.step_seconds`, `record.page_deadline_seconds`, `record.deadline_slowdown`, `record.renderer_retries`, `record.encode_threads`, `elevenlabs.base_url`, `dtsp.base_url`, `dtsp.handshake_seconds`, `events.max_bytes`, `tools.chromium`, `tools.ffmpeg`, `tools.ffprobe`, `tools.timeout_seconds`, `tools.fix_timeout_seconds` and `tools.cache_dir`.

## `[video]`

These keys set the frame size and the encoding of every recording and of the final mp4.

| Key | Type | Default | Safe range | Unit | Scope | Decides | Meaning |
|---|---|---|---|---|---|---|---|
| `size` | string | `"wide"` | must match the pattern ^(?:wide\|square\|vertical\|(?:(?:2[4-9]\|[3-9][0-9]\|[1-6][0-9]{2}\|7[0-5][0-9]\|76[0-7])[02468]\|7680)x(?:(?:2[4-9]\|[3-9][0-9]\|[1-6][0-9]{2}\|7[0-5][0-9]\|76[0-7])[02468]\|7680))$ | pixels | project |  | The frame of every recording and of the final mp4: wide (1920 by 1080), square (1080 by 1080), vertical (1080 by 1920), or WIDTHxHEIGHT in pixels. A page is laid out on a canvas of the frame's shape whose short side is 1080 CSS pixels, which it reads as --dt-width and --dt-height, so a square copy of a project is the project copied with this one key changed. |
| `fps` | integer | `25` | must be one of 25, 30, 50, 60 | frames per second | project |  | Frame rate of every recording and of the final mp4. The recorder steps the section clock one frame of this rate at a time, so every frame of a film is the page at its own second. |
| `preset` | string | `"medium"` | must be one of ultrafast, superfast, veryfast, faster, fast, medium, slow, slower, veryslow |  | project |  | x264 preset. Use veryfast for drafts. |
| `crf` | integer | `18` | must be between 0 and 32 |  | project | `CUE_NO_CHANGE`, `CUE_THIN_CHANGE`, `PAGE_THIN_DRAW` | x264 quality. A lower value gives higher quality and a larger file. |
| `slate_color` | string | `"0x0e1116"` | must match the pattern ^(#\|0[xX])[0-9A-Fa-f]{6}$ |  | project |  | Color of the plain frame that plays when a slate image cannot be rendered, as #RRGGBB or 0xRRGGBB. |

<Warning>
**`video.size`** An odd side cannot be encoded, because the film's colour is stored at half the frame's width and height, and a side past the range is a frame Chromium and x264 are not held to drawing.

**`video.crf`** Above about 32 the encoder's own ringing is larger than a small reveal, so a cue that played reads as no change and the check that would have caught it passes instead.

**`video.slate_color`** The colour is placed inside an ffmpeg filter graph and the slate page's stylesheet, so any other text could add a filter that opens a file or a rule that loads a URL.

</Warning>

## `[narration]`

These keys govern how the script is turned into audio.

| Key | Type | Default | Safe range | Unit | Scope | Decides | Meaning |
|---|---|---|---|---|---|---|---|
| `voice` | string | `"narrator"` | must match the pattern ^[a-z][a-z0-9]*$ |  | project |  | The default voice: the voice that reads every section no voice direction in the script names, and every turn of a section that names none. It names a [voices.NAME] table, and with no such table written it is a voice at every default. |
| `concurrency` | integer | `2` | must be between 1 and 8 |  | machine |  | How many turns `narrate` voices at once. |
| `retries` | integer | `3` | must be between 0 and 10 |  | machine |  | How many more times `narrate` asks again when the voice provider or the aligner answers that it is busy or failed. |
| `mp3_bitrate` | string | `"128k"` | must be one of 64k, 96k, 128k, 160k, 192k, 256k |  | project |  | Bitrate of the mp3 files that DeckTalk writes, which are the placeholders and the joined narration. |
| `words_per_minute` | integer | `140` | must be between 60 and 300 | words per minute | project |  | Pacing of the estimated length in the narrate table. |
| `placeholder_words_per_minute` | integer | `150` | must be between 60 and 300 | words per minute | project |  | Pacing of a placeholder, the click audio a section plays until its take is voiced. |
| `lead_seconds` | number | `0.5` | must be between 0 and 5 | seconds | project |  | Silence before the first word of every spoken section, so the picture changes before the voice speaks. A section's own `lead_seconds` replaces it. |
| `turn_gap_seconds` | number | `0.3` | must be between 0 and 5 | seconds | project |  | Silence between two turns of a section when no timed pause is written where the voice changes. A [pause N] written there replaces it, and neither is part of either turn's take. |
| `placeholder_beat_seconds` | number | `0.7` | must be between 0 and 10 | seconds | project |  | Seconds each beat adds to the length of a placeholder take. |
| `tail_seconds` | number | `0.7` | must be between 0 and 10 | seconds | project | `CUT_SPEECH` | Silence after the last word of every spoken section, so a cut never falls on speech. The take is placed so that exactly this much follows its last sound. A section's own `tail_seconds` replaces it. |
| `takes_dir` | string | `"takes"` | must match the pattern ^.+$ | path | project |  | Directory inside the project that holds every take the film plays and the words its voice sent with each, which you commit so a fresh clone builds the film with no key. The take index stays under the build, because it is a cache built again from the takes. A take is looked for here first and in the machine's take store, `store_dir`, second, and a take this project voices or finds there is written here. |
| `store_dir` | string | `""` | takes any value of its type | path | machine |  | The take store: a folder outside every project where this machine keeps a second copy of every voiced take it makes and its provider words, each named by its digest. A take is looked for here after `takes_dir`, and one found here is checked and copied into `takes_dir`, so a deck with the same words as another plays it without buying it, and a take nobody committed yet survives a `git clean`. Each take is written here once, and a store that already holds a good copy keeps it. It is empty for the `takes` folder in the per-user data folder, such as `~/Library/Application Support/decktalk/takes` on macOS. |
| `context_characters` | integer | `1500` | must be between 0 and 5000 | characters | project |  | Characters of the neighbouring turns sent with a request, for continuous prosody: the end of the turn before and the start of the turn after that the same voice reads among the turns the run selects. 0 sends no neighbouring text, so each turn is sent on its own. |
| `timeout_seconds` | integer | `180` | must be between 10 and 1800 | seconds | project |  | Seconds before a speech or alignment request times out. With `retries` it also sets how long a run waits while another run on this machine voices the same take into the take store: one whole take request, every attempt this long with the waits between them, before it is refused as locked. |
| `sound_end_noise_dbfs` | number | `-35.0` | must be between -60 and -25 | dBFS | project | `CUT_SPEECH`, `TAKE_WORD_CUT`, `TAKE_SILENT` | Level under which the tail of a take counts as silence, which is where the take's sound ends. |
| `sound_end_min_run_seconds` | number | `0.05` | must be between 0.02 and 0.5 | seconds | project | `CUT_SPEECH`, `TAKE_WORD_CUT`, `TAKE_SILENT` | Shortest run under the noise level that counts as the end of a take's sound. |

<Warning>
**`narration.concurrency`** A voice provider limits requests per account, and a busy answer is retried rather than paid twice.

**`narration.takes_dir`** An empty value, a directory outside the project, an absolute path, the project directory itself, a directory inside the build directory or one that holds it is refused when the project loads, because a voiced take must land in a folder the project keeps, and a project someone else wrote would otherwise choose where this machine reads and writes its takes.

**`narration.store_dir`** It holds the spoken words of every script voiced on this machine, so keep it out of a synced or shared folder. A relative path, a folder inside the project or one inside the tool cache is refused when the project loads. Write an absolute path or one that starts with ~.

**`narration.sound_end_noise_dbfs`** Above about -25 dBFS the scan calls quiet speech silence, so the take is placed early and the cut that follows it lands on a word.

</Warning>

## `[record]`

These keys tune how `record` opens each page section in headless Chromium and steps it frame by frame.

| Key | Type | Default | Safe range | Unit | Scope | Decides | Meaning |
|---|---|---|---|---|---|---|---|
| `color_scheme` | string | `"light"` | must be one of light, dark, no-preference |  | project |  | Color scheme that Chromium reports to the page. |
| `page_policy` | string | `"trusted"` | must be one of trusted, untrusted |  | machine |  | How far `record`, `check` and `storyboard` trust a page. `trusted` lets a page reach the network as a browser would. `untrusted` turns the Chromium sandbox on and refuses every request that is not for the project's own origin, through every channel a page can open. It is the machine's to set, so a project someone else wrote cannot trust its own page. |
| `programs` | string | `"refuse"` | must be one of refuse, ask, run |  | machine |  | Whether `record` runs the programs a project names, which are its render sections' `render_command`. A program runs with your user's rights and can read every file you can, the project's `.env` included. `refuse` runs none of them. `ask` lists every program the run would start and runs them only when a person at a terminal answers yes, and refuses without a terminal, under `--no-input` and under `--json`. `run` runs them without asking. Under the `untrusted` page policy no program runs whatever this says. It is the machine's to set, so a project cannot allow its own programs. |
| `concurrency` | integer | `0` | must be between 0 and 16 |  | machine |  | How many recorders `record` runs at once, each a Chromium of its own that records one chunk of a section after another. Zero chooses from the CPU this process may use, which inside a container is its quota rather than the host's core count. |
| `chunk_frames_min` | integer | `50` | must be between 1 and 100000 | frames | machine |  | Fewest frames `record` puts in one chunk when it splits a section across its recorders. A section shorter than two chunks of this length is recorded whole by one recorder. |
| `chunk_startup_seconds` | number | `0.2` | must be above 0 and must be at most 60 | seconds | machine |  | How long one chunk takes to start on this machine: a page opened and loaded in a recorder's Chromium and stepped to the chunk's first frame. `record` splits a section into about sqrt(step_seconds * steps * recorders / chunk_startup_seconds) chunks, never more than the recorders, where steps are what its last recording took. |
| `step_seconds` | number | `0.014` | must be above 0 and must be at most 10 | seconds | machine |  | How long one recorder takes to step its page once on this machine, the capture of the frame it lands on included, which `record` weighs against `chunk_startup_seconds` when it splits a section. |
| `page_deadline_seconds` | number | `15.0` | must be between 1 and 600 | seconds | machine |  | Longest one call into a page may take before DeckTalk closes the page and stops with a TOOL error naming where it was stuck: a load, a step, a capture, a still or a report. `record` names the section and the frame, and `check`, `storyboard`, `cue` and `assemble` hold the pages they open to it too. It is many times the longest a step measures, so only a page that stopped answering reaches it, such as one that spins its main thread or waits on a font or an image that never arrives. |
| `deadline_slowdown` | number | `30.0` | must be between 1 and 10000 |  | machine |  | How many times slower than this machine's `chunk_startup_seconds` and `step_seconds` a recording may run before `record` stops it. A chunk may take `page_deadline_seconds` plus this many times chunk_startup_seconds + step_seconds * frames, and the whole run this many times the time its chunks take spread over the recorders, plus its longest chunk, so a page that answers every call and never gets on still ends with a TOOL error. |
| `renderer_retries` | integer | `1` | must be between 0 and 5 |  | machine |  | How many more times `record` records a chunk, in a fresh page, when the page's renderer crashed or its page was closed under it. A frame is a function of its index, so a chunk recorded again is the same frames. |
| `encode_threads` | integer | `0` | must be between 0 and 64 |  | machine |  | Threads each recorder's lossless encode runs on. Zero shares this process's CPUs among the recorders at once, at least one each. Every piece of a run is encoded with the same number, and the frames are the same whatever it is. |
| `skip_still` | boolean | `true` | takes any value of its type |  | project |  | Write a frame again rather than capture it when the page reports that nothing it draws changed since the frame before, which is most frames of a narrated slide, and write every frame before the next change the page reports without stepping the page to each. The frames are the same either way, so it changes how long `record` takes and nothing it writes. |

<Warning>
**`record.page_policy`** A service that renders pages other people wrote sets `untrusted` on its machine, because a trusted page can reach anything the machine can, including a cloud metadata endpoint.

**`record.programs`** `run` executes whatever a project's decktalk.toml names as soon as `record` or `build` reaches it, so set it only on a machine that builds projects whose programs you have read.

**`record.concurrency`** Each recorder steps its own Chromium and its own encode, so a number above the machine's share makes every chunk wait on the others and the run slower rather than faster.

**`record.chunk_frames_min`** Every chunk loads the page again, so chunks much shorter than a page load spend the machine on loading rather than on frames.

**`record.chunk_startup_seconds`** A start-up stated far too low splits short sections into chunks that each spend more loading the page than recording it.

**`record.page_deadline_seconds`** A deadline set near the time a frame takes stops healthy recordings on a busy machine.

**`record.deadline_slowdown`** A value near one stops a recording that a loaded machine is merely slow to make, because the two calibrations are this machine's speed when it is idle.

**`record.encode_threads`** x264 buffers frames for every thread it runs, so a large number costs each recorder hundreds of megabytes and buys no speed, because the encode is never what a recording waits on.

</Warning>

## `[verify]`

These keys are the limits `verify` judges the assembled mp4 against.

| Key | Type | Default | Safe range | Unit | Scope | Decides | Meaning |
|---|---|---|---|---|---|---|---|
| `after_dip_seconds` | number | `0.2` | must be between 0 and 2 | seconds | project | `RECORD_BLACK` | Seconds after a section start to the frame that the start check reads. |
| `reference_lead_extra_ms` | number | `0.0` | must be between 0 and 80 | milliseconds | project | `CUE_OFF` | Extra lead added to the reference frame beyond the one the offset limit implies. |
| `probe_delays_seconds` | array | `[0.7, 1.5]` | must hold at least 1 and must hold values that each must be above 0 and must be at most 10 | seconds | project | `CUE_NO_CHANGE` | Seconds after the cue time for each probe. The later probe catches a slow reveal. |
| `probe_diff_luma` | integer | `40` | must be between 4 and 200 | luma | project | `CUE_NO_CHANGE`, `CUE_THIN_CHANGE` | Luma difference a pixel must exceed to count as changed, for the probes and the control shares. |
| `changed_share_min_percent` | number | `0.1` | must be between 0.001 and 5 | percent | project | `CUE_NO_CHANGE`, `CUE_THIN_CHANGE`, `PAGE_THIN_DRAW` | Smallest share of the frame, in percent, that the reported probe must find changed. |
| `margin_min_points` | number | `0.1` | must be between 0.001 and 5 | percentage points | project | `CUE_NO_CHANGE`, `CUE_THIN_CHANGE` | Smallest margin, in percentage points, between the reported probe and its control. |
| `thin_change_factor` | number | `3.0` | must be between 1 and 10 |  | project | `CUE_THIN_CHANGE` | A passing cue whose changed share or margin is under this many times its floor is a warning rather than clean. A value of 1 turns that second opinion off. |
| `onset_rise_points` | number | `0.01` | must be between 0.001 and 1 | percentage points | project | `CUE_OFF`, `CUE_NO_ONSET` | Rise in the changed share from one frame to the next that marks the onset, in percentage points. |
| `onset_diff_luma` | integer | `12` | must be between 2 and 60 | luma | project | `CUE_OFF`, `CUE_NO_ONSET` | Luma difference a pixel must exceed to count as changed, for the onset scan alone. |
| `click_search_seconds` | number | `0.25` | must be between 0.02 and 2 | seconds | project | `CUE_OFF` | Seconds on each side of the cued word's start that the click search covers. |
| `click_floor_dbfs` | number | `-38.0` | must be between -60 and -24 | dBFS | project | `CUE_OFF` | Level a sample must exceed for the click search to call it the click. |
| `cue_offset_max_ms` | number | `80.0` | must be between 20 and 400 | milliseconds | project | `CUE_OFF`, `MOTION_OFF`, `MOTION_NO_EDGE` | How far the measured onset may sit from the cue time, early or late. |
| `motion_floor_percent` | number | `0.5` | must be between 0.05 and 20 | percent | project | `MOTION_OFF`, `MOTION_NO_EDGE` | How much of a moving element's own area must change from one frame to the next for verify to read it as moving, which is where a motion's departure and arrival are found. |
| `motion_mask_max_percent` | number | `40.0` | must be between 5 and 90 | percent | project | `MOTION_MASK_LARGE` | The most of the frame verify may mask out of a cue's measurement before it says it measured less of the picture than usual. |
| `av_offset_max_ms` | number | `120.0` | must be between 80 and 500 | milliseconds | project | `CUE_OFF` | How far the click may sit from the word it marks, early or late. It is wider than the cue limit because the click carries the encoder's own jitter as well. |
| `black_max_luma` | number | `60.0` | must be between 1 and 200 | luma | project | `RECORD_BLACK` | A frame whose brightest luma is at most this is black, whether `record` or `verify` reads it. |
| `cut_window_seconds` | number | `0.15` | must be between 0.01 and 2 | seconds | project | `CUT_SPEECH` | Seconds of narration before each cut that the cut check measures. |
| `cut_max_dbfs` | number | `-40.0` | must be between -90 and -20 | dBFS | project | `CUT_SPEECH` | Loudest level the cut window may reach before the cut counts as falling on speech. |
| `cut_change_max_percent` | number | `0.1` | must be between 0.001 and 10 | percent | project | `CUT_POP` | Largest share of the frame, in percent, that may change across a cut into a seamless section. |

<Warning>
**`verify.reference_lead_extra_ms`** The lead is already the offset limit plus the grid guard, so extra lead is only ever the escape hatch for a deck whose reference frame is still inside its own reveal. Above about 80 milliseconds the reference frame reaches back into the previous cue and the check compares two changes rather than one.

**`verify.probe_diff_luma`** A high value counts only a change that crosses most of the range, so a reveal that fades in or moves a light element on a light slide reads as no change at all.

**`verify.changed_share_min_percent`** Above about 5 percent only a change across most of the slide passes, so every small reveal in the deck reports a failure it cannot fix.

**`verify.onset_rise_points`** The rise is measured over a quarter-size frame, so one point is already tens of thousands of pixels. Above about one point no frame ever qualifies, every cue reports a null offset, and the check that names a late reveal stops running while the run still exits clean.

**`verify.click_floor_dbfs`** DeckTalk generates its own click at -24 dBFS, so a floor at or above that level finds no click at all and every a/v row measures nothing while reporting no failure.

**`verify.cue_offset_max_ms`** A viewer sees a reveal land late at about a fifth of a second, so above roughly 200 milliseconds the limit passes films whose pictures visibly miss their words.

**`verify.motion_floor_percent`** Above a few percent the slow last frames of a firm arrival read as still, so its arrival is measured early and a motion that landed on its word fails.

**`verify.motion_mask_max_percent`** Near the top of the range a cue is judged on a sliver of the frame, so a reveal under a large declared motion passes on very little evidence.

**`verify.av_offset_max_ms`** An mp3 frame smears a transient across about 26 milliseconds and the encode adds its own, so a limit under 80 milliseconds reports a failure that no edit to the film can clear.

</Warning>

## `[voices]`

Every voice of the project, one table per voice, each named by the name a voice direction in the script calls it by. The table `[narration] voice` names is the default voice.

These keys are the three every voice has: which provider reads its turns, in which voice and at what pace. Each voice is one `[voices.NAME]` table. Everything a provider is particular about, its own fields, its model and its rate, is in that provider's own table, and a voice may state any of that table's chosen keys for itself alone, so changing `provider` never sends one vendor's fields or model to another.

Write one table per voice, named by the name the script's voice directions use, such as
`[voices.guest]`. A voice name is a lower-case letter followed by lower-case letters and digits. Each
key below is set for that voice alone, and its variable spells the voice's name, such as
`DECKTALK_VOICES_GUEST_ID`. A key that names a provider table's key reads that table's value until
the voice states its own.

| Key | Type | Default | Safe range | Unit | Scope | Decides | Meaning |
|---|---|---|---|---|---|---|---|
| `provider` | string | `"elevenlabs"` | takes any value of its type |  | project |  | The speech provider that reads this voice's turns, which is a name the machine's own map answers. An unregistered name loads, and fails only when a run asks it for a take, which a run that does not spend never does. DeckTalk ships `elevenlabs`, the cloud voice whose own keys are `[elevenlabs]`, and `dtsp`, a provider served by a local server, whose own keys are `[dtsp]`. |
| `id` | string | `""` | must match the pattern ^[A-Za-z0-9_-]*$ |  | project |  | The voice that reads this voice's turns, as the provider names it. | `speed` | number | `1.0` | must be between 0.7 and 1.2 |  | project |  | How fast the voice speaks, as a multiple of its natural pace. |
| `model` | string | `elevenlabs.model` or `dtsp.model` | takes any value of its type |  | project |  | This voice's own model, over [elevenlabs or dtsp] model, which every voice of that provider reads unless it sets its own. |
| `stability` | number | `elevenlabs.stability` | must be between 0 and 1 |  | project |  | This voice's own stability, over [elevenlabs] stability, which every voice of that provider reads unless it sets its own. |

## The numbers that are not settings


These are the numbers that decide something and are still not settings. A derived number is written
as its expression, so it follows the keys it reads at every frame size and every rate. A constant is
a fact about a codec, a standard, or a tool DeckTalk drives, and it is fixed for the same reason a
sample rate is. Neither can be set, and both are here so that a setting you cannot find is a number you
can read.

| Number | Kind | Formula | At the defaults | Why |
|---|---|---|---|---|
| `verify.probe_width` | derived | `the frame width video.size names // PROBE_SCALE` | 480 pixels | Derived: every share is measured over the frame scaled down by PROBE_SCALE, at every frame size. |
| `verify.probe_height` | derived | `the frame height video.size names // PROBE_SCALE` | 270 pixels | Derived: every share is measured over the frame scaled down by PROBE_SCALE, at every frame size. |
| `verify.block_width` | derived | `the frame width video.size names // BLOCK_PX` | 240 pixels | Derived: one pixel per H.264 transform block, so the block average cancels the encoder's ringing at every frame size rather than only at 1080p. |
| `verify.block_height` | derived | `the frame height video.size names // BLOCK_PX` | 135 pixels | Derived: one pixel per H.264 transform block, so the block average cancels the encoder's ringing at every frame size rather than only at 1080p. |
| `verify.reference_lead_seconds` | derived | `verify.cue_offset_max_ms / 1000 + GUARD_FRAMES / video.fps + verify.reference_lead_extra_ms / 1000` | 0.14 seconds | Derived: the reference frame has to sit outside the window the offset limit allows, or the check compares a cue against a frame the same cue had already changed. |
| `record.truncated_slack_seconds` | derived | `1 / video.fps` | 0.04 seconds | Derived: the recorder writes a section's span rounded to the nearest whole frame, so a whole recording runs at most half a frame under it, and one more than a frame under it stopped early. |
| `SLOWEST_FPS` | constant | `25` | 25 frames per second | Truth: the slowest rate a film is recorded at, whose frame is the step every page range is written in. |
| `PROBE_SCALE` | constant | `4` | 4 times | Calibration: a frame a quarter the film's size keeps every share a cue can move while comparing a sixteenth of the pixels. |
| `BLOCK_PX` | constant | `8` | 8 pixels | Truth: the H.264 transform block the block-averaged copy of a frame cancels ringing over. |
| `GUARD_FRAMES` | constant | `1.5` | 1.5 frames | Truth: half a frame of rounding guard on each side of the window the offset limit allows. |
| `CLICK_LEVEL_DBFS` | constant | `-24.0` | -24.0 dBFS | Truth: the level DeckTalk generates its own click at, which every click floor sits under. |
| `MEASURABLE_SPAN_SECONDS` | constant | `0.5` | 0.5 seconds | Truth: the span at which an effect covers its own cue, which is the ceiling every declared span, every scaled span and every staggered total is held under. |
