```text
decktalk [-v | -q] [-p DIR] <command> [flags]
```

Every project command takes `--project DIR`, or `-p DIR`. The default is the
`DECKTALK_PROJECT` variable, then the current directory. Each command reads `.env` from
the project and never prints a key. Progress goes to stderr, and the tables go to stdout.
`-v` or `--verbose` shows debug logging, including every ffmpeg command line, and `-q` or
`--quiet` shows warnings only. Both go before or after the command name. `--version`
prints the version. A flag that repeats, such as `--only`, takes one value each time and
does not take commas. `status`, `beats`, `check`, `verify`, and `doctor` also take
`--json`, `--strict`, and `--no-fail`, which
[Machine-readable output](#machine-readable-output) describes.

## Machine-readable output

`status`, `beats`, `check`, `verify`, and `doctor` share three flags.

| Flag | Meaning |
|---|---|
| `--json` | The flag prints the result as one JSON object on stdout instead of the tables. Progress still goes to stderr. |
| `--strict` | The flag also makes the command exit 1 on an uncertain finding, which is a verdict that ends in a question mark or, in `beats`, a section whose speech ends before its `min_seconds`. |
| `--no-fail` | The flag makes the command exit 0 even when a check fails, for scripts that read the table or the JSON themselves. |

Every object opens with the same four keys, and a fifth key named after the command holds
the result.

```json
{
  "command": "verify",
  "version": "<version>",
  "ok": true,
  "findings": { "certain": 0, "uncertain": 0 },
  "verify": { "...": "the result, described below" }
}
```

| Key | Meaning |
|---|---|
| `command` | The key names the command that ran, such as `verify`. |
| `version` | The key holds the DeckTalk version that ran the command. |
| `ok` | The key is `true` when the command would exit 0 without `--no-fail`. `--strict` counts, so an uncertain finding makes it `false` under `--strict`. |
| `findings.certain` | The key counts the certain findings the command made. Any one of them exits 1. |
| `findings.uncertain` | The key counts the uncertain findings the command made. They exit 1 only with `--strict`. |

| Command | The key named after it holds |
|---|---|
| `doctor` | The key holds `components`, a list of `{name, ok, detail}` with one entry per row of the table. |
| `status` | The key holds six entries. `project` has `root`, `name`, `script`, `script_exists`, `cues`, and `cues_exists`. `sections` is a list of `{key, kind, source, recorded, cut}`, where `kind` is `page` or `clip`. `timeline` has `exists`, `estimated`, `total_seconds`, and `sections`, a list of `{key, title, start, end, duration}`. `beats` has `exists` and `sections`, a list of `{key, cues}`. `final` has `path`, `exists`, and `duration`. `outputs` has `srt`, `vtt`, and `chapters`, each `{path, exists}`. |
| `beats` | The key holds `estimated`, `beats_file`, `unresolved`, `unknown`, and `sections`, a list of `{key, speech_end, min_seconds, skipped, cues, notes}`. Each note is `{cue, verdict, detail}`, where `verdict` is `UNRESOLVED`, `UNKNOWN`, or `null` for a note without a verdict. |
| `check` | The key holds `recordings`, a list of `{key, file, duration, wanted, y10, y50, y90, max50, verdicts, stall_ms, page_errors}`. `verdicts` lists the verdict names of the row, and `stall_ms` holds the length of a `STALLED` gap. |
| `verify` | The key holds `final`, `total_seconds`, `silent`, and three lists. `starts` holds `{key, start, probe_at, yavg, ymax, verdict}`, `cuts` holds `{key, cut_at, rms_db, verdict}`, and `cues` holds `{section, cue, cue_seconds, final_seconds, changed_percent, control_percent, offset_ms, av_ms, verdict, reason}`. |

In `beats` and in `status.beats`, `cues` is an object that maps each cue id to its seconds
after the section start. Every `key` is a two-digit section string such as `"03"`, and
`section` in a `verify` cue row is an integer such as `3`.

Numbers are JSON numbers, a value that does not exist is `null`, and every verdict is
a verdict name that the table prints. Paths are relative to the project root and use
forward slashes on every platform. The exceptions are `project.root` in `status`, which is
absolute, and a path outside the project, which stays absolute. `doctor` runs outside any
project, so its details keep full paths. Only the object goes to stdout, so
`decktalk verify --json > verify.json` captures nothing else.

`status` reads what exists and judges nothing, so its findings are always zero and it
exits 0 unless the project cannot be loaded.

## Setting up a machine and a project

### `decktalk setup`

This command downloads headless Chromium into Playwright's cache, ffmpeg and ffprobe into
the Python environment through `static-ffmpeg`, and a KaTeX release into a per-user
cache, once per machine. On Linux it also installs Chromium's system libraries, which asks
for sudo unless setup runs as root. When the KaTeX download fails, `setup` warns, and `init` writes pages that
load KaTeX from a CDN instead. [Requirements and costs](/requirements) lists what each
download needs.

### `decktalk doctor`

This command reports the Python, Chromium, ffmpeg, ffprobe, per-machine config file, and
KaTeX found, and it exits 1 when a tool is missing. Each `MISSING` row is a certain
finding. The config row is `ok` whether or not the file exists. The command changes
nothing.

```text
python    ok      3.13 (.venv/bin/python3)
chromium  ok      <version>
ffmpeg    ok      .venv/lib/python3.13/site-packages/static_ffmpeg/bin/darwin/ffmpeg
ffprobe   ok      .venv/lib/python3.13/site-packages/static_ffmpeg/bin/darwin/ffprobe
config    ok      none (optional, at ~/Library/Application Support/decktalk/decktalk.toml)
katex     ok      ~/Library/Caches/decktalk/katex/<version>
```

A `katex` row marked `MISSING` means the cache is empty, so `init` would write a page
that loads KaTeX from a CDN. Run `setup` first.

| Flag | Meaning |
|---|---|
| `--json`, `--strict`, `--no-fail` | These flags work as [Machine-readable output](#machine-readable-output) describes. |

### `decktalk init DIR`

This command scaffolds a project with a working example deck and copies the cached KaTeX into
`deck/katex/`.

| Flag | Meaning |
|---|---|
| `--name NAME` | The flag sets the project name. The default is the directory name. It may contain letters, digits, dots, dashes, and underscores. |
| `--force` | The flag lets the command write into a directory that is not empty. |

### `decktalk runtime`

This command copies the packaged `decktalk-runtime.js` over every copy in the project, or into
`deck/` when there is none. Run it after an upgrade.

## Turning the script into narration and cues

### `decktalk narrate`

This command turns the script into per-section audio with word timestamps, then builds the continuous
track and `timeline.json`. It caches each section by its text and voice settings, and it
prints the narrate table and the timeline.

| Flag | Meaning |
|---|---|
| `--only N` | The command acts only on these section numbers. Repeat the flag for several. |
| `--force` | The flag ignores the text-hash cache and synthesizes every section, which spends credits on all of them. |
| `--allow-placeholders` | The flag lets the command synthesize a section that still has a `[CAPITAL]` placeholder. |
| `--dry-run` | The flag parses the script and prints the exact text per section, the voice settings, and the table. The command makes no API call. |
| `--silent` | The flag writes placeholder tracks with a soft click at every estimated word start, together with estimated word times. The command needs no key, and the placeholders replace the voiced audio and empty the narration cache. |
| `--model M` | The flag sets the ElevenLabs model for this run. |

### `decktalk beats`

This command resolves every cue phrase to a second and prints a table of sections, their speech end,
their `min_seconds`, and their resolved cues. It also reads the page of each page section
and notes every cue id that the page never mentions as a quoted literal, as
`4.1answer: not in deck/index.html`. It writes `beats.json` either way. A phrase it
cannot find and a cue id that its page never mentions are certain findings, so `beats`
exits 1 on either. A section whose speech ends before its `min_seconds` is an uncertain
finding, so it exits 1 only with `--strict`.

| Flag | Meaning |
|---|---|
| `--allow-unknown` | The command still notes a cue id that appears nowhere in the page that plays it, but it does not count the id as a finding, for a page that builds its ids at run time. |
| `--json`, `--strict`, `--no-fail` | These flags work as [Machine-readable output](#machine-readable-output) describes. |

### `decktalk soundscape`

This command generates the ambience, the sound effects, and the underscore from the
prompts in `decktalk.toml` with the ElevenLabs sound and music endpoints, so it spends
credits, as [Requirements and costs](/requirements) explains. Each output has a manifest
with its request hash, and an output whose manifest matches is skipped.

| Flag | Meaning |
|---|---|
| `--only NAME` | The command generates only this item, which is `ambience`, `music`, or an effect name. Repeat the flag for several. |
| `--force` | The flag regenerates an item even if its file exists. |
| `--dry-run` | The flag prints every request without sending it. The command needs no key. |

## Recording the pages

### `decktalk record`

This command records each page section with headless Chromium, for its span in the timeline plus
`extra_seconds`.

| Flag | Meaning |
|---|---|
| `--only N` | The command acts only on these section numbers. Repeat the flag for several. |
| `--seconds S` | The flag overrides every duration, which is useful for smoke tests and works without a timeline. |
| `--settle S` | The flag sets the seconds after load before the clock starts, for this run. |
| `--no-beats` | The recording uses the page's autoplay timing instead of `?beats=`. |

### `decktalk measure`

This command finds narration t=0 in each recording from the magenta cover and writes it to the
sidecar. The table shows the trim point, the recorder's own wall-clock estimate, and the
method.

```text
sec    trim    wall  method
 01   1.440   1.505  cover (36 magenta frames)
```

A method beginning `NO COVER` means the cover was not found and the trim is a guess.

| Flag | Meaning |
|---|---|
| `--only N` | The command acts only on these section numbers. Repeat the flag for several. |

### `decktalk check`

This command checks each recording's length against what was requested and its luma at ten, fifty,
and ninety percent of the way through.

```text
sec  webm_s   want_s   Y10    Y50    Y90    MAX50   verdict
01   21.4     18.7     232    229    229    245     ok
02   30.4     28.9     230    227    227    243     ok
03   73.6     72.5     229    229    228    245     ok
04   20.8     19.3     227    226    225    245     ok
05   13.7     12.2     106    230    228    245     ok
```

| Verdict | Certain | Meaning |
|---|---|---|
| `ok` | | The recording shows nothing suspect. |
| `NO COVER` | yes | `measure` found no magenta run, so the alignment is a guess. |
| `BLACK?` | no | The brightest pixel at the midpoint is below `black_ymax`, so the page probably drew nothing. |
| `TRUNCATED` | yes | The recording is shorter than requested by more than `truncated_slack_seconds`. |
| `KATEX?` | no | The page warned that KaTeX never loaded or that a `data-tex` value could not be parsed, so an equation may be plain text or red. |
| `STALLED` | yes | The page went longer than `stall_ms` between two frames while recording, so a reveal may have been captured late. The recorder already retried up to `retries` times. |
| `PAGE ERROR` | yes | The page threw a script error or exposed no `window.__decktalk.catalog`, so the section recorded a blank stage. `build` stops on it. |

Several verdicts may appear together, separated by spaces. `check` exits 1 when any
recording has a certain verdict. A verdict that ends in a question mark is uncertain, so it
exits 1 only with `--strict`.

| Flag | Meaning |
|---|---|
| `--only N` | The command acts only on these section numbers. Repeat the flag for several. |
| `--json`, `--strict`, `--no-fail` | These flags work as [Machine-readable output](#machine-readable-output) describes. |

## Assembling and checking the video

### `decktalk assemble`

This command cuts, concatenates, mixes, normalizes, writes captions and chapters, and
publishes the video. It prints the final path and length.

| Flag | Meaning |
|---|---|
| `--nomix` | The mix carries narration and clip audio only, with no beds and no effects. |
| `--no-loudnorm` | The flag skips loudness normalization. |
| `--strict` | The flag makes the command fail on a missing clip or recording instead of substituting a slate or black, and fail on a loudness miss. A silent build skips the loudness pass, so it has no loudness to fail on. |
| `--preset P` | The flag sets the x264 preset for this run, and `veryfast` suits drafts. |
| `--crf N` | The flag sets the x264 quality for this run. |

### `decktalk verify [SECTION:CUE ...]`

This command confirms that every section opens on a real frame, that the narration is quiet in the
last 150 ms before every cut, and that the picture changed at every cue in
`build/audio/beats.json`, in section order and then cue time. For a cue that changed the
picture it also measures how far from the cue the first changed frame sits. After a
silent build the cue table gains an `a/v` column, which
[How it works](/concepts/how-it-works#definitions) defines. A cue that `cues.json` marks
`"verify": false` is reported as `skipped` and never fails. Name cues as arguments or
with `--cue` to check only those, in the order given. A cue named this way is measured
even when `cues.json` marks it `"verify": false`.

| Flag | Meaning |
|---|---|
| `SECTION:CUE …` | The arguments name the only cues to check, such as `3:3.1eq`. |
| `--cue SECTION:CUE` | The flag adds one more cue to check, after any positional cues. Repeat it for several. |
| `--only N` | The command measures only the cues of these section numbers, and it always checks every section start and cut. Repeat the flag for several. |
| `--json`, `--strict`, `--no-fail` | These flags work as [Machine-readable output](#machine-readable-output) describes. |

```text
sec   cut at  before cut  result
 01    18.35   -130.2 dB  quiet
 02    47.01   -125.4 dB  quiet
 03   119.15   -130.2 dB  quiet
 04   138.21   -125.4 dB  quiet
 05   148.45   -120.0 dB  quiet

check                 cue       at   chg %   ctl %   offset     a/v  result
3:3.1p1             39.37    86.37    0.56    0.00    -10ms    -9ms  changed
3:3.1eq             41.71    88.71    0.41    0.00    -30ms   -32ms  changed
3:3.1crawl              -        -       -       -        -       -  skipped OPTED_OUT: cues.json sets "verify": false
5:5.1cap             2.80   141.00    0.66    0.00    -40ms   -44ms  changed
```

The table above is shortened. A plain `decktalk verify` on the scaffold lists every
resolved cue.

| Result | Certain | Meaning |
|---|---|---|
| `ok` | | The section starts on a real frame. |
| `BLACK` | yes | The section starts on a dark frame. |
| `quiet` | | The narration in the last `cut_window_seconds` before the cut is below `cut_max_db`. Clip sections are not listed. |
| `SPEECH AT CUT` | yes | The narration is still sounding there, so the cut is early. |
| `changed` | | The cue changed the picture, its `offset` is within `max_offset_frames` of its cue time, and after a silent build its `a/v` value is within `max_av_frames`. |
| `OFF CUE` | yes | The picture changed, but the `offset` or the `a/v` value is past its limit. The note says by how much. |
| `NO CHANGE` | yes | The picture did not change enough, or no more than it was already changing. |
| `UNRESOLVED` | yes | A cue named as an argument or with `--cue` is not in `beats.json`. |
| `skipped` | | Nothing was measured, and the reason follows the verdict. `OPTED_OUT` means `cues.json` sets `"verify": false` on the cue. `REFERENCE_CLAMPED` means no reference frame fits after the section's fade-in and before the cue, which is usual for a `$start` cue. `SECTION_NOT_ASSEMBLED` means the section has no `NN-section.mp4`. `TOO_CLOSE_TO_END` means every probe would fall past the end of the section. |

`verify` exits 1 on any certain result. A measured cue whose `a/v` column shows `-` after
a silent build carries the reason `NO_CLICK` in the JSON, which means that no click was
found within `click_search_seconds` of the cued word's start. That cue is still judged on its
`offset`, so `NO_CLICK` is not a failure.

[How it works](/concepts/how-it-works#what-verify-measures) explains the columns.

### `decktalk shots`

This command writes one PNG per step, one PNG of a step frozen at one of its cues, or frames from a
section while it plays with its real cues.

| Flag | Meaning |
|---|---|
| `--page F` | The command captures the steps of this page file, and the flag can be repeated to capture several pages. The default is every page in `decktalk.toml`. |
| `--step ID` | The command captures only these step ids. Repeat the flag for several. |
| `--cue ID` | The flag freezes the step at the moment this cue fires. The step's cues fire in autoplay order up to and including this one, and an element that waits for a later cue of the step stays hidden. The flag needs exactly one `--step` and does not combine with `--section`. Repeat it for one PNG per cue. |
| `--section N` | The command plays this section with its resolved cues and captures frames from it. |
| `--at S` | The frame is captured this many seconds after narration t=0. Repeat the flag for several. The default is 0.5. |

Step screenshots land at `build/shots/step-<id>.png`, and a step frozen at a cue lands at
`build/shots/step-<id>-cue-<cue>.png`, such as `step-3.1-cue-3.1eq.png`. Both go in a
subdirectory per page when there are several pages. Frames land at
`build/shots/section-NN-at-<S>s.png`.

A step frozen at a cue opens the page as `?step=ID&cue=CUE`, which
[the runtime reference](/reference/runtime#url-parameters) describes. Handlers still
receive `ctx.frozen` as true, so a figure that draws its end state when frozen, such as
the scaffold's scene 3 surface, shows that end state at every cue. When the id is not one
of the step's cues, the page warns and the whole step is captured.

## Everything at once

### `decktalk build`

This command runs narrate, beats, record, measure, check, assemble, and verify in order
and prints each stage's table. It stops with exit 1 after the beats table when a cue
phrase is not found, unless `--allow-unresolved` is given, and when a cue id appears
nowhere in the page that plays it, unless `--allow-unknown` is given. It stops with exit 1
after the check table when a page threw an uncaught error or exposed no catalog, which
`check` reports as `PAGE ERROR`. Its verify stage checks section starts and cuts and
measures no cue, so the build exits 1 on `BLACK` or `SPEECH AT CUT`. An error in any stage
also exits 1.

`TRUNCATED`, `STALLED`, and `NO COVER` do not change the build's exit code, and neither
does a cue that misses. A script that gates on the video therefore runs the checks on
their own.

```console
decktalk build --silent && decktalk check && decktalk verify
```

| Flag | Meaning |
|---|---|
| `--silent` | The build uses placeholder narration with a click at every word start and needs no key. The placeholders replace the voiced audio and empty the narration cache, as [Requirements and costs](/requirements) explains. |
| `--force` | The build synthesizes every section again and spends credits on all of them. |
| `--only N` | The build records, measures, and checks only these sections. It still runs narrate on every section and assembles every section. Repeat the flag for several. |
| `--allow-unresolved` | The build continues even if some cue phrases were not found. |
| `--allow-unknown` | The build continues even if some cue ids in `cues.json` appear nowhere in their page, for a page that builds its ids at run time. |
| `--nomix`, `--no-loudnorm`, `--strict`, `--preset P`, `--crf N` | These flags work as they do for `assemble`. |

  05  deck/index.html?scene=5                  rec cut
  #  section                  start     end  length

## Environment variables

| Variable | Meaning |
|---|---|
| `DECKTALK_PROJECT` | The variable names the default project directory. |
| `DECKTALK_CACHE_DIR` | The variable sets where the KaTeX cache lives. The default is the platform's cache directory under `decktalk`. Chromium's cache belongs to Playwright. |
| `DECKTALK_CONFIG` | The variable names the per-machine settings file. The default is `~/Library/Application Support/decktalk/decktalk.toml` on macOS, `%APPDATA%\decktalk\decktalk.toml` on Windows, and `~/.config/decktalk/decktalk.toml` on Linux. Only tuning tables belong in it. |
| `DECKTALK_FFMPEG`, `DECKTALK_FFPROBE` | The variables hold paths to your own binaries and are set together. They override the `static-ffmpeg` build and any ffmpeg on PATH. |
| `DECKTALK_<TABLE>_<FIELD>` | The variable sets any tuning field, for example `DECKTALK_VIDEO_PRESET=veryfast`. [Configuration](/reference/configuration) lists them. |
| `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID` | The variables hold the speech provider's secrets, which are also read from `.env`. |

## Exit codes

| Code | Meaning |
|---|---|
| 0 | The command succeeded, or it found only uncertain verdicts, or `--no-fail` was given. |
| 1 | The command hit an error, printed to stderr as `error: …`, or it made a certain finding from `beats`, `check`, `verify`, or `doctor`, or an uncertain one under `--strict`. `build` exits 1 on an error, on `PAGE ERROR`, on an unresolved or unknown cue unless the matching flag is given, and on `BLACK` or `SPEECH AT CUT`. |
| 2 | The command line has a usage error, such as an unknown flag, a missing command, or `shots --cue` without exactly one `--step`, and the usage is printed. |
| 130 | The command was interrupted. |

| Finding | Kind | Reported by |
|---|---|---|
| `PAGE ERROR`, `STALLED`, `TRUNCATED`, `NO COVER` | certain | `check` |
| `BLACK`, `SPEECH AT CUT`, `OFF CUE`, `NO CHANGE`, `UNRESOLVED` | certain | `verify` |
| An unmatched phrase, an unknown cue id | certain | `beats` |
| A missing tool, shown as `MISSING` | certain | `doctor` |
| `BLACK?`, `KATEX?` | uncertain | `check` |
| Speech shorter than `min_seconds` | uncertain | `beats` |

`--no-fail` turns every finding into exit 0, and `ok` in the JSON still says whether the
command passed. An error is not a finding, so a `DeckTalkError` exits 1 even with
`--no-fail`. An unexpected exception prints `error: <type>: <message> (add -v for the
traceback)` and exits 1, and `-v` re-raises it instead.
