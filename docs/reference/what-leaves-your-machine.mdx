This page is the whole list. DeckTalk itself contacts the hosts in the first two tables and no
others, and it sends no telemetry, no usage report and no crash report anywhere. The one request it
does not choose is a page's own: a page you record loads what its author wrote it to load, and the
third table says when that reaches the network and how a machine refuses it.

Hand this page to a reviewer who has to approve DeckTalk on a managed machine. The three facts that
decide most reviews are that a cloud speech service receives your script, that the first run
downloads a browser and a media tool, and that a recorded page reaches the network as it would in a
browser unless the machine sets `record.page_policy = "untrusted"`.

## Requests that carry your content

These requests carry text from your project. Every one of them is made only by a command you run on
purpose, and every one of them needs an API key that you supply.

| Host | Request | Sent by | What DeckTalk sends |
|---|---|---|---|
| api.elevenlabs.io | Narration | `decktalk narrate`, and `decktalk build` on a voiced run | The section's spoken text, the voice id, the model name and the audio format, together with up to `narration.context_chars` characters of the previous section and up to the same of the next section as speaking context. The default is 1500 characters, and `narration.context_chars = 0` keeps the neighbouring sections on your machine. |
| api.elevenlabs.io | Sound effects and ambience | `decktalk score` | The prompt string written in the `[score.ambience]` or a `[score.effects.<name>]` table, the length you asked for and the audio format. No part of `script.md` is sent. |
| api.elevenlabs.io | Music | `decktalk score` | The prompt string written in the `[score.music]` table, the length you asked for and the audio format. No part of `script.md` is sent. |

**Narration to `api.elevenlabs.io`.** The request carries the value of `ELEVENLABS_API_KEY` in a header, to the host `[elevenlabs] api_base` names. That value must be an https URL on elevenlabs.io, because the key goes wherever it points. Rebuilding one section still sends that section's neighbours, because the voice reads them for intonation. A run with `--no-spend` sends nothing at all.

**Sound effects and ambience to `api.elevenlabs.io`.** The request carries the value of `ELEVENLABS_API_KEY` in a header. The prompt is text you wrote in `decktalk.toml`, so you decide what it describes.

**Music to `api.elevenlabs.io`.** The request carries the value of `ELEVENLABS_API_KEY` in a header. The music file is generated once and then reused from `build/`.

### Reading a request before you make it

`decktalk check --json` prices the narration of a voiced run with no API key and no request. Its `spend` object
reports the sections a voiced run would pay for, their character count, the price per thousand
characters and the layer that set it, so a reviewer can read exactly what would be sent before
anything is sent. `decktalk build` stops at the same point and names the price before it spends a
credit, and `--max-cost N` refuses the whole run before the first call when the ceiling is above N.

Set `narration.context_chars = 0` when the neighbouring sections must stay on the machine. Each
section is then sent on its own, with no surrounding text.

## One-time downloads

DeckTalk fetches the tools a recording needs, once per machine: the first command that opens a page
downloads the browser, the first command that encodes downloads the media tool, and `decktalk
install` does both up front. These requests carry nothing from your project, and after they succeed
a build without voice needs no network at all, unless a page loads something from another host.

| Host | What it holds | Fetched by | What DeckTalk sends |
|---|---|---|---|
| cdn.playwright.dev | Headless Chromium | the first command that opens a page, or `decktalk install` | A download request for the pinned browser build, and nothing else. |
| github.com | ffmpeg and ffprobe on Linux and on Windows | the first command that encodes, or `decktalk install` | A download request for one pinned release archive, and nothing else. |
| evermeet.cx | ffmpeg and ffprobe on an Intel Mac | the first command that encodes, or `decktalk install` | A download request for two pinned archives, and nothing else. |
| ffmpeg.martin-riedl.de | ffmpeg and ffprobe on an Apple silicon Mac | the first command that encodes, or `decktalk install` | A download request for two pinned archives, and nothing else. |

**`cdn.playwright.dev`.** This is Playwright's own download host. `PLAYWRIGHT_DOWNLOAD_HOST` points it at a mirror, and `[record] browser_path` skips the download by recording with a browser the machine already has.

**`github.com`.** GitHub answers a release download with a redirect to its asset host, so a proxy rule needs both. The archive is checked against a pinned SHA-256 digest and discarded when the digest does not match.

**`evermeet.cx`.** The archives are checked against pinned SHA-256 digests and discarded when a digest does not match.

**`ffmpeg.martin-riedl.de`.** The archives are checked against pinned SHA-256 digests and discarded when a digest does not match.

## Requests a page makes

A deck is a web page, and its own script runs in the browser that records it. DeckTalk serves the
page and the files the project declares from inside that browser, so none of those requests leaves
the machine. A request the page makes for any other host is the page's, not DeckTalk's.

| Host | Request | Sent by | What it carries |
|---|---|---|---|
| Any host the page names | A page's own requests | `decktalk record`, `decktalk check` and `decktalk storyboard`, and `decktalk assemble` when it draws the poster, so `decktalk build` too | Whatever the page asks for, such as a font, a script, an image or a call to an API its author wrote. DeckTalk adds nothing to the request. The browser that makes it is started with paths, locale and proxy settings alone, so `ELEVENLABS_API_KEY` and every other key the process holds are not in its environment. |

**A page's own requests.** Under the default `record.page_policy = "trusted"` the request goes to the network the way it would in the author's browser, through the machine's own proxy. Under `untrusted` it is refused before it leaves the browser, whatever its scheme. Either way the run names every other origin the page reached for, as [`PAGE_CDN_ASSET`](/reference/findings/PAGE_CDN_ASSET), so a reviewer reads which hosts a deck depends on from `decktalk check --json` before anything is recorded.

## What never leaves

DeckTalk has no telemetry. It reports no usage, no errors and no project contents to its authors,
and it has no update check. Nothing about a build is sent anywhere unless a command in the first
table above sends it, or a page you record sends it itself.

DeckTalk's log records are written to the run's own events file. When DeckTalk runs inside a
program of your own, the same records also reach that program's logging, with every credential
DeckTalk holds already replaced by its variable name. Where that logging goes is the program's
choice.

No DeckTalk environment variable has its value printed, logged or placed in a request body. The one
exception is `DECKTALK_ALLOW_ANY_API_BASE`, which is a switch and never a secret. An error message
that quotes a reply from a service has every credential the request carried replaced before the quote
is cut to length, whatever header carried it. A redirect to another host, scheme or port never carries
a header that holds a credential.

KaTeX ships inside the wheel, so an equation needs no download and no content delivery network.

## The agent is a second service

The six DeckTalk skills run inside your coding agent. When you ask an agent to write a script,
place cues or fix a finding, the agent puts your `script.md`, your `decktalk.toml`, your `cues.json`
and the JSON that DeckTalk prints in front of whatever model that agent runs. That model is a cloud
service of its own, under its vendor's terms and not under DeckTalk's, and a policy review that
covers the speech service should cover it too. Running DeckTalk from the command line alone contacts
no model.

## On a managed machine

A laptop with an intercepting proxy, no administrator rights and a policy review needs five things,
and none of them is a DeckTalk feature you have to wait for.

- **Build with no voice and no key.** `decktalk build --no-spend` plays every take on disk,
  writes placeholder narration where a take is missing, and makes a complete video. It contacts no
  service, so you can show a finished internal video before any approval comes back.
- **Use the browser the machine already has.** Set `record.browser_path` with
  `decktalk config set record.browser_path PATH --where machine`, or point `[tools] cache_dir` at a
  directory whose `ms-playwright` folder your administrators have already filled. Both are machine
  keys, so a project file that sets either is refused. The pinned build is the reference, and a managed
  browser is supported and unverified.
- **Use the ffmpeg the machine already has.** `[tools] ffmpeg` and `[tools] ffprobe` name
  executables directly, and a build that finds them downloads nothing from the second table. Both
  are machine keys, so they belong in this machine's settings file rather than in a project that
  ships to somebody else.
- **Bypass the proxy for the preview server alone.** A recorded page is served at
  `http://project.localhost/` from inside the browser: no socket opens, no port is chosen and no
  proxy sees that host, so recording needs no proxy rule. `decktalk serve` is the one command that
  opens a real server, for previewing a deck in your own browser. It binds to `127.0.0.1` by default
  and takes `--host` and `--port`, so a proxy that intercepts the loopback address needs a bypass
  for it.
- **Refuse what a page reaches for.** Set `record.page_policy` to `untrusted` with
  `decktalk config set record.page_policy untrusted --where machine` when the machine records pages
  it should not trust with the network. [A page someone else wrote](/requirements#a-page-someone-else-wrote)
  says what that policy holds.

[Requirements and costs](/requirements) has the full managed-machine section, with the package index
mirror and the `[tools]` keys.

`decktalk doctor` reports what is installed and which browser and media build a run would use,
without fetching anything, and `decktalk doctor --json` prints the same reading as one object with
no credential in it.
