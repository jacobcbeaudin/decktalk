title: Your first deck
description: Write one DeckTalk section from scratch in script.md, decktalk.toml, cues.json, and deck/index.html, then build the slide and verify that every reveal lands on its word.
icon: "pen-line"
---

You write three files for a DeckTalk section, the script, the cues, and the page, and
the voice returns a fourth, the words file. One cue id ties them together, and the project
file maps the section to its page. This guide writes one section, a simplified gradient
descent scene drawn with SVG rather than the scaffold's three.js surface, and shows every
reference as it is made. Start from `decktalk init my-lesson` so that the runtime and
KaTeX are in place, and replace the scaffold's section 3 in all four files with the code
below. In `script.md`, replace everything from `## 3. Gradient descent` up to `## 4.`. In
`cues.json`, replace the `"3"` entry. The section 3 table in `decktalk.toml` already
matches. In `deck/index.html`, delete the scaffold's `DeckTalk.scene(3, …)` call and paste
the `<style>` and `<script>` blocks below just before `</body>`. Deleting the call matters,
because a second `DeckTalk.scene(3, …)` silently replaces the first and leaves the
scaffold's cues with no owner. The scene carries the few CSS rules it needs, because the
scaffold's stylesheet defines only its own classes. This is the finished section in the
script, the project file, the cues, and the page.

<CodeGroup>

```md script.md
## 3. Gradient descent

[Deck scene 3. A loss bowl draws, a point steps down it, and the update rule appears.]

Now a short lesson. Here is gradient descent, at a high level. [beat] Start with a loss
surface. For this lesson it is a bowl. [beat] Pick a point anywhere on it. [beat] The gradient
says which way is uphill, so take a step the other way. [beat] The learning rate sets
the size of that step. [beat] Step again. [beat] And again, and each step is smaller as
the slope flattens out.

[beat] Pause and think: what happens if the learning rate is too large?

[pause 3]

You overshoot, and bounce from side to side. [beat] Too small, and you crawl. [beat] Just
right, and you settle at the bottom.
```

```toml decktalk.toml
[[section]]
number = 3
title = "Gradient descent"
page = "deck/index.html"
scene = 3
```

<Steps>
  <Step title="Write the section in script.md">
    Each `## N. Title` heading starts a section. A heading may also carry a time budget,
    such as `— 0:40 to 1:20`, which the narrate table compares with the real length, and
    [Writing for the ear](/guides/writing-for-the-ear#give-a-section-a-time-budget) shows one. Text
    in square brackets is a stage direction, and it is not spoken. A plain direction and
    `[beat]` are beats, which the voice reads as a dash and a short pause, and `[pause 3]`
    is three seconds of silence requested from the voice. Write numbers and symbols as you
    want them said, because cue phrases match spoken words. The script says "learning
    rate" and the slide shows η. [script.md](/reference/script-md) lists every rule.
  </Step>

  <Step title="Declare the section in decktalk.toml">
    Every script section needs one `[[section]]` table with the same `number`. A section
    is either a page, which DeckTalk records and cuts, or a clip, which is your own video.
    The `scene` value is what the page receives as `?scene=`, and it defaults to the
    section number. [decktalk.toml](/reference/decktalk-toml) lists every key.
  </Step>

  <Step title="Name the moments in cues.json">
    A cue pairs a cue id with the spoken phrase it lands on. Matching takes the first
    occurrence and ignores case and punctuation. The values `$start` and `$end` are the
    edges of the section's speech, `offset` shifts the moment in seconds, and `occurrence`
    picks a later repeat of the same words. Here the bowl draws on `loss surface`, each
    move of the point lands on the verb that makes it, the update rule appears on
    `learning rate`, the overshoot path draws on `overshoot`, and the settled point trails
    `settle` by a fifth of a second. The `min_seconds` key warns when the speech is
    shorter than the thirty seconds the animation needs. [Cues](/concepts/cues) has the
    matching rules and the advice on choosing a phrase.

    <Warning>The `3.1` cue on `$start` mounts the step at 0.0, and that is all it is for.
    The verify check needs a reference frame at least one frame before the cue and after the
    section's fade-in, and a cue at 0.0 leaves no such frame. `decktalk verify` therefore
    reports a `$start` cue at 0.0 as `skipped` with the reason `REFERENCE_CLAMPED` rather
    than measuring a landing.</Warning>

    Run `decktalk narrate --silent` once, then `decktalk beats` at any time to see where
    each phrase resolved. A phrase that is
    not among the section's words is reported as `phrase not found`, and `build` stops
    there until you fix it or pass `--allow-unresolved`.

    ```text
    sec  speech   need  cues
     03    49.3   30.0  3.1@0.0,3.1bowl@7.39,3.1p0@11.83,3.1p1@18.73,3.1eq@22.18,3.1p2@26.13,3.1p3@27.11,3.1think@33.03,3.1over@39.44,3.1min@47.53
    ```
  </Step>

  <Step title="Build the slide in deck/index.html">
    A page registers one scene per section. A scene is a list of steps, and each step
    renders one slide. Every cue here belongs to step `3.1`, because the step's `cues`
    object names it and because `3.1` is the longest prefix of each id. The elements
    marked `data-cue` stay hidden until their cue fires. The bowl is an SVG path with
    `pathLength="1"` and `data-fx="draw"`, so its stroke draws itself over 1.6 seconds.
    Each move of the point pops on its cue, and the moves shrink as the slope flattens.
    The update rule is a `data-tex` element that KaTeX typesets, with the plain text as
    its fallback. The overshoot path draws on `overshoot`, and the settled point pops
    last. [The page contract](/concepts/page-contract) explains ownership, and
    [the runtime reference](/reference/runtime) lists every attribute.

    Inside the backticks of a `render` template, write every backslash twice. The
    `data-tex` value `\\theta_{t+1}` reaches KaTeX as `\theta_{t+1}`.
  </Step>

  <Step title="Look before you build">
    Open `deck/index.html?step=3.1` in a browser to see the step with everything
    revealed, or `?scene=3` to watch it autoplay. Then take screenshots of every step, and
    of the scene at a given second with its real cues.

    ```console
    decktalk shots
    decktalk shots --section 3 --at 22
    ```
  </Step>

  <Step title="Build and verify">
    ```console
    decktalk build --silent          # placeholder voice, no key
    decktalk verify 3:3.1eq 3:3.1p1
    decktalk build                   # your voice
    ```

    Verify after the silent build, because only a silent build's placeholder track has the
    clicks that the `a/v` column measures. The voiced build then replaces the placeholder
    narration with your voice, and `decktalk verify` can measure its cues again. The verify
    table shows, for each cue, the second at which it fired in the final mp4,
    the share of pixels that changed across it, the same measure over a quiet control
    span just before it, and how far from the cue time the first changed frame sits. After a
    silent build it also shows [`a/v`](/concepts/how-it-works#what-verify-measures), which
    compares the picture with the placeholder click at the cued word and so shows whether
    the finished file's audio and picture agree.

    ```text
    check                 cue       at   chg %   ctl %   offset     a/v  result
    3:3.1eq             22.18    69.18    0.44    0.00    -20ms   -29ms  changed
    3:3.1p1             18.73    65.73    0.16    0.00    -10ms   -18ms  changed
    ```

    Every row is within the two-frame limit. A negative offset means that the picture
    began that many milliseconds before the cue time, which is the word's start plus the
    cue's `offset`, and one frame is 40 ms at 25 fps. A reveal
    further from its cue time than that limit is reported as `OFF CUE` by
    `decktalk verify`, which exits 1. `build` checks only section starts and
    cuts.
    [How it works](/concepts/how-it-works#what-verify-measures) explains the columns and
    the limit that turns `changed` into `OFF CUE`.
  </Step>
</Steps>

## The browser preview and the recorded video

A page plays two ways. In a browser with `?scene=3` it autoplays from the timings in the
page. During a recording the resolved cues drive it and most of those timings are
ignored. This table says which value matters where.

| Value | In the browser preview | In the recorded video |
|---|---|---|
| `hold` on a step | The seconds the step stays before the next one mounts. | Ignored. A step mounts at its earliest cue and the last cued step holds until the recorder stops. |
| The `cues` object on a step | The seconds after the mount at which each handler cue fires. | Ownership only. The times come from `build/audio/beats.json`. |
| `data-at` on an element | The seconds after the mount at which the element appears. | Used only when the element's cue is not in `?beats=`, or when it has no `data-cue`. |
| `data-cue` on an element | The element appears at its `data-at` time, which defaults to zero. | The element appears when the cue fires. |
| `data-sync` on an element | The element appears whole. | The element appears one word at a time from the `?words=` list the recorder passes. |

## The naming chain

| In | Name | Refers to |
|---|---|---|
| `script.md` | `## 3.` | the section number |
| `decktalk.toml` | `number = 3`, `scene = 3` | the same section, and the scene the page plays for it |
| `cues.json` | `"3"`, `"cue": "3.1eq"` | the section, and a cue id the page understands |
| `deck/index.html` | `DeckTalk.scene(3, …)`, `id: "3.1"`, `data-cue="3.1eq"` | the scene, its step, and the element that appears on the cue |
