This guide writes one section of your own, from nothing, in the four files you write. Do it after the
[quickstart](/quickstart), in the `my-lesson` project it made. The starter holds sections 1, 2 and 3,
and this adds a section 4 beside them. Nothing has to be deleted first.

The section is deliberately small. The point is not the slide: it is the loop of writing a section,
letting `decktalk check` tell you what is missing, and measuring the film afterwards.

## How one section ties four files together

A section is one number written in four places, and one moment on a page named in two.

| File | What it holds | What names the section |
|---|---|---|
| `script.md` | What the voice says. | A `## 4. Title` heading opens section 4. |
| `decktalk.toml` | The project file. | One `[[section]]` table with `number = 4`, naming the page and the scene it plays. |
| `deck/index.html` | The slides. | A `[data-scene="4"]` wrapper holding one or more `<template data-slide>` elements. |
| `cues.json` | The seconds. | A `"4"` entry with one row per moment the slide declares. |

`cues.json` owns seconds and the page owns what a thing looks like and what it means. No attribute on
the page ever writes a second, and no row in `cues.json` ever says what a thing looks like.

An element on a slide has four moments, each naming a cue local to that slide: `data-in` when it
arrives, `data-back` when it steps back, `data-front` when it comes forward again, and `data-out`
when it leaves. The runtime qualifies a cue name with the slide it is written in, so `data-in="waits"`
inside `<template data-slide="4.1">` is the cue id `4.1:waits`, and that is the id `cues.json`
carries. Write the cue name on the page and the cue id in `cues.json`.

## Write the section

<Steps>
  <Step title="Add the words to script.md">
    Paste this at the end of `script.md`.

    ```md script.md
    ## 4. One more section

    [Scene 4. The heading, then the band about waiting.]

    Here is one more section, written by hand. [beat] A cue is a phrase from this script, and the
    picture waits for it.
    ```

    Each `## N. Title` heading opens a section, and the number is what every other file refers to.
    The voice does not speak text in square brackets, so the line naming the scene is a note to
    yourself. `[beat]` is a short pause and `[pause 3]` asks the voice for three seconds of silence.
    [script.md](/reference/script-md) lists every rule, and [Writing for the
    ear](/guides/writing-for-the-ear) covers choosing words a picture can land on.
  </Step>

  <Step title="Add the section to decktalk.toml">
    Paste this after the last `[[section]]` table.

    ```toml decktalk.toml
    [[section]]
    number = 4
    chapter = "One more section"
    page = "deck/index.html"
    scene = "4"
    ```

    Every script section needs one `[[section]]` table with the same `number`, and the tables are
    read in order. `page` names the file and `scene` names the scene inside it that this section
    plays. `chapter` is the chapter title in the finished film. [decktalk.toml](/reference/decktalk-toml)
    lists every key.
  </Step>

  <Step title="Add the scene to deck/index.html">
    Paste this just before `</body>` in `deck/index.html`. It reuses the starter's own classes, so it
    needs no new CSS.

    ```html deck/index.html
    <div data-scene="4" data-name="One more section">
      <template data-slide="4.1" data-hold="10" data-describe="the heading and the band about waiting">
        <p class="eyebrow">One more section</p>

        <div class="title" style="top: 190px" data-in="heading" data-describe="the heading, one more section">
          <h1>One more section.</h1>
          <div class="rule"></div>
        </div>

        <p class="strip" style="top: 640px" data-in="waits"
           data-describe="a band reading: the picture waits for the phrase">
          The picture waits for the phrase.
        </p>
      </template>
    </div>
    ```

    - A `[data-scene]` wrapper is a scene and never draws anything itself. `data-name` is what the scene index calls it.
    - Each `<template data-slide>` inside it is one slide, cloned onto the stage when the slide mounts. `data-hold` is how long the preview rests on the slide, and no recording reads it.
    - An element with `data-in` stays hidden until that cue fires. The cue name is yours to choose, and it has to be unique within the slide.
    - `data-describe` says in one sentence what the moment shows. It is what the transcript reads and what a reviewer checks a reveal against, and a moment without one is reported.
    - Every element is placed absolutely on the 1920 by 1080 stage, so one thing arriving moves nothing else.

    Declare a scene number one time per page. A second `[data-scene="4"]` wrapper replaces the first.
    [The page contract](/concepts/page-contract) covers the whole model, and `decktalk schema page`
    prints all twenty-four attributes with their values, ranges and warning codes.
  </Step>

  <Step title="Add one cue row to cues.json">
    Add a `"4"` entry under `"sections"`, with a row for the heading alone. The second moment is left
    out on purpose. Put a comma after the closing brace of section `"3"` first, because JSON
    separates one entry from the next with a comma.

    ```json cues.json
    "4": {
      "cues": [
        { "id": "4.1:heading", "phrase": "one more section", "occurrence": 1 }
      ]
    }
    ```

    `id` is the cue id: the slide id, a colon, and the cue name the page wrote. `phrase` is a word or
    short phrase from that section of `script.md`, matched with case and punctuation ignored, and
    `occurrence` picks which match when the phrase is said more than once. `$start` is the section
    start, `$end` is the end of speech, and `offset_seconds` shifts a cue by seconds.
    [cues.json](/reference/cues-json) lists every key, and [Cues](/concepts/cues) explains the
    matching.
  </Step>
</Steps>

## Let check find what is missing

`decktalk check` judges the written files and the pages before a build. It produces nothing, it calls
no API, and it prices what a voiced build would cost. Run it on the new section.

`--section 4` narrows it to the section you just wrote. `--no-frames` keeps the browser, which is
what reads the moments the page declares, and drops the comparison of frozen frames, which is the
slow part and not what finds a missing row.

```console
decktalk check --section 4 --no-frames
```

```text
No voice is named, so the cache cannot be checked, because [voice] id is empty and DECKTALK_VOICE_ID is not set.
Checking script.md, cues.json, deck/index.html.
The takes on disk could not be matched to a voice, so this run costs up to $0.03 at $0.30 per 1,000 characters.
cues.json: CUE_MISSING section 4 declares 1 moment(s) that cues.json does not list, which is 4.1:waits, so nothing gives them a second.
  fix (safe): Add 1 row to section 4 of cues.json, each waiting for the words you write in its `phrase`.
Found 1 finding, 1 error. 1 fixable with --fix.
```

It exits 1, because it found an error. The slide declares `4.1:waits` and no row gives it a
second, which is [CUE_MISSING](/reference/findings/CUE_MISSING). The finding carries a safe fix, so
`--fix` applies it.

```console
decktalk check --section 4 --no-frames --fix
```

```text
cues.json:37: CUE_UNRESOLVED the cue 4.1:waits has no phrase yet, so write the words it lands on into its 'phrase' and it will have a second.
Found 1 finding, 1 error.
```

The row is in the file:

```json cues.json
"4": {
  "cues": [
    {"id": "4.1:waits", "phrase": ""},
    { "id": "4.1:heading", "phrase": "one more section", "occurrence": 1 }
  ]
}
```

The fix writes the id, because DeckTalk knows the id, and leaves `phrase` empty, because the phrase is
your line and not DeckTalk's. The run reads the project again after the fix and reports the empty
phrase as [CUE_UNRESOLVED](/reference/findings/CUE_UNRESOLVED), so it still exits 1. Write the phrase
and the section is complete.

```json cues.json
{ "id": "4.1:waits", "phrase": "the picture waits" }
```

```console
decktalk check --section 4 --no-frames
```

```text
No voice is named, so the cache cannot be checked, because [voice] id is empty and DECKTALK_VOICE_ID is not set.
Checking script.md, cues.json, deck/index.html.
The takes on disk could not be matched to a voice, so this run costs up to $0.03 at $0.30 per 1,000 characters.
```

Nothing found, and it exits 0. The two lines about the voice are the price explaining itself: with
no voice id named, no take on disk can be matched to the voice that made it, so the section counts
toward the most the run can cost rather than toward what it certainly costs. Set `[voice] id` in
`decktalk.toml` and the same line states one figure: `This run costs $0.03 for 111 characters
at $0.30 per 1,000 characters.`

<Tip>Run `decktalk check` with no flags before a build. It opens the pages, freezes every slide
either side of every cue, and reports a reveal too small to be measured, which is the judgement
`--no-frames` drops. `--fail-on warning` also fails on a warning, and `--allow CODE` carries
on past one code.</Tip>

## Build it and measure it

```console
decktalk build --no-spend
```

```text
run a86cc81a91cc, events build/events/a86cc81a91cc.jsonl
     Narrate    0:00
         Cue    0:00
      Record    0:22
The project declares no score for this run, so there is nothing to generate.
  Score    0:00
The loudness pass is skipped because the narration is a placeholder, so the soundtrack is encoded as it was mixed.
    Assemble    0:03
      Verify    0:02
       Built build/final/my-lesson.mp4, $0.00, nothing found
```

`--no-spend` uses estimated word times and a placeholder, so the new section costs nothing to try.
Its page records beside the other three, so a fourth section adds little to the time the build
takes.

`verify` runs as the last stage of a build, and it is also a command, so you can measure one section
without building again.

```console
decktalk verify --section 4
```

```text
Verifying build/final/my-lesson.mp4, 1:01 long.

 Section   Cue           Spoken   Shown   Offset
 ───────────────────────────────────────────────
 4         4.1:heading   51.77    51.80   +0.03
 4         4.1:waits     58.24    58.28   +0.04

```

`Spoken` is the second the cue phrase is said on the film's clock. `Shown` is the second the picture
was measured arriving in the encoded frames. `Offset` is the difference, and it is the product's whole
claim written as a number: both moments landed within four hundredths of a second of their word.
`verify` reports `CUE_OFF` and exits 1 when that difference is outside the limit, which is
`verify.cue_offset_max_ms`. [Verify](/reference/verify) defines every measurement it takes.

Run `decktalk verify` with no scope to measure every section, every cut and every seam at once.

## What to do next with it

- Voice it. With a key in `.env`, `decktalk check --json` prices the narration and `decktalk storyboard` shows you what you are about to buy. [Requirements and costs](/requirements#how-the-price-is-worked-out) covers the ceiling.
- Make the slide worth watching. [Design a slide](/guides/design-a-slide) covers reveal styles, the camera and making a reveal large enough to be measured, and [Slide recipes](/guides/slide-recipes) has patterns to copy.
- Change one word and rebuild. [Rebuild one section](/guides/rebuild-one-section) says which edit runs which stage again.
