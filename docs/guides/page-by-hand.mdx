title: Write a page by hand
description: Build a deck page from an empty file: the skeleton, the scene wrapper, the slide templates, the DeckTalk object and the query keys.
---

`decktalk init` writes a deck that already builds, and copying one of its pages is the shortest route
to a second one. This guide is for the other case: a page written from an empty file, because the
deck belongs to a design that neither packaged example fits.

Everything here is the same contract the starter obeys. A `[data-scene]` wrapper is one scene, each
`<template data-slide>` inside it is one slide, an element has four moments and each moment is the
local name of a cue. No attribute ever writes a second, because `cues.json` owns seconds.

## The skeleton

```html deck/mine.html
<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<title>My lesson</title>

<link rel="stylesheet" href="./katex/katex.min.css">
<script src="./katex/katex.min.js"></script>
<script src="./decktalk-runtime.js"></script>

<style>
  :root { --ground: #ffffff; --ink: #0f0f12; --accent: #2c1fea;
          --sans: ui-sans-serif, system-ui, sans-serif; }
  html, body { margin: 0; background: var(--ground); color: var(--ink); font-family: var(--sans); }
  body { width: 100vw; height: 100vh; overflow: hidden; }
  #dt-stage { background: var(--ground); }
</style>
</head>

<body>

<div data-scene="1" data-name="Open">
  <template data-slide="1.1" data-hold="10" data-describe="the opening title">
    <h1 data-in="title" data-describe="the title, My lesson">My lesson</h1>
  </template>
</div>

</body>
</html>
```

That is a complete page. It lists its scene when opened with no query, plays it with `?scene=1`, and
records under the cue times a run resolves.

### Loading the runtime and KaTeX

`decktalk init` copies two things into `deck/` beside the page: `decktalk-runtime.js`, the compiled
runtime, and `katex/`, a pinned KaTeX release with its stylesheet, its licence and its font files.
Load them with relative paths, as above.

KaTeX goes before the runtime, so the first slide is already typeset when the recorder starts the
clock. The runtime waits for a typesetter a page asks for, and a page with `data-tex` on it and no
KaTeX at all earns [`PAGE_KATEX_MISSING`](/reference/findings/PAGE_KATEX_MISSING). A page with no
equations needs neither line.

<Warning>Load nothing from a network address. A recording that fetched a font, a stylesheet or a
highlighter from somebody else's server is a film that depends on a host it does not own, which is
[`PAGE_CDN_ASSET`](/reference/findings/PAGE_CDN_ASSET). Copy the asset into `deck/` instead, which is
what the lesson example does with its bundled OFL fonts.</Warning>

### The stage

The runtime builds a stage element, `#dt-stage`, that is 1920 by 1080 CSS pixels, and scales it to
fit the window. A page that declares its own `<div id="dt-stage">` keeps that element and the runtime
builds around it, which is how a deck puts one background under all of its slides. Style it, and do
not size it.

## The scene wrapper

```html deck/mine.html
<div data-scene="1" data-name="Open">
```

`data-scene` is the id a `[[section]]` in `decktalk.toml` names in its `scene` key. `data-name` is the
scene's name in the index page and in the catalog, and a scene with no name is called "Scene" and its
id.

A wrapper holding no `<template data-slide>` is [`PAGE_SCENE_EMPTY`](/reference/findings/PAGE_SCENE_EMPTY).
A moment attribute written on the wrapper itself, outside every template, has no slide to qualify it,
so it is [`PAGE_MOMENT_UNKNOWN`](/reference/findings/PAGE_MOMENT_UNKNOWN).

## The slide templates

A slide is a `<template>` the runtime clones when the slide mounts. Four attributes belong to it.

| Attribute | Values | Default | What it does |
|---|---|---|---|
| `data-slide` | any id | required | Declares the slide. Its id qualifies every moment written inside it. |
| `data-hold` | 1 to 60 seconds | 8 | How long a preview rests on this slide. No recording reads it. |
| `data-enter` | `crossfade`, `cut` | `crossfade` | How this slide replaces the one before it. A crossfade is 0.24 s and a cut is instant. |
| `data-owns` | local names, space separated | none | The cues only a handler serves, which no moment attribute mentions. |

```html deck/mine.html
<template data-slide="1.4" data-hold="20" data-enter="cut" data-owns="long short"
          data-describe="the error drawn as a hill the model walks down">
  <h1 data-in="hill" data-describe="the heading, picture the error as a hill">Picture the error as a hill.</h1>
</template>
```

Use `data-enter="cut"` where the picture changes completely, because a crossfade there reads as a
dissolve rather than as a new idea. `data-describe` on the template is the slide's own subject, and
`data-describe` on an element inside it is that element's.

Four rules the reader checks before a pixel is drawn.

- A template inside a scene with no `data-slide` is [`PAGE_SLIDE_NO_ID`](/reference/findings/PAGE_SLIDE_NO_ID).
- Two templates claiming one id give every moment inside either of them two owners, which is
  [`PAGE_SLIDE_DOUBLED`](/reference/findings/PAGE_SLIDE_DOUBLED).
- A template nested inside a slide with no `data-slide` of its own is never mounted, which is
  [`PAGE_TEMPLATE_IGNORED`](/reference/findings/PAGE_TEMPLATE_IGNORED).
- A slide no recorded section ever mounts is [`PAGE_SLIDE_UNUSED`](/reference/findings/PAGE_SLIDE_UNUSED).

[Design a slide](/guides/design-a-slide) covers the element attributes, and
[Slide recipes](/guides/slide-recipes) has a pattern for each thing they do.

## The DeckTalk object

`decktalk-runtime.js` publishes `window.DeckTalk`, which is everything a page may call. A page written
only in markup calls none of it.

| Member | What it is |
|---|---|
| `DeckTalk.version` | The runtime version this page carries. |
| `DeckTalk.scene(id, definition)` | Declares one scene from script, for a slide built in code rather than written as a template. Returns `DeckTalk`, so calls chain. |
| `DeckTalk.on(cue, fn)` | Runs `fn` at one cue, wherever in the deck that cue belongs. Returns `DeckTalk`. |
| `DeckTalk.waitFor(promise)` | Holds the page's readiness until a promise of your own has settled. |
| `DeckTalk.start()` | Reads the page and starts it, which a page that loads the runtime late may have to call itself. |
| `DeckTalk.startClock()` | Starts the narration clock. The recorder sends this once its cover has come off, and a page has no reason to call it. |
| `DeckTalk.scenes` | Every scene the page declared, as a Map keyed by scene id. |
| `DeckTalk.params` | The page's own query, as `URLSearchParams`. |
| `DeckTalk.findSlide(id)` | The scene and slide one slide id names, or null. |
| `DeckTalk.buildSlide(scene, slide)` | One slide's element, built and not yet wired. |

`window.__decktalk` is the same page read back: the mode, the scene, the slide, the cues, the
warnings and the measured catalog. The recorder and every check read the page through it, and a page
never writes to it.

### A cue a handler serves

```js deck/mine.html
const step = (left) => (slide) => {
  const thumb = slide.querySelector(".l-thumb");
  if (thumb) thumb.style.left = left;
};
DeckTalk.on("1.5:long", step("1500px")).on("1.5:short", step("90px"));
```

<Note>`DeckTalk.on` takes a wire id, which is the slide id, a colon and the local name, because a
handler may be registered anywhere in the deck and nothing around the call says which slide it means.
A slide's own `owns` and `on` keys are local names, because the slide they belong to already says
which slide that is.</Note>

A handler receives the mounted slide element, or null when no slide is mounted, and a context of
`id`, the wire id of the cue, `at`, the second on the page clock, `frozen`, whether the page is a
still, and `slideId`. A handler that throws earns
[`PAGE_HANDLER_THREW`](/reference/findings/PAGE_HANDLER_THREW), and the moment does nothing rather
than the page failing.

List in `data-owns` every cue a handler serves that no moment attribute names. That is what makes
the slide the owner of the cue, and ownership is what decides when the slide is mounted. A cue in
`cues.json` that no slide owns is [`PAGE_NO_OWNER`](/reference/findings/PAGE_NO_OWNER), and a cue that
fires and finds neither a moment nor a handler is
[`PAGE_CUE_UNKNOWN`](/reference/findings/PAGE_CUE_UNKNOWN).

### A slide built in code

`DeckTalk.scene` declares a scene whose slides build their own markup. A scene declared in script and
a `[data-scene]` wrapper with the same id are one scene, so a deck may be half markup and half code,
and a slide that defines `render` keeps it rather than taking the markup of a template with its id.

```js deck/mine.html
DeckTalk.scene("2", {
  name: "How it works",
  slides: [
    {
      id: "2.1",
      hold: 14,
      enter: "crossfade",
      owns: ["sweep"],
      render: ({ frozen }) => `<h1 data-in="heading" data-describe="the heading">The average</h1>`,
      entered: (el, ctx) => { /* the slide has just mounted */ },
      on: { sweep: (el, ctx) => { /* the local name, not the wire id */ } },
    },
  ],
});
```

A `render` returns the slide's inner HTML and is given the scene, the slide and whether the page is
frozen. It throws into [`PAGE_RENDER_THREW`](/reference/findings/PAGE_RENDER_THREW), `entered` throws
into [`PAGE_ENTER_THREW`](/reference/findings/PAGE_ENTER_THREW) and a handler in `on` throws into
[`PAGE_SLIDE_HANDLER_THREW`](/reference/findings/PAGE_SLIDE_HANDLER_THREW), and in every case the
slide is drawn as its markup stands rather than the page failing.

<Warning>Inside the backticks of a `render`, every backslash has to be written twice, because the
markup is a JavaScript string. In a `<template>` a backslash is written once. That alone is reason
enough to write an equation as a template.</Warning>

### Waiting for something of your own

```js deck/mine.html
const image = new Image();
image.src = "./media/status.png";
DeckTalk.waitFor(image.decode());
```

`DeckTalk.waitFor` holds the page's readiness until the promise settles, so the recorder does not
start the clock on a page that is still loading. The budget is five seconds. A promise that rejects
is [`PAGE_WAIT_REJECTED`](/reference/findings/PAGE_WAIT_REJECTED), one that never settles is
[`PAGE_WAIT_UNSETTLED`](/reference/findings/PAGE_WAIT_UNSETTLED), and the page is drawn either way, so
a missing file never hangs a build.

## The query keys the runtime reads

One URL decides which of four things the page is doing: it lists its scenes, it previews one, it
plays one against the narration clock, or it freezes one slide.

| Key | What it asks the page for |
|---|---|
| `scene` | Play this scene from its first slide. |
| `slide` | Freeze this slide with its cues already fired, which is what a still opens. |
| `cues` | The cue times to fire at, as `id@seconds` pairs separated by a comma. |
| `words` | The spoken words to sync a line against, as `word@seconds` pairs separated by a comma. |
| `t0` | The narration second the page starts at, or `signal` when the recorder starts the clock. |
| `speed` | Multiply the preview clock, so a long section is reviewed quickly. The slowest it goes is 0.05. |
| `hud` | Set it to `1` to draw the on-page clock and cue list, which is for an author and never for a recording. |
| `after` | Freeze after this cue, so the cues up to and including it fire and later ones stay hidden. |
| `before` | Freeze just before this cue, so it and every later cue stay hidden. |

`after` and `before` are answered by the probe that `decktalk check` and `decktalk storyboard` inject
into the page. A page you open yourself with `?slide=1.1` freezes that slide with every one of its
cues fired, and a cue those two keys name that the slide does not declare is
[`PAGE_FREEZE_CUE_UNKNOWN`](/reference/findings/PAGE_FREEZE_CUE_UNKNOWN).

## Open the page yourself

The recorder opens every page over http, so open yours the same way rather than from a `file://` URL.

```console
decktalk serve
```

It serves the deck directory and the files `decktalk.toml` declares, and nothing else. It prints
where the deck is served and then closes its output, so a caller that captured it reads one object
and is not left waiting on a stream that never ends. `--host` and `--port` choose the interface and
the port, and a port of 0 takes any free one.

The deck directory is every directory a `page` sits in, so every name under it is served however the
page spells it. A file outside it, such as a clip, a words file or a sound, is served only by the
spelling `decktalk.toml` gives it. Write the same name in the page, down to its case, because a
request for `Media/Intro.mp4` is refused when the project declared `media/intro.mp4`, on every
platform alike. The recorder opens the page under the same rule, so a page that previews cleanly
records cleanly.

From the URL it prints:

- The page with no query lists every scene and every slide, and links a preview and a still of each.
- `?scene=1` previews that scene. Once `decktalk cue` has run, the preview asks the origin for the
  cue times that run resolved and plays the film's own timing. With none to find, it fires each cue
  a second apart so a deck whose cues have never been resolved still shows its whole self.
- `?scene=1&speed=4&hud=1` reviews a long scene quickly with the clock and the cue list on screen.
- `?slide=1.1` freezes one slide with its cues fired.

## Put the page in the project

```toml decktalk.toml
[[section]]
number = 1
chapter = "Open"
page = "deck/mine.html"
scene = "1"
```

The section number, the scene its `[[section]]` names and the slide ids of its cues agree, which is
the shape every DeckTalk project follows. Then write the section's narration in `script.md` and one
row per moment in `cues.json`, and judge the three together:

```console
decktalk check
```
