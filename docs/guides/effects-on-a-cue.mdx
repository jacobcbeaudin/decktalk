---
title: Put a sound effect on a cue
description: Generate a one-shot sound and play it on the second a named cue lands.
---

A sound effect is one short file that plays once, at the second a named cue fires. Two tables carry
it and each one is read by a different stage. `[score.effects.<name>]` says what the sound is,
and `decktalk score` generates it. `[[mix.effect]]` says where it plays, and `decktalk
assemble` lays it into the soundtrack.

The two are split because the sound is bought once and placed as often as you like. Moving an effect
to another word costs nothing, and the file is asked for again only when its own prompt changes.

The starter that `decktalk init` writes declares neither table, so every table below is one you add
to `decktalk.toml`. The example puts a click on `1.2:word`, the cue in the starter's section 1 where
the closing band lands.

## Before you start

- Resolve the cues once, with any build or with `decktalk narrate --no-spend` and then
  `decktalk cue`. An effect plays at the second its cue resolved to, so a cue that has never been
  resolved has no second to sit on, and `cue` needs the words `narrate` writes.
- Put `ELEVENLABS_API_KEY` in `.env` to generate the sound. Generating one costs money for every
  second of audio asked for, at the US dollars per minute `[score.effects] dollars_per_minute` states.
- Bring your own audio file instead if you have one. Any file ffmpeg can read works, it needs no key,
  and only the fourth step below applies to it.

<Steps>
  <Step title="Describe the sound">
    The table is named for the sound, and that name is what the generated file is called.

    ```toml decktalk.toml
    [score.effects.tick]
    prompt = "one soft interface click, short, dry, no reverb"
    ```

    `decktalk score` writes it to `score/tick.mp3`, in the score directory you commit, so
    deleting `build/` never buys it again. Set `out` in the same table to write it somewhere else,
    such as `media/tick.mp3`.

    The same table may carry `duration_seconds`, `prompt_influence` and `model`, each of which
    replaces the matching setting of [`[score.effects]`](/reference/configuration#score-effects)
    for this one sound. At the defaults an effect is half a second long.
  </Step>

  <Step title="Read the plan before you buy it">

    prompt and the price first.


  <Step title="Generate it">
    ```console
    decktalk score --spend
    ```

    The file lands at the path the plan named. What was bought is recorded in
    `score/ledger.json`, keyed by the request itself, so a second run that would send the
    same request keeps the file it has and sends nothing. Change the prompt and the next run buys the
    sound again, because the request no longer matches the row. `--force` never buys a sound again,
    so a sound whose request has not moved is bought again only once its file is deleted.
  </Step>

  <Step title="Cue the sound">
    A `[[mix.effect]]` row names the file, the section and the cue. The cue is a [cue id](/concepts/cues#the-cue-id).

    ```toml decktalk.toml
    [[mix.effect]]
    file = "score/tick.mp3"
    section = 1
    cue = "1.2:word"
    db = -16
    offset_seconds = 0.0
    caption = "soft click"
    ```

    | Key | Default | What it does |
    |---|---|---|
    | `file` | required | The audio file, relative to the project. It is the path the `[score.effects.<name>]` table writes, or a file of your own. |
    | `section` | required | The section whose clock the cue is read on. A number no `[[section]]` declares is refused at load. |
    | `cue` | required | The cue id of the moment the sound lands on. |
    | `db` | `-16` | The level the sound plays at. |
    | `offset_seconds` | `0.0` | Seconds added to the cue time, which is how a sound sits a beat after the word. |
    | `caption` | `""` | The line a viewer reading captions sees. |

    The sound plays at the section's start in the film, plus the second the cue resolved to, plus
    `offset_seconds`. The cue time is on the section's own clock, so moving a section elsewhere in the film
    moves its sounds with it and costs no edit here.

    A row may reuse a file another row already names, so one bought sound can click on six different
    cues.
  </Step>

  <Step title="Mix it into the film">
    ```console
    decktalk assemble
    ```

    `assemble` mixes the soundtrack again and records nothing, so a level or a cue you changed here
    costs one stage rather than a build.

    A file the row names that the score stage has not bought yet is a `SOUND_MISSING` warning, and
    one that nothing generates and the project has not got is a `FILE_MISSING` error. Either way
    that layer plays as silence. A cue that did not resolve is one sentence on the stream, and the sound does
    not play. The film is still written either way.
  </Step>
</Steps>

## Give every sound a caption

`caption` is what a viewer who cannot hear the film reads in its place. The build writes it into the
SubRip and WebVTT files as its own cue, wrapped in square brackets, so `caption = "soft click"` is
read as `[soft click]`. A caption you write with the brackets already on it is left as you wrote it.

A sound with no `caption` is in the film and in no caption file, and `assemble` says so on every
run. [Captions carry the whole soundtrack](/guides/accessible-video#captions-carry-the-whole-soundtrack)
says how a sound's caption shares the screen with speech.

## What ducks and what does not

The music bed plays at `[mix] music_db` and ducks by `[mix] music_duck_db` under every span that
carries speech, ramped in and out over `[mix] duck_ramp_seconds` at each edge.
[Sound](/concepts/sound#ducking) owns the whole rule. A span that carries
speech is a spoken section from its start to its last word, and a clip section for the whole of its
own length.

A sound effect is neither of those. It does not duck the music, and the music does not duck it, so
the only thing that decides whether a click is heard over the bed is the `db` on its own row. That is
why the level sits on the effect rather than on the table that generated it: the same file mixed at
`-16` under a quiet passage and at `-8` under a loud one is one bought sound used twice.

[Sound](/concepts/sound) is the whole mix, layer by layer.

## Pick the sounds one run generates

`--section` selects sections, which is what every stage selects on, and the score's own items
are named rather than numbered. So a run that names sections keeps the effects those sections cue.

```console
decktalk score --section 1 --spend
```

An effect belongs to that run when a `[[mix.effect]]` row in one of the named sections points at
the file the item writes. The row's `file` and the item's output path are compared as paths, so a
row that names `media/tick.mp3` while the table writes `score/tick.mp3` selects nothing.
Set `out` on the table when you want the sound somewhere else, rather than copying the file by hand.

The music is generated whenever any section is selected, because one bed plays under the whole film,
and the ambience bed is generated when a selected page section sets `with_ambience = true`.
