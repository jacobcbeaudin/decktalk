A silent build needs no API key and no network once the tools are cached, so a project
can be built and verified on every push. This is how DeckTalk's own repository does it.

## The commands

```console
decktalk setup                            # Chromium, ffmpeg, and KaTeX, once per machine
decktalk doctor                           # exits 1 when a tool is missing
DECKTALK_VIDEO_PRESET=veryfast decktalk build --silent
decktalk check                            # exits 1 on a certain recording verdict
decktalk verify                           # exits 1 when a cue did not land
decktalk shots                            # one PNG per step, worth uploading as an artifact
```

On Linux, `setup` passes `--with-deps` to Playwright so that Chromium's system libraries
are installed too, and Playwright asks for sudo to install them. The verify command is the
test, and with no arguments it checks every cue in `beats.json` except the cues that
`cues.json` marks `"verify": false`. `build` verifies only section starts and cuts, and the
cue checks measure each reveal in the finished mp4. A silent build's placeholder track
carries a click at every word start, so the cue table also reports an
[`a/v`](/concepts/how-it-works#definitions) column, which compares the picture with
the click at the cued word. The job fails when an `a/v` value is further from zero than
`max_av_frames`, which is three frames by default. That makes a silent build a
test of the whole chain, not only of the cues.

`build` exits 1 when a page throws, when a cue phrase is unresolved or a cue id is unknown,
or when a section start or a cut fails. The `TRUNCATED`, `STALLED`, and `NO COVER` verdicts
in its check table do not change its exit code, and its verify stage does not measure the
cues. A script that gates on the video should therefore run all three commands.

```console
decktalk build --silent && decktalk check && decktalk verify
```

## A GitHub Actions job

```yaml .github/workflows/video.yml
jobs:
  video:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: astral-sh/setup-uv@v10.1.0
      - run: uv tool install decktalk
      - name: Cache Chromium and KaTeX
        uses: actions/cache@v4
        with:
          path: |
            ~/.cache/ms-playwright
            ~/.cache/decktalk
          key: browsers-${{ runner.os }}
      - run: decktalk setup
      - run: decktalk doctor
      - run: decktalk build --silent
        env:
          DECKTALK_VIDEO_PRESET: veryfast
      - run: decktalk check
      - run: decktalk verify --json > verify.json
      - uses: actions/upload-artifact@v7
        with:
          name: video
          path: build/out/*.mp4
      - uses: actions/upload-artifact@v7
        if: always()
        with:
          name: verify
          path: verify.json
```

Chromium lives in Playwright's cache, which is `~/.cache/ms-playwright` on Linux,
`~/Library/Caches/ms-playwright` on macOS, and `%LOCALAPPDATA%\ms-playwright` on Windows.
KaTeX lives in DeckTalk's own cache, which follows the same platform rule under a
`decktalk` directory, and `DECKTALK_CACHE_DIR` moves it. The `static-ffmpeg` package
downloads ffmpeg into its own directory, so ffmpeg lives in the Python environment rather
than in either cache.

To build a voiced video in CI, put `ELEVENLABS_API_KEY` and `ELEVENLABS_VOICE_ID` in the
job's secrets and export them. DeckTalk never prints either.

<Warning>A silent build writes its placeholder tracks over the voiced mp3 files in
`build/audio/` and empties the narration cache, so the next voiced build voices every
section again and spends credits on all of them. A job that keeps `build/` between voiced
builds should never run a silent build in the same directory.</Warning>

Headless Chromium draws WebGL in software, because a hosted runner has no GPU it can use. A
page with a 3D figure therefore renders more slowly on a hosted runner than on a laptop, and the
macOS and Windows runners are slower than Linux. A reveal on such a page can land two or three
frames late there, which `verify` reports as `OFF CUE`, and a long first draw can be reported as
`STALLED`. When that happens on a slower runner, widen the window for that runner with the
settings' environment variables and keep the default on the machine you record on. DeckTalk's own
CI keeps Linux at the default and widens macOS and Windows like this.

```yaml .github/workflows/video.yml
      - name: Widen the sync tolerance on the slower runners
        if: runner.os != 'Linux'
        run: |
          echo "DECKTALK_VERIFY_MAX_OFFSET_FRAMES=4" >> "$GITHUB_ENV"
          echo "DECKTALK_VERIFY_MAX_AV_FRAMES=5" >> "$GITHUB_ENV"
          echo "DECKTALK_ALIGN_STALL_MS=400" >> "$GITHUB_ENV"
```

## Asserting in CI

`status`, `beats`, `check`, `verify`, and `doctor` share one exit rule, so a job can use
their exit codes as its assertions. A certain finding, such as `OFF CUE`, `TRUNCATED`,
or an unknown cue id, exits 1. An uncertain finding, whose verdict ends in a question
mark, such as `BLACK?` on a page that is dark on purpose, exits 0 unless `--strict` is
given. A cue marked `"verify": false` in `cues.json` is reported as `skipped` and never
fails.

```console
decktalk check --strict      # fail on BLACK? and KATEX? too
decktalk verify              # fail on any certain finding
```

To keep the job running and decide later, add `--no-fail` and read the JSON. The object
on stdout carries `ok` and the finding counts, and progress stays on stderr.

```console
decktalk verify --json --no-fail > verify.json
jq -e '.ok' verify.json
jq '.verify.cues[] | select(.verdict != "changed")' verify.json
```

`jq -e` exits 1 when `ok` is `false`, so the first `jq` line is the assertion and the
second lists the cues to look at. [Machine-readable output](/reference/cli#machine-readable-output)
lists every key.

A silent build skips the loudness pass, so `--silent` and `--strict` combine on `build`
without a false failure.

## The project directory

Every project command takes `--project DIR`, and the `DECKTALK_PROJECT` variable sets
the default, so a job can run from the repository root.

```console
DECKTALK_PROJECT=lessons/derivatives decktalk build --silent
```

## Offline

After `decktalk setup`, a silent build needs no network. `decktalk init` copies the cached
KaTeX into `deck/katex/`, and the scaffold's page loads it from there. A project created
before `setup` ran loads KaTeX from a CDN instead, which fails offline and leaves every
equation as plain text with a `KATEX?` verdict in the check table. Run `setup`, then
either run `init` again into a fresh directory or copy the cached `katex` directory into
`deck/` and point the two tags at it.

```html deck/index.html
<link rel="stylesheet" href="./katex/katex.min.css">
<script src="./katex/katex.min.js"></script>
```

When a proxy blocks Playwright's download, set `PLAYWRIGHT_DOWNLOAD_HOST` to a mirror,
as Playwright documents.
