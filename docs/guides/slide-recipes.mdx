---
title: Slide recipes
description: Nine copy-and-paste patterns, each with its markup, its cue row and what it costs to measure.
---

Nine patterns, one for each thing an author actually wants a slide to do. Every one is adapted from
the two decks `decktalk init` writes, so each is markup the runtime already accepts.

Each recipe is three things: the markup for one slide, the `cues.json` rows that give its moments a
second, and one sentence saying what the pattern costs to measure. That last sentence matters,
because a reveal DeckTalk cannot measure is usually a reveal a viewer cannot see either.

## Before you start

The recipes are slides of one scene numbered 4, which neither packaged deck uses. To add one to a
project:

1. Paste the `<template>` inside a `<div data-scene="4" data-name="…">` in the page's `<body>`.
2. Paste the recipe's `<style>` rules into the page's own `<style>` block.
3. Paste the `cues.json` rows into `"4": { "cues": [ … ] }` inside `sections`.
4. Add a `[[section]]` with `number = 4`, the page path and `scene = "4"` to `decktalk.toml`, and a
   `## 4. …` section to `script.md` that speaks each phrase.

A moment inside `<template data-slide="4.1">` is qualified with that slide id, so `data-in="title"`
is the wire id `4.1:title` and that is what `cues.json` carries. The recipes use the starter's own
custom properties, such as `--ink` and `--accent`, and its `.eyebrow` class.

## A title that arrives on its word

The heading and the bar under it are one element with one cue, so the whole block lands together.

```html deck/index.html
<style>
  .r-title { position: absolute; left: 120px; top: 190px; width: 1680px; margin: 0;
             font: 700 96px/1.06 var(--sans); letter-spacing: -.03em; }
  .r-title h1 { margin: 0; font: inherit; letter-spacing: inherit; }
  .r-title .r-rule { margin-top: 28px; width: 1000px; height: 12px; background: var(--accent); }
</style>

<template data-slide="4.1" data-hold="10" data-describe="the opening title">
  <p class="eyebrow">Open</p>
  <div class="r-title" data-in="title" data-describe="the title, This is DeckTalk">
    <h1>This is DeckTalk.</h1>
    <div class="r-rule"></div>
  </div>
</template>
```

```json cues.json
"4": { "cues": [
  { "cue": "4.1:title", "on": "This is DeckTalk", "occurrence": 1 }
] }
```

**What it costs to measure.** A line of type is a few hundred pixels of ink, which is well under the
0.1 percent floor on its own. The 1000 by 12 accent bar arriving with it is 12,000 pixels, about 0.6
percent of the frame, and that is what carries the cue past `CUE_THIN_CHANGE`.

## A list that staggers

One cue, and the container's children arrive one step apart.

```html deck/index.html
<style>
  .r-row { position: absolute; left: 120px; top: 420px; display: flex; gap: 24px; }
  .r-tile { width: 372px; height: 260px; border-radius: 20px; background: var(--ink); }
</style>

<template data-slide="4.2" data-hold="14" data-describe="four examples of the same kind of thing">
  <p class="eyebrow">Examples</p>
  <div class="r-row" data-in="examples" data-in-style="fade" data-stagger="0.04"
       data-describe="four examples, arriving one after another">
    <div class="r-tile"></div>
    <div class="r-tile"></div>
    <div class="r-tile"></div>
    <div class="r-tile"></div>
  </div>
</template>
```

```json cues.json
"4": { "cues": [
  { "cue": "4.2:examples", "on": "Here are four of them", "occurrence": 1 }
] }
```

**What it costs to measure.** The whole spread is the step times the children after the first, plus
the entrance, so this one is 0.04 × 3 + 0.24, which is 0.36 seconds. Anything at or above 0.5 seconds
is [`PAGE_STAGGER_OVERRUN`](/reference/findings/PAGE_STAGGER_OVERRUN), and the arithmetic that says
so is exact, so the finding is certain.

## A figure that swaps for another

The card that leaves and the card that arrives share one cue. `data-swaps` holds the leaving card in
place until its replacement has arrived, so the two read as one thing changing.

```html deck/index.html
<style>
  .r-card { position: absolute; left: 120px; top: 440px; width: 1680px; height: 220px;
            padding: 30px 38px; box-sizing: border-box; border-radius: 20px;
            background: var(--ink); color: #fff; font: 500 44px/56px var(--sans); }
  .r-card.grey { background: var(--mute); }
  .r-card .r-k { font: 600 26px/34px var(--mono); letter-spacing: .12em;
                 text-transform: uppercase; color: #a9a9ff; }
</style>

<template data-slide="4.3" data-hold="14" data-describe="the slow way, replaced by the fast one">
  <p class="eyebrow">The direction</p>
  <div class="r-card grey" data-in="one" data-out="instead" data-out-style="fall"
       data-describe="turning one knob at a time, and the billions of tries it would take"
       data-describe-out="the slow way falls away">
    <div class="r-k">one knob at a time</div>
    billions of tries for every step
  </div>
  <div class="r-card" data-in="instead" data-swaps
       data-describe="one round of maths, giving every knob a direction at once">
    <div class="r-k">every knob at once</div>
    one round of maths, one direction each
  </div>
</template>
```

```json cues.json
"4": { "cues": [
  { "cue": "4.3:one", "on": "one knob at a time", "occurrence": 1 },
  { "cue": "4.3:instead", "on": "Instead", "occurrence": 1 }
] }
```

**What it costs to measure.** A swap is between one thing and one other thing. Zero elements leaving
on the arrival cue, or two, is [`PAGE_SWAP_AMBIGUOUS`](/reference/findings/PAGE_SWAP_AMBIGUOUS) and
certain, and two halves landing far enough apart to read as unrelated is
[`PAGE_SWAP_APART`](/reference/findings/PAGE_SWAP_APART) and uncertain, which is why both cards here
share a box.

## An element that steps back while a second comes to the front

`data-back` dims an element to 45 percent and `data-front` brings it back. Neither is a second
reveal, so neither needs a second element.

```html deck/index.html
<style>
  .r-formula { position: absolute; left: 120px; top: 360px; width: 820px; height: 280px;
               box-sizing: border-box; display: grid; place-items: center;
               border: 10px solid var(--ink); border-radius: 20px; font: 500 58px/1 var(--mono); }
  .r-code { position: absolute; left: 1000px; top: 360px; width: 800px; height: 280px;
            box-sizing: border-box; padding: 36px 40px; border-radius: 20px;
            background: var(--ink); color: #fff; font: 500 32px/52px var(--mono); white-space: pre; }
</style>

<template data-slide="4.4" data-hold="16" data-describe="the formula beside the code that computes it">
  <p class="eyebrow">How it works</p>
  <div class="r-formula" data-in="formula" data-in-style="fade" data-back="code" data-front="waited"
       data-describe="the formula for the mean of n numbers">x bar = (x1 + … + xn) / n</div>
  <div class="r-code" data-in="code" data-describe="the same average written as two lines of Python">
def average(xs):
    return sum(xs) / len(xs)</div>
</template>
```

```json cues.json
"4": { "cues": [
  { "cue": "4.4:formula", "on": "the formula", "occurrence": 1 },
  { "cue": "4.4:code", "on": "in code", "occurrence": 1 },
  { "cue": "4.4:waited", "on": "waited", "occurrence": 1 }
] }
```

**What it costs to measure.** The step back takes 0.28 seconds and the return 0.20 seconds, both well
under the ceiling. Attention only registers as a change when the element is large, because dimming a
label to 45 percent moves too few pixels to clear the floor, so step back a whole panel rather than a
line.

## A line shown word by word on the voice

`data-words` matches the element's own text against the section's spoken words and reveals it one
word at a time, each word whole by the second the voice reaches it.

```html deck/index.html
<style>
  .r-strip { position: absolute; left: 120px; top: 720px; width: 1680px; margin: 0;
             padding: 28px 40px; box-sizing: border-box; border-radius: 18px;
             background: var(--accent); color: #fff; font: 600 52px/62px var(--sans); }
</style>

<template data-slide="4.5" data-hold="12" data-describe="the promise, filled in on the voice">
  <p class="eyebrow">The promise</p>
  <p class="r-strip" data-in="word" data-in-style="fade" data-words
     data-describe="a band that fills in on the voice">
    every picture waits for its own word
  </p>
</template>
```

```json cues.json
"4": { "cues": [
  { "cue": "4.5:word", "on": "its own word", "occurrence": 1 }
] }
```

**What it costs to measure.** One word lighting up is far under the change floor, so the runtime
reports the line through its own telemetry instead of through pixels, and the band fading in on the
cue is what the frame comparison sees. The text has to be the words the narration really says, or the
line earns [`PAGE_WORDS_NOT_FOUND`](/reference/findings/PAGE_WORDS_NOT_FOUND). `data-words` defaults
to `highlight`, which starts every word dim. `data-words="appear"` starts them absent and is limited
to eight words, above which it earns
[`PAGE_APPEAR_TOO_LONG`](/reference/findings/PAGE_APPEAR_TOO_LONG).

## A number that counts up

`data-count="last"` grows the last number in the text from zero when the element arrives, and
`data-count="first"` grows the first one, so the figure the voice says and the figure on screen land
together.

```html deck/index.html
<style>
  .r-stat { position: absolute; left: 120px; top: 620px; width: 1120px; margin: 0;
            padding: 34px 48px; box-sizing: border-box; border-radius: 20px;
            background: var(--accent); color: #fff; font: 700 76px/1.1 var(--sans); }
</style>

<template data-slide="4.6" data-hold="10" data-describe="the count of files a project holds">
  <p class="eyebrow">Open</p>
  <p class="r-stat" data-in="files" data-count="last"
     data-describe="the count of files a project holds">
    4 files in one folder
  </p>
</template>
```

```json cues.json
"4": { "cues": [
  { "cue": "4.6:files", "on": "Four files", "occurrence": 1 }
] }
```

**What it costs to measure.** The count runs 0.48 seconds, which ties with the `draw` entrance as the
longest span the contract declares and leaves nothing under the 0.5 second ceiling. The digits alone are
a slow, thin change, and the filled band arriving underneath them is what the cue is measured on. The
script writes the figure in words, because a cue phrase is matched against spoken words.

## A formula typeset with KaTeX

`data-tex` holds the TeX and the element's own text is the readable fallback. `data-tex-display`
makes it a display equation on its own line.

```html deck/index.html
<style>
  .r-eq { position: absolute; left: 120px; top: 360px; width: 1680px; height: 280px;
          box-sizing: border-box; display: grid; place-items: center;
          border-radius: 20px; background: #f4f4f5; }
  .r-eq .katex { font-size: 58px; }
</style>

<template data-slide="4.7" data-hold="14" data-describe="the mean of n numbers, typeset">
  <p class="eyebrow">The formula</p>
  <div class="r-eq" data-in="formula" data-in-style="fade"
       data-describe="the formula for the mean of n numbers">
    <span data-tex-display data-tex="\bar{x} = \frac{1}{n} \sum_{i=1}^{n} x_i">
      x bar = (1 / n) * (x1 + x2 + ... + xn)
    </span>
  </div>
</template>
```

```json cues.json
"4": { "cues": [
  { "cue": "4.7:formula", "on": "the formula", "occurrence": 1 }
] }
```

**What it costs to measure.** Typeset glyphs are thin, so the equation sits in a filled panel that
arrives with it and carries the change. Write the fallback text as correct, fully parenthesised
mathematics that reads well out loud, because it is what shows if KaTeX never loads, it is what the
transcript prints, and it is what a screen reader reads. In markup a backslash is written once. KaTeX
refusing the TeX is [`PAGE_KATEX_ERROR`](/reference/findings/PAGE_KATEX_ERROR) and the element falls
back to that text, and a page with no KaTeX at all is
[`PAGE_KATEX_MISSING`](/reference/findings/PAGE_KATEX_MISSING).

## A class change the page's own stylesheet animates

`data-class` adds a class at a moment, written as `moment:name` pairs. It is how a page makes a change
the contract has no word for.

```html deck/index.html
<style>
  .r-guess { position: absolute; left: 1120px; top: 490px; width: 680px; margin: 0;
             padding: 30px 38px; box-sizing: border-box; border-radius: 20px;
             background: #f4f4f5; font: 700 72px/1.1 var(--mono);
             transition: background-color .2s ease, color .2s ease; }
  .r-guess.stale { background: var(--mute); color: #e4e4e7; }
  .r-guess.live { background: #22c55e; color: #052e16; }
  :where(.dt-reduced) .r-guess { transition-duration: 0s; }
</style>

<template data-slide="4.8" data-hold="16" data-describe="the model's answer, set aside and then corrected">
  <p class="eyebrow">The loop</p>
  <p class="r-guess" data-in="guess"
     data-class="nudge:stale|right:live"
     data-describe-class="nudge:the answer is set aside while the knobs turn|right:the answer turns green, because it now matches the example"
     data-describe="the model's answer for this example">cat</p>
</template>
```

```json cues.json
"4": { "cues": [
  { "cue": "4.8:guess", "on": "and it guesses", "occurrence": 1 },
  { "cue": "4.8:nudge", "on": "nudges the knobs", "occurrence": 1 },
  { "cue": "4.8:right", "on": "it is right", "occurrence": 1 }
] }
```

**What it costs to measure.** This is the one span the contract cannot bound in advance, so DeckTalk
lays the slide out, adds each class and reads the longest transition the stylesheet gives it. Keep it
under half a second. Each class needs its phrase in `data-describe-class` or the change earns
[`PAGE_CLASS_UNDESCRIBED`](/reference/findings/PAGE_CLASS_UNDESCRIBED), and the stylesheet must drop
the motion under `.dt-reduced` or a reduced build earns
[`PAGE_CLASS_NOT_REDUCED`](/reference/findings/PAGE_CLASS_NOT_REDUCED).

## A cue only a handler serves

A cue that no moment attribute names has to be listed in `data-owns`, which is how a slide declares a
cue it draws with script of its own.

```html deck/index.html
<style>
  .r-slider { position: absolute; left: 120px; top: 520px; width: 1680px; height: 40px;
              border-radius: 999px; background: #f4f4f5; }
  .r-thumb { position: absolute; top: -60px; left: 760px; width: 160px; height: 160px;
             border-radius: 999px; background: var(--accent); transition: left .3s ease; }
  :where(.dt-reduced) .r-thumb { transition-duration: 0s; }
</style>

<template data-slide="4.9" data-hold="14" data-owns="long short"
          data-describe="one setting, deciding how long each step is">
  <p class="eyebrow">The step size</p>
  <div class="r-slider"><span class="r-thumb"></span></div>
</template>

<script>
// A handler takes the wire id, because a handler may be registered anywhere in the deck.
const step = (left) => (slide) => {
  const thumb = slide.querySelector(".r-thumb");
  if (thumb) thumb.style.left = left;
};
DeckTalk.on("4.9:long", step("1500px")).on("4.9:short", step("90px"));
</script>
```

```json cues.json
"4": { "cues": [
  { "cue": "4.9:long", "on": "Too long", "occurrence": 1 },
  { "cue": "4.9:short", "on": "Too short", "occurrence": 1 }
] }
```

**What it costs to measure.** Nothing in the contract bounds a handler, so the length and the size of
the change are yours to keep honest: hold the motion under half a second and move something large
enough to clear the change floor, or the cue reads as
[`CUE_NO_CHANGE`](/reference/findings/CUE_NO_CHANGE). A cue named in `data-owns` that the deck never
declares is [`PAGE_CUE_UNKNOWN`](/reference/findings/PAGE_CUE_UNKNOWN), and a handler that throws is
[`PAGE_HANDLER_THREW`](/reference/findings/PAGE_HANDLER_THREW), which leaves that moment doing
nothing rather than failing the page.
