Narration is cached by each section's text, so after an edit `decktalk build` voices again
only the sections whose text changed. A plain build still records, measures, and checks every
section again in real time, and `decktalk build --only N` records only section N. This guide
says what each edit runs again and how to limit a build to the sections that changed.

<Warning>A silent build writes its placeholder tracks over the voiced mp3 files in
`build/audio/` and empties the narration cache. The next voiced build therefore voices every
section again and spends credits on all of them.
[A silent build and a voiced build](#a-silent-build-and-a-voiced-build) explains why.</Warning>

## What an edit costs

| You changed | What runs again | What a plain `build` does | What `--only N` spares |
|---|---|---|---|
| A sentence in section N of `script.md` | Section N is voiced again and recorded again. | The build voices section N again, takes every other section's narration from the cache, and records every section again. | The flag spares the recording of every other section. Those recordings stay valid, because cue times are relative to each section's own start. |
| The title in a section's heading | That section is voiced again, because its audio file name comes from its number and title, and it is recorded again. | The build voices that section again and records every section again. | The flag spares the recording of every other section. |
| A phrase in `cues.json` | No section is voiced again. The section whose cues changed is recorded again. | The build voices nothing and records every section again. | The flag spares the recording of every section whose cues did not change. |
| A slide in `deck/index.html` | No section is voiced again. Every section whose scene the edit touches is recorded again. | The build voices nothing and records every section again. | The flag spares the sections it leaves out, so it must name every section whose scene the edit touches. |
| The voice id, the model, the output format, or a `[voice]` setting | Every section is voiced again, because the cache key includes all of them, and every section is recorded again. | The build voices and records every section again. | The flag spares nothing safely, because every section's words move. |
| A clip file, `hold_seconds`, `[transition]`, or `[mix]` | Only `assemble` runs again. | The build records every section again before it assembles. | The `decktalk assemble` command spares every recording, which `--only` cannot do. |
| `extra_seconds` on a section | That section is recorded again, because its recording's length changed. | The build records every section again. | The flag spares the recording of every other section. |

## The narration cache

The narration cache is `build/audio/manifest.json`. Each entry carries a hash of the
provider, the voice id, the model, the output format, the voice settings, and the exact text
sent. `narrate` skips a section when its hash matches, its file name is unchanged, and its mp3
and its words file both exist. The file name comes from the section's number and title, so
renaming a heading voices that section again. The hash leaves out the neighboring sections, so
an edit never voices a neighbor again, although the voice receives the neighbors' text for
continuity. A section that is voiced again costs the characters of its whole text, not only
those of the sentence that changed. The recording stage has no cache of its own, so `--only`
is how a recording is spared.

## Limit a build to one section

```console
decktalk build --only 3                  # narration from the cache, section 3 recorded, then assemble and verify
decktalk build --only 3 --only 4         # two sections, because the flag repeats and does not take commas
decktalk build --only 3 --preset veryfast
```

With `--only`, the `record`, `measure`, and `check` stages touch only the sections named.
Narration still runs for every section, so every section whose text changed is voiced again
whether or not the flag names it, and the cached sections cost nothing. The `assemble` stage
still cuts every section, because the final mp4 needs all of them. Name every section whose
text or page changed. A section left out keeps its old recording even if its words moved.

## Run the stages by hand

Each stage is also a command, and the sequence below is what `build --only 3` does for
the recording.

```console
decktalk narrate                         # cached sections are skipped
decktalk beats
decktalk record --only 3
decktalk measure --only 3
decktalk check --only 3
decktalk assemble
decktalk verify 3:3.1eq
```

After a page edit with no script change, `record --only N`, `measure --only N`, and
`assemble` are enough. After replacing a clip file, `assemble` alone is enough. In both cases
`decktalk verify` measures the result.

## Force a fresh narration

```console
decktalk narrate --force                 # ignore the hash and voice every section again
decktalk build --force
```

A forced run spends credits on every section. `decktalk narrate --dry-run` prints the text
that a run would send, section by section, with no API call, and the character count
follows from it.

## A silent build and a voiced build

The manifest records whether its entries are silent placeholders, and `narrate` reuses the
previous manifest only when it is of the same kind. A silent build writes a placeholder track
for every section over the mp3 file of the same name and replaces the manifest, so the voiced
entries are gone. The next voiced build starts from an empty cache, voices every section
again, and spends credits on all of them. A voiced build after a silent one also starts from
an empty cache, which costs nothing extra, because placeholders are never reused.

Once a project has been voiced, rehearse silently in a separate copy of it, or leave the
silent builds to CI. Neither kind of build replaces the final mp4 until it finishes, and a
timestamped copy of every finished video sits beside `build/out/<name>.mp4`.
