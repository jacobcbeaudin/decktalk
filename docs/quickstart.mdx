---
title: Quickstart
description: Install DeckTalk, build the starter film with no account, then add your own voice.
---

Three lines take a machine with nothing on it to a finished film.

```console
curl -LsSf https://decktalk.ai/install.sh | sh
decktalk init my-lesson && cd my-lesson
decktalk build --no-spend
```

The third line spends nothing and needs no account, because `--no-spend` buys no take and plays a
placeholder wherever a take is missing. Part 3 of this page adds your own voice, which is
the one thing in DeckTalk that costs money.

## Part 1: install

<Steps>
  <Step title="Install the decktalk command">
    <Tabs>
      <Tab title="One line">
        ```console
        curl -LsSf https://decktalk.ai/install.sh | sh
        ```

        The script installs uv if the machine has none, then runs `uv tool install decktalk`, and uv
        brings its own Python. That is all it does. It never runs sudo, and it fetches neither
        Chromium nor ffmpeg, because on Linux that download reaches `apt-get` through sudo and an
        installer you piped into a shell has no business asking for a root password. [Read the
        script](https://decktalk.ai/install.sh) before you run it. That is why it is served from a
        URL rather than hidden in a package.

        It finishes by naming the version it installed and the three commands to run next. Pipe it
        into `sh -s -- --dry-run` to print what it would do and change nothing, and set
        `DECKTALK_VERSION` to install one version rather than the latest.

        It runs on Linux and on macOS. On a musl system such as Alpine it stops and says why, because
        Playwright, which records the slides, publishes no musl wheels. On Windows, use the uv tab.
      </Tab>
      <Tab title="uv">
        ```console
        uv tool install decktalk
        ```

        uv is a Python package manager and it brings its own Python. This is the way to install on
        Windows. [Install uv](https://docs.astral.sh/uv/getting-started/installation/) first if the
        machine has none.
      </Tab>
      <Tab title="pipx">
        ```console
        pipx install decktalk
        ```

        pipx uses a Python already on the machine, which has to be 3.12 or later.
      </Tab>
    </Tabs>

    Check the install by asking for the version.

    ```console
    decktalk --version
    ```

    If the shell cannot find `decktalk`, add `~/.local/bin` to your PATH and open a new shell. That
    is where uv puts the command.
  </Step>

  <Step title="Read the machine">
    `decktalk doctor` reports what is installed and what a run would use. This is what it prints on a
    machine that has recorded before.

    ```console
    decktalk doctor
    ```

    {/* sample: decktalk doctor, on a Mac that has recorded before, with the home folder written as ~ and the source checkout it ran from as ~/workspace/decktalk */}
    ```text
     Tool       Version         Where
     ──────────────────────────────────────────────────────────────────────────────────────────────────
     chromium   153.0.8010.12   ~/Library/Caches/decktalk/ms-playwright/chromium-1243/chrom…
                                Chrome for Testing.app/Contents/MacOS/Google Chrome for Testing
     ffmpeg     8.1.2           ~/Library/Caches/decktalk/ffmpeg/8.1.2-darwin-arm64/ffmpeg
     ffprobe    8.1.2           ~/Library/Caches/decktalk/ffmpeg/8.1.2-darwin-arm64/ffprobe
     katex      0.18.7          ~/workspace/decktalk/src/decktalk/katex

    Python    3.13.1 (~/workspace/decktalk/.venv/bin/python)
    Platform  macOS-26.6.2-arm64-arm-64bit-Mach-O (darwin)
    API key   missing
    ```

    `API key   missing` means `ELEVENLABS_API_KEY` is unset, which is the right state for everything up to
    part 3. KaTeX is not a download: the pinned release ships inside the package, and DeckTalk serves
    it to the page.

    On a machine that has never recorded, the `chromium`, `ffmpeg` and `ffprobe` rows read
    `missing`, and each one comes with a finding. `doctor` also prints `Chromium is not installed. Run
    decktalk install to fetch it.` above the table.

    {/* sample: doctor-empty-cache, DECKTALK_TOOLS_CACHE_DIR=<an empty folder> decktalk doctor, the findings under the table, which exits 1 */}
    ```text
    chromium: FILE_MISSING chromium is not on this machine, so a build that needs it cannot run.
      fix (safe): Fetch chromium into the cache.
    ffmpeg: FILE_MISSING ffmpeg is not on this machine, so a build that needs it cannot run.
      fix (safe): Fetch ffmpeg into the cache.
    ffprobe: FILE_MISSING ffprobe is not on this machine, so a build that needs it cannot run.
      fix (safe): Fetch ffprobe into the cache.
    Found 3 findings, 3 errors. 3 fixable with --fix.
    ```

    The fix is the command `decktalk install`, so `decktalk doctor --fix` fetches what is absent. On a
    terminal, `doctor` offers once to fetch it too. On macOS and Windows you never have to, because the
    first command that needs a tool fetches it. On Linux, run `decktalk install` once first. It is the
    one command that installs Chromium's system libraries.
  </Step>
</Steps>

## Chromium and ffmpeg

DeckTalk drives headless Chromium to record the slides and ffmpeg to cut and encode them. It fetches
both itself, one time per machine, the first time a command needs one. The run announces each
download as it starts and reports the bytes as they arrive, so a long first build says what it is
waiting on. Under `--events` the same thing is one `tool.fetch` line per step on stderr.

{/* sample: DECKTALK_TOOLS_CACHE_DIR=<an empty folder> decktalk install --events --no-input, the first tool.fetch line of stderr */}
```json
{"event":"tool.fetch","time":"2026-01-01T00:00:00.000000Z","seq":2,"run":"769c5119cd83","tool":"chromium","bytes":0,"total_bytes":null}
```

`decktalk install` makes both downloads up front instead, and does nothing else.

```console
decktalk install
```

Nothing has to run it on macOS or Windows, and a build works on a machine where it never has. On
a fresh Linux machine, run it once before the first build.
[What `decktalk install` is for](/requirements#what-decktalk-install-is-for) says when it is worth
running, and [what DeckTalk downloads](/requirements#what-decktalk-downloads) gives the sizes and the
cache paths.

## Part 2: build the starter film

<Steps>
  <Step title="Write the project">
    ```console
    decktalk init my-lesson && cd my-lesson
    ```

    {/* sample: init, decktalk init my-lesson, in an empty folder */}
    ```text
    Wrote my-lesson from the starter example, 14 files.
    Next   cd my-lesson && decktalk build --no-spend
    ```

    On a terminal `init` asks for the name, the example and whether to write the skills. Pass
    `--no-input` to take every default and ask nothing, which is what it does with no terminal
    anyway. `--example NAME` writes a finished project to read rather than the starter to build on,
    and `--no-skills` leaves the packaged skills out.

    | File | What it is |
    |---|---|
    | `script.md` | The narration. Each `## N. Title` heading opens section N. |
    | `decktalk.toml` | The project file: one `[[section]]` per script section, plus the voice, the mix and the score. |
    | `cues.json` | One row per moment on a page, naming the spoken phrase it lands on. |
    | `deck/index.html` | The slides. They load the runtime and KaTeX from `/__decktalk/`, which DeckTalk serves, so the project holds no copy of either. |
    | `.env.example` | The one ElevenLabs variable a voiced run reads, the API key, as a placeholder. |
    | `AGENTS.md` | The rules an agent working in this project follows, written when the directory has none. |
    | `.agents/skills/` | Six packaged skills, with `.claude/skills` beside them. |

    The starter is three sections on one page, and none of it is a demo to delete first.
  </Step>

  <Step title="Build it without buying">
    ```console
    decktalk build --no-spend
    ```

    {/* sample: build, decktalk build --no-spend, on a fresh decktalk init my-lesson, which exits 0 */}
    ```text
    run fc3e5b583fcd, events build/events/fc3e5b583fcd.jsonl
         Narrate    0:00
             Cue    0:00
          Record    0:22
    The project declares no score for this run, so there is nothing to generate.
           Score    0:00
    The loudness pass is skipped because a take is a placeholder, so the soundtrack is encoded as it was mixed.
        Assemble    0:03
          Verify    0:02
           Built build/final/my-lesson.mp4, $0.00, 3 findings
    script.md: TAKE_MISSING Section 1 plays a placeholder, because it has no voiced take yet. Run decktalk narrate --section 1 --spend to buy its take.
    script.md: TAKE_MISSING Section 2 plays a placeholder, because it has no voiced take yet. Run decktalk narrate --section 2 --spend to buy its take.
    script.md: TAKE_MISSING Section 3 plays a placeholder, because it has no voiced take yet. Run decktalk narrate --section 3 --spend to buy its take.
    Found 3 findings, 0 errors.
    ```

    One line per stage, in run order, with the seconds it took. `Built` is the line to read: the
    film, what the run spent, and what the run found. Here that is one
    [`TAKE_MISSING`](/reference/findings/TAKE_MISSING) per section, because no section has a voiced
    take yet and each plays a placeholder. Each is a warning, so the build still exits 0, and each
    names the command that buys its take. [Build times](/reference/measured#build-times) says how
    long this build takes on a named machine that already has Chromium and ffmpeg. Recording is the
    long part. It runs in real time, with several sections recording at once as the machine's CPU
    allows, so a longer film takes longer.

    The two middle lines are the run explaining itself. The starter declares no score, so that
    stage has nothing to do. The loudness pass is skipped because normalising a placeholder to a
    broadcast target would teach you nothing about the mix your voice will make.

    Run the same command again and it takes under a second. Nothing changed, so every stage keeps what
    it made, and `assemble` and `verify` say so.

    If this machine has never run DeckTalk before, the download comes first and the run names it.
  </Step>

  <Step title="Find the film">
    The film and everything that goes with it land in `build/final/`.

    ```console
    ls build/final
    ```

    {/* sample: ls build/final, after the build above */}
    ```text
    my-lesson-poster.png       my-lesson.mp4  placements.json
    my-lesson-transcript.html  my-lesson.srt
    my-lesson.chapters.txt     my-lesson.vtt
    ```

    `my-lesson.mp4` is the film. The name comes from `[project] name` in `decktalk.toml`. The
    captions, the chapter marks, the transcript page and the poster frame are written from the same
    words the film was cut against, so they cannot drift from it.

    <Tabs>
      <Tab title="macOS">
        ```console
        open build/final/my-lesson.mp4
        ```
      </Tab>
      <Tab title="Linux">
        ```console
        xdg-open build/final/my-lesson.mp4
        ```
      </Tab>
      <Tab title="Windows">
        ```console
        start build\final\my-lesson.mp4
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Ask what the project is holding">
    ```console
    decktalk status
    ```

    {/* sample: status-built, decktalk status, after the build above */}
    ```text
     Section   Key   Plays                     Take          Recorded   Assembled   Stale
     ────────────────────────────────────────────────────────────────────────────────────
     1         01    deck/index.html?scene=1   placeholder   yes        yes         no
     2         02    deck/index.html?scene=2   placeholder   yes        yes         no
     3         03    deck/index.html?scene=3   placeholder   yes        yes         no

    Film   build/final/my-lesson.mp4, 0:50 long
    ```

    One row per section, with the scene of the page it plays. `Take` is the section's take state:
    `voiced` once a voice has spoken a take of its current text, voice and settings. A build that does
    not spend writes a placeholder take instead, so it reads `placeholder` here while `Recorded` and
    `Assembled` read `yes`. `Stale` is the column that matters after an edit: it marks a section whose
    inputs have moved since the film was cut. `status` is a reading of the project rather than a third
    opinion beside `check` and `verify`, and the one thing it judges is a file the project names and
    has not got, which is a `FILE_MISSING` error.

    Before the first build the same table reads `missing` under `Take` and `no` in every other column,
    and a `Next` line under it reads `decktalk narrate --no-spend`. Once the film on disk is the one
    the last build measured, there is nothing next, so the line is gone.
  </Step>
</Steps>

## What the starter shows

Three sections on one page, one scene each, every slide written as markup inside a
`<template data-slide>` element. There is no JavaScript in it to read.

| Section | Plays | What it shows |
|---|---|---|
| 1. Open | `deck/index.html?scene=1` | The title and a growing count of files, then a card for each of the two files you write, then a band that fills in on the voice. |
| 2. How it works | `deck/index.html?scene=2` | A heading, one displayed equation typeset by KaTeX, the same average as two lines of Python, and a closing band. |
| 3. Close | `deck/index.html?scene=3` | The idea, the line about rebuilding one part, and the end card. |

Open `deck/index.html` in a browser for the scene index, which lists every scene and every slide
with the cues it declares.

</Frame>

```console
decktalk serve
```

{/* sample: decktalk serve, in the starter */}
```text
Serving http://127.0.0.1:52203
```

`serve` answers from the project directory on 127.0.0.1, which is the origin the recorder uses, so
what the browser shows is what the recorder sees. The port is any free one unless `--port` names
one. Press Ctrl-C to stop it.

The equation in scene 2 is where the starter shows its one trap. `data-tex` holds the TeX and the
element's own text is the fallback that shows if KaTeX ever fails to load, so the fallback is written
to read correctly out loud rather than left as raw TeX.

## Part 3: add your own voice

A voiced build sends each section's text to ElevenLabs and gets speech back, and that is the only
part of DeckTalk that costs money. Stop here if you have no account: the film you built is a complete
film.

<Steps>
  <Step title="Put the key in .env and the voice in decktalk.toml">
    <Tabs>
      <Tab title="macOS and Linux">
        ```console
        cp .env.example .env
        ```
      </Tab>
      <Tab title="Windows">
        ```console
        copy .env.example .env
        ```
      </Tab>
    </Tabs>

    Replace the placeholder with your key, and write the id of the voice to speak in as `[voice] id`
    in `decktalk.toml`.

    ```dotenv .env
    ELEVENLABS_API_KEY=<your-elevenlabs-key>
    ```

    ```toml decktalk.toml
    [voice]
    provider = "elevenlabs"
    id = "<your voice id>"
    ```

    Both values come from your ElevenLabs account. The key is the one credential, and DeckTalk never
    prints it: no value read from `.env` or from the environment reaches a `--json` payload, a log
    line or an error message. The voice id is a published name rather than a secret, so it is
    committed with the project. It says which voice to speak in and grants nothing, since a cloned
    voice is usable only with its own account's key, and it is part of what names a take, so changing
    it voices every section again. `DECKTALK_VOICE_ID` in the environment overrides it for anyone who
    keeps it out of the file.

    A value that still starts with `<` counts as unset, so the example file as it ships approves
    nothing. A variable already in the environment wins over the file. The starter's `.gitignore`
    already covers `.env`, and keeps `.env.example`.
  </Step>

  <Step title="Price the run before you make it">
    `decktalk check` judges the written files and the pages and prices the narration a voiced build
    would buy. It calls no API and writes nothing a stage reads, so it is the one call to make when
    you want the price of the voice. A project with a score prices its sound with
    `decktalk score --no-spend`.

    ```console
    decktalk check --json
    ```

    The result is one flat object carrying `run`, `written`, `judged`, `pages_opened`, `frames_compared`,
    `cost` and `storyboard` beside the four keys every result reserves. Its `cost` is the price:

    {/* sample: check-cost-quickstart, decktalk check --json, on a fresh decktalk init my-lesson, the cost object */}
    ```json
    {
      "state": "estimate",
      "sections": [1, 2, 3],
      "characters": 476,
      "seconds": 39.9,
      "dollars": 0.15,
      "ceiling_dollars": 0.15,
      "billing": "per_character",
      "dollars_per_1000_characters": 0.3,
      "dollars_per_minute": 0.0,
      "price_key": "elevenlabs.dollars_per_1000_characters",
      "averaged": false,
      "price_layer": "project",
      "stages": [
        {
          "state": "estimate",
          "sections": [1, 2, 3],
          "characters": 476,
          "seconds": 39.9,
          "dollars": 0.15,
          "ceiling_dollars": 0.15,
          "billing": "per_character",
          "dollars_per_1000_characters": 0.3,
          "dollars_per_minute": 0.0,
          "price_key": "elevenlabs.dollars_per_1000_characters",
          "averaged": false,
          "price_layer": "project",
          "stage": "narrate"
        }
      ]
    }
    ```

    `dollars` is the price at your rate, and `ceiling_dollars` is the most the run can reach.
    ElevenLabs declares that it bills per character, so the rate is the key `price_key` names,
    `[elevenlabs] dollars_per_1000_characters` in your own `decktalk.toml`, and the figure is your
    plan's and not an invention. [How the price is worked out](/requirements#how-the-price-is-worked-out)
    gives every field and says why the two dollar figures can differ.
  </Step>

  <Step title="Look at what you are about to buy">
    ```console
    decktalk storyboard
    ```

    {/* sample: storyboard, decktalk storyboard, on the starter */}
    ```text
    Wrote build/storyboard.html, 16 panels.
    ```

    A storyboard freezes every slide at every cue onto one page. It is the checkpoint before anything
    is bought: open `build/storyboard.html` and read the film as stills, because a slide you fix here
    costs nothing and a slide you fix after a voiced build costs that section again. `--section`,
    `--slide`, `--after`, `--before` and `--at` narrow the sheet.
  </Step>

  <Step title="Build with your voice">
    <Warning>This command buys from ElevenLabs, at your plan's rate.</Warning>

    ```console
    decktalk build --spend --max-cost 1
    ```

    `--spend` approves the spend. `--max-cost N` refuses the whole run before the first paid call
    when the most it can cost is over N US dollars, and the refusal names the figure that would let
    it through. A ceiling of five cents on this project reads:

    {/* sample: build-over-the-ceiling, decktalk build --spend --max-cost 0.05, on the starter with [voice] id set and no API key, which exits 2 before any request */}
    ```text
    error[APPROVAL]: This run costs $0.15 for 476 characters at $0.30 per 1,000 characters. The most it can cost, $0.15, is over the $0.05 ceiling --max-cost set.
      hint: Raise the ceiling to --max-cost 0.15, or narrow the run with --section.
      docs: https://docs.decktalk.ai/reference/errors/APPROVAL
    ```

    The price is held to the ceiling before anything else, so a run the ceiling refuses opens no run
    and draws nothing. A run within it draws the storyboard next, so it is there to read before you
    approve.

    On a terminal, `decktalk build` with neither flag prints the price and asks. With no terminal
    there is nobody to ask, so it refuses rather than guessing, and the refusal carries the price, so
    one call prices the run.

    {/* sample: build-no-terminal, decktalk build --no-input, on the starter with [voice] id set and no API key, which exits 2 */}
    ```text
    error[APPROVAL]: This run costs $0.15 for 476 characters at $0.30 per 1,000 characters. No terminal is here to approve it.
      hint: Run decktalk build --spend to approve that cost, or decktalk build --no-spend to play a placeholder wherever a take is missing and silence where a sound is unbought.
      docs: https://docs.decktalk.ai/reference/errors/APPROVAL
    ```

    A take is named by the digest of its text and its voice settings, so the next build voices only the
    sections whose words or voice changed and reads the rest from the cache.
  </Step>
</Steps>
