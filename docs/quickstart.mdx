title: Quickstart
description: Install DeckTalk, build the starter film with no account, then add your own voice.
---

Three lines take a machine with nothing on it to a finished film.

```console
curl -LsSf https://decktalk.ai/install.sh | sh
decktalk init my-lesson && cd my-lesson
decktalk build --no-voice
```

The third line spends nothing and needs no account, because `--no-voice` writes placeholder
narration and a click track in place of a voice. Part 3 of this page adds your own voice, which is
the one thing in DeckTalk that costs money.

## Part 1: install

<Steps>
  <Step title="Install the decktalk command">
    <Tabs>
      <Tab title="One line">
        ```console
        curl -LsSf https://decktalk.ai/install.sh | sh
        ```

        The script installs uv if the machine has none, then runs `uv tool install decktalk`, and uv
        brings its own Python. That is all it does. It never runs sudo, and it fetches neither
        Chromium nor ffmpeg, because on Linux that download reaches `apt-get` through sudo and an
        installer you piped into a shell has no business asking for a root password. [Read the
        script](https://decktalk.ai/install.sh) before you run it. That is why it is served from a
        URL rather than hidden in a package.

        It finishes by naming the version it installed and the three commands to run next. Pipe it
        into `sh -s -- --dry-run` to print what it would do and change nothing, and set
        `DECKTALK_VERSION` to install one version rather than the latest.

        It runs on Linux and on macOS. On a musl system such as Alpine it stops and says why, because
        Playwright, which records the slides, publishes no musl wheels. On Windows, use the uv tab.
      </Tab>
      <Tab title="uv">
        ```console
        uv tool install decktalk
        ```

        uv is a Python package manager and it brings its own Python. This is the way to install on
        Windows. [Install uv](https://docs.astral.sh/uv/getting-started/installation/) first if the
        machine has none.
      </Tab>
      <Tab title="pipx">
        ```console
        pipx install decktalk
        ```

        pipx uses a Python already on the machine, which has to be 3.12 or later.
      </Tab>
    </Tabs>

    Check the install by asking for the version.

    ```console
    decktalk --version
    ```

    If the shell cannot find `decktalk`, add `~/.local/bin` to your PATH and open a new shell. That
    is where uv puts the command.
  </Step>

  <Step title="Read the machine">
    `decktalk doctor` reports what is installed and what a run would use. This is what it prints on a
    machine that has recorded before.

    ```console
    decktalk doctor
    ```

    ```text
     Tool       Version         Where
     ──────────────────────────────────────────────────────────────────────────────────
     chromium   153.0.8010.12
     ffmpeg     8.1.2           ~/Library/Caches/decktalk/ffmpeg/8.1.2-darwin-arm64/ffmpeg
     ffprobe    8.1.2           ~/Library/Caches/decktalk/ffmpeg/8.1.2-darwin-arm64/ffprobe
     katex      0.18.7          ~/.local/share/uv/tools/decktalk/lib/python3.13/site-p…

    Python    3.13.1 (~/.local/share/uv/tools/decktalk/bin/python)
    Platform  macOS-26.6.2-arm64-arm-64bit-Mach-O (darwin)
    Voice key no
    ```

    `Voice key no` means `ELEVENLABS_API_KEY` is unset, which is the right state for everything up to
    part 3. KaTeX is not a download: the pinned release ships inside the wheel, and `decktalk init`
    copies it into the project.

    `doctor` fetches nothing itself, so on a machine that has never recorded the `chromium`, `ffmpeg`
    and `ffprobe` rows read `missing`, and each one comes with a finding.

    ```text
    chromium: FILE_MISSING chromium is not on this machine, so a build that needs it cannot run.
      fix (safe): Fetch chromium into the cache.
    Found 1 finding, 1 certain. 1 fixable with --fix.
    ```

    The fix is the command `decktalk install`, so `decktalk doctor --fix` fetches what is absent. You
    never have to, because the first command that needs a tool fetches it.
  </Step>
</Steps>

## Chromium and ffmpeg

DeckTalk drives headless Chromium to record the slides and ffmpeg to cut and encode them. It fetches
both itself, one time per machine, the first time a command needs one. The run announces each
download as it starts and reports the bytes as they arrive, so a long first build says what it is
waiting on. Under `--events` the same thing is one `fetch` line per step on stderr.

```text
{"event":"fetch","time":"2026-09-24T10:36:18.527286Z","seq":1,"run":"85725c3fff31","tool":"chromium","bytes":0,"total_bytes":null}
{"event":"fetch","time":"2026-09-24T10:36:19.030032Z","seq":2,"run":"85725c3fff31","tool":"ffmpeg","bytes":0,"total_bytes":28196358}
```

`decktalk install` makes both downloads up front instead, and does nothing else.

```console
decktalk install
```

Nothing has to run it, and a build works on a machine where it never has. It exists for the three
cases where the timing of a few hundred megabytes matters: a `RUN decktalk install` layer in a
Dockerfile is cached, a CI job gets one step to cache and one place to read when a download fails,
and a laptop that is about to go offline gets everything while there is a network. On Linux it is
also the one command that installs Chromium's system libraries, and therefore the one command that
may ask for a password. [Requirements and costs](/requirements#what-decktalk-downloads) gives the
sizes and the cache paths.

## Part 2: build the starter film

<Steps>
  <Step title="Write the project">
    ```console
    decktalk init my-lesson && cd my-lesson
    ```

    ```text
    Wrote my-lesson from the starter example, 16 files.
    Next   cd my-lesson && decktalk build --no-voice
    ```

    On a terminal `init` asks for the name, the example and whether to write the skills. Pass
    `--defaults` to take every default and ask nothing, which is what it does with no terminal
    anyway. `--example NAME` writes a finished project to read rather than the starter to build on,
    and `--no-skills` leaves the packaged skills out.

    | File | What it is |
    |---|---|
    | `script.md` | The narration. Each `## N. Title` heading opens section N. |
    | `decktalk.toml` | The project file: one `[[section]]` per script section, plus the voice, the mix and the soundscape. |
    | `cues.json` | One row per moment on a page, naming the spoken phrase it lands on. |
    | `deck/index.html` | The slides, with `deck/decktalk-runtime.js` and `deck/katex/` beside them. |
    | `.env.example` | The two ElevenLabs variables a voiced run reads, as placeholders. |
    | `AGENTS.md` | The rules an agent working in this project follows, written when the directory has none. |
    | `.agents/skills/` | Six packaged skills, with `.claude/skills` beside them. |

    The starter is three sections on one page, and none of it is a demo to delete first.
  </Step>

  <Step title="Build it with no voice">
    ```console
    decktalk build --no-voice
    ```

    ```text
    run 819a92a4ab4f, events build/events/819a92a4ab4f.jsonl
         Narrate    0:00
             Cue    0:00
          Record    0:56
    The project declares no soundscape for this run, so there is nothing to generate.
      Soundscape    0:00
    The loudness pass is skipped because the narration is a placeholder, so the soundtrack is encoded as it was mixed.
        Assemble    0:02
    another cue sits close to 1:1.1:title, so its probes were fitted to 0.7, 1.281 seconds after it.
    another cue sits close to 1:1.1:files, so its probes were fitted to 0.7, 1.14 seconds after it.
    another cue sits close to 3:3.1:again, so its probes were fitted to 0.7, 0.772 seconds after it.
    another cue sits close to 3:3.1:make, so its probes were fitted to 0.62, 1.5 seconds after it.
          Verify    0:09
           Built build/final/my-lesson.mp4, $0.00, nothing found
    ```

    One line per stage, in run order, with the seconds it took. The last line is the one to read:
    `Built`, the film, what the run spent, and what the measurements found. That run took 69 seconds
    in all on a MacBook Pro with an Apple M5 Pro and 64 GB of memory, on a machine that already had
    Chromium and ffmpeg. Recording is the long part and it runs in real time, so a longer film takes
    longer.

    The middle lines are the run explaining itself. The starter declares no soundscape, so that stage
    has nothing to do. The loudness pass is skipped because normalising a click track to a broadcast
    target would teach you nothing about the mix your voice will make. The four `verify` lines say
    that two cues sat close enough together that the probes either side of the first were fitted into
    the gap.

    If this machine has never run DeckTalk before, the download comes first and the run names it.
  </Step>

  <Step title="Find the film">
    The film and everything that goes with it land in `build/final/`.

    ```console
    ls build/final
    ```

    ```text
    cuts.json             my-lesson-transcript.html  my-lesson.mp4  my-lesson.vtt
    my-lesson-poster.png  my-lesson.chapters.txt     my-lesson.srt
    ```

    `my-lesson.mp4` is the film. The name comes from `[project] name` in `decktalk.toml`. The
    captions, the chapter marks, the transcript page and the poster frame are written from the same
    word clock the film was cut against, so they cannot drift from it.

    <Tabs>
      <Tab title="macOS">
        ```console
        open build/final/my-lesson.mp4
        ```
      </Tab>
      <Tab title="Linux">
        ```console
        xdg-open build/final/my-lesson.mp4
        ```
      </Tab>
      <Tab title="Windows">
        ```console
        start build\final\my-lesson.mp4
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Ask what the project is holding">
    ```console
    decktalk status
    ```

    ```text
     Section   Key   Plays                     Voiced   Recorded   Cut   Stale
     ─────────────────────────────────────────────────────────────────────────
     1         01    deck/index.html?scene=1   yes      yes        yes   no
     2         02    deck/index.html?scene=2   yes      yes        yes   no
     3         03    deck/index.html?scene=3   yes      yes        yes   no

    Film   build/final/my-lesson.mp4, 0:50 long
    Next   decktalk verify
    ```

    One row per section, with the scene of the page it plays. `Voiced` is true when a take of that
    section's current text is on disk, which a build without voice writes as a placeholder, so it
    reads `yes` here. `Stale` is the column that matters after an edit: it marks a section whose
    inputs have moved since the film was cut. `status` judges nothing and never exits 1, so it is a
    reading of the project rather than a third opinion beside `check` and `verify`.

    Before the first build the same table reads `no` in every column, and `Next` reads
    `decktalk narrate --no-voice`.
  </Step>
</Steps>

## What the starter shows

Three sections on one page, one scene each, every slide written as markup inside a
`<template data-slide>` element. There is no JavaScript in it to read.

| Section | Plays | What it shows |
|---|---|---|
| 1. Open | `deck/index.html?scene=1` | The title and a growing count of files, then a card for each of the two files you write, then a band that fills in on the voice. |
| 2. How it works | `deck/index.html?scene=2` | A heading, one displayed equation typeset by KaTeX, the same average as two lines of Python, and a closing band. |
| 3. Close | `deck/index.html?scene=3` | The idea, the line about rebuilding one part, and the end card. |

Open `deck/index.html` in a browser for the scene index, which lists every scene and every slide
with the cues it declares.

</Frame>

```console
decktalk serve
```

```text
Serving . on http://127.0.0.1:64517
```

`serve` answers from the project directory on 127.0.0.1, which is the origin the recorder uses, so
what the browser shows is what the recorder sees. The port is any free one unless `--port` names
one. Press Ctrl-C to stop it.

The equation in scene 2 is where the starter shows its one trap. `data-tex` holds the TeX and the
element's own text is the fallback that shows if KaTeX ever fails to load, so the fallback is written
to read correctly out loud rather than left as raw TeX.

## Part 3: add your own voice

A voiced build sends each section's text to ElevenLabs and gets speech back, and that is the only
part of DeckTalk that costs money. Stop here if you have no account: the film you built is a complete
film.

<Steps>
  <Step title="Put the two values in .env">
    <Tabs>
      <Tab title="macOS and Linux">
        ```console
        cp .env.example .env
        ```
      </Tab>
      <Tab title="Windows">
        ```console
        copy .env.example .env
        ```
      </Tab>
    </Tabs>

    Replace the two placeholders with your own values.

    ```dotenv .env
    ELEVENLABS_API_KEY=<your-elevenlabs-key>
    ELEVENLABS_VOICE_ID=<voice-id>
    ```

    Both values come from your ElevenLabs account. The key is the one credential, and DeckTalk never
    prints it: no value read from `.env` or from the environment reaches a `--json` payload, a log
    line or an error message. The voice id is a published name rather than a secret. It says which
    voice to speak in and grants nothing, and it is part of what names a take, so changing it voices
    every section again.

    A value that still starts with `<` counts as unset, so the example file as it ships approves
    nothing. A variable already in the environment wins over the file. The starter's `.gitignore`
    already covers `.env`, and keeps `.env.example`.
  </Step>

  <Step title="Price the run before you make it">
    `decktalk check` judges the written files and the pages and prices what a voiced build would
    cost. It produces nothing and calls no API, so it is the one call to make when you want the
    price of a run.

    ```console
    decktalk check --json
    ```

    The result is one flat object carrying `judged`, `pages`, `frames`, `storyboard`, `written` and
    `findings` beside the four keys every result reserves. Its `spend` is the price:

    ```json
    {
      "state": "estimate",
      "sections": [1, 2, 3],
      "characters": 476,
      "dollars": 0.14,
      "ceiling_dollars": 0.14,
      "price_per_1000_characters": 0.3,
      "price_layer": "project"
    }
    ```

    `state` is `estimate` for what a run would cost and `charged` for what one did cost.
    `characters` is what would be sent, `dollars` is that at the stated rate, and `ceiling_dollars`
    is the most the run can reach. The rate is `[voice] price_per_1000_characters` in your own
    `decktalk.toml`, and `price_layer` names which of the five settings layers set it, so the figure
    is your plan's and not an invention. [Requirements and costs](/requirements#how-the-price-is-worked-out)
    explains why the two dollar figures can differ.
  </Step>

  <Step title="Look at what you are about to buy">
    ```console
    decktalk storyboard
    ```

    ```text
    Wrote build/storyboard.html, 16 panels.
    ```

    A storyboard freezes every slide at every cue onto one page. It is the checkpoint before credits
    are spent: open `build/storyboard.html` and read the film as stills, because a slide you fix here
    costs nothing and a slide you fix after a voiced build costs that section again. `--section`,
    `--slide`, `--after`, `--before` and `--at` narrow the sheet.
  </Step>

  <Step title="Build with your voice">
    <Warning>This command spends ElevenLabs credits.</Warning>

    ```console
    decktalk build --spend --max-cost 1
    ```

    `--spend` approves the spend. `--max-cost N` refuses the whole run before the first paid call
    when the most it can cost is over N US dollars, and the refusal names the figure that would let
    it through. A ceiling of five cents on this project reads:

    ```text
    error[APPROVAL]: this run can cost up to $0.14, which is over the $0.05 ceiling --max-cost set.
      hint: Raise the ceiling to --max-cost 0.14, or narrow the run with --section.
      docs: https://docs.decktalk.ai/reference/errors/APPROVAL
    ```

    On a terminal, `decktalk build` with neither flag prints the price and asks. With no terminal
    there is nobody to ask, so it refuses rather than guessing, and the refusal carries the price, so
    one call prices the run.

    ```text
    error[APPROVAL]: voicing 3 sections sends 476 characters and costs up to $0.14, and no terminal is here to approve it.
      hint: Run decktalk build --spend to approve that spend, or decktalk build --no-voice to finish with placeholder narration.
      docs: https://docs.decktalk.ai/reference/errors/APPROVAL
    ```

    A take is named by the hash of its text and its voice settings, so the next build voices only the
    sections whose words or voice changed and reads the rest from the cache.
  </Step>
</Steps>
