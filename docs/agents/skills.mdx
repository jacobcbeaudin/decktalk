DeckTalk ships six agent skills. A skill is a folder with a `SKILL.md` file, written in the Agent
Skills open format, that a coding agent loads when a task matches its description.

The skills carry only what a command line cannot say. The CLI is the instruction set and it
documents itself, so a skill never repeats a flag, a default or a code. What is left is craft:
writing for the ear, spoken symbols, cue phrases, slide patterns, reading a finding, and the scope
of a revision.

That rule is enforced rather than intended. The repository's own tests refuse a skill that names a
command outside the final vocabulary, that spells a command line or a flag, or that names a vendor,
a model or a harness. A skill that pointed at something the tool does not have would fail the suite,
exactly like a test that lies.

The skills live inside the Python package, so every installation carries the skills that match its
own CLI. `decktalk init` writes them into a new project, and
[Install the skills](/agents/install) covers the folders they land in.

## The six skills

| Skill | It starts when | It ends with |
|---|---|---|
| `decktalk-script` | someone asks for a new narrated video, explainer, tutorial, product demo or lesson, adds a section, or changes what the voice says. | A script written for the ear, and a table of every spoken phrase beside the symbol it stands for. |
| `decktalk-slide` | a narrated video needs a new slide or scene, when maths or code has to appear on screen, when a picture must be added to an existing section, or when a reveal is too small, overlapping or off frame. | Markup that obeys the page contract, with every reveal large enough to be seen and described for a reader. |
| `decktalk-cues` | a script, a page or a reveal changes, when a cue is reported as unresolved or unknown, or when a picture appears early, late or not at all. | Every moment on the page matched to a phrase, in both directions, with the gaps a viewer can follow. |
| `decktalk-build` | someone asks to build, render, export, preview or check a narrated video, an explainer, a tutorial or a lesson, or after any edit to the script, the cues, the project file or a deck page. | A verified film, and an author who saw the price and the frames before either was spent. |
| `decktalk-fix` | a command reports a finding, when a cue is unresolved or unknown, when a reveal lands off its word or shows no change, when a recording stalls or opens black, or when a check could measure nothing at all. | The smallest edit that removes the cause, and the command that failed run again on what changed. |
| `decktalk-revise` | someone says a demo, tutorial, explainer or lesson is out of date, asks for this week's update, or names a release that changed what the film claims. | The fewest edits, a rebuild of the changed sections alone, and a note saying what changed and what it cost. |
{/* skills:end */}

Each skill ends with a hand-off section that names the sibling a different job belongs to, so an
agent that starts in the wrong one is sent to the right one rather than improvising. A rule two
skills share is one file, byte for byte, in both.

## What the skills will not do on their own

The skills are written so that an agent cannot spend your money or hide a failure.

- A voiced run stops and asks. `decktalk-build` names every section a voiced run would voice and
  why, the total, and the price the estimate is based on, and then waits for an answer. When nobody
  can answer, it runs only what spends nothing.
- No skill passes a flag that hides a finding, forces a run past a refusal or discards a paid take.
- No skill changes the voice, the model or a voice setting without an answer, because each of those
  re-voices every section that uses it.
- No skill buys music or an effect without an answer of its own, because generated sound spends too.
- `decktalk-fix` reads the findings out of the JSON rather than parsing a printed table, fixes the
  cause rather than the measurement, and stops after three tries with a report instead of a fourth
  guess.
- No skill reports a film as done while a certain finding stands.
- An error is not a finding. On an error the agent stops and tells you, because an error means
  DeckTalk itself could not run.

No portable field in the skill format stops a model from starting a skill on its own, so these
guards live in the skill text and in the CLI rather than in front matter.

## The other agent surfaces

A skill is not the only thing to hand an agent.

- [AGENTS.md](/agents/agents-md) is the short file `decktalk init` writes, which names the four calls
  that tell an agent everything.
- [The reference card](/reference/card) puts the install, the four input files, every command, the
  JSON contract, the exit codes, the stages, the page vocabulary and the settings on one page. Hand
  it to an agent that has no skills loaded.
- [The JSON contract](/agents/json) is what an agent reads back after every command.
- [`llms.txt`](https://docs.decktalk.ai/llms.txt) indexes every page on this site, and
  [`llms-full.txt`](https://docs.decktalk.ai/llms-full.txt) is the whole site as one file. Hand
  those to an agent that can fetch a URL.

DeckTalk ships no MCP server. The CLI with `--json` and its exit codes is the machine interface, and
the skills teach an agent to use it.
