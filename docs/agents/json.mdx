---
title: The JSON contract
description: The one flat object every command prints under --json, the finding and fix shapes inside it, the error codes, the exit codes and the event stream.
---

Every DeckTalk command takes `--json`. Under that flag the command prints exactly one JSON object on
stdout, prints nothing else on stdout, turns colour off and sends every log line to stderr. An error
prints an object too, so a caller that reads stdout always has something to parse.

There is no wrapper. The object is flat: the reserved keys and the command's own fields sit side by
side at the top level. There is no `command` key, no `exit_code` key and no nesting under the
command's name. A reader that wants a field reads it, and a reader that wants to know which fields a
command has reads `decktalk schema NAME`.

```console
decktalk status --json
decktalk schema status      # the JSON Schema of the object that call prints
decktalk schema             # every command, flag, exit, error code and finding code, in one object
```

## The four reserved keys

Every result carries all four.

| Key | Type | Meaning |
|---|---|---|
| `schema` | integer | The shape version of the object, which is `1`. It changes only when the shape changes, and it is not the product version. Check it before reading anything else. |
| `ok` | boolean | True when the command ran and judged nothing that reaches the threshold `--fail-on` and `--allow` set, so it is true exactly when the command exits 0. |
| `findings` | array | Every judgement this call made, in the order it made them, which is the order the `finding.raised` events streamed. Empty when it judged nothing. Read `severity` to tell the ones that fail the run from the rest. |
| `error` | object or null | Filled only when the command could not run at all, and null otherwise. |

## The two declared fields

Two more fields are declared once and carried by the commands that earn them, so a reader learns
from the schema which commands do those things rather than meeting a null on the ones that do not.

| Key | Type | Carried by |
|---|---|---|
| `run` | string | Every result whose command opens a run, which is every command except the five under `config`. It is the run id, and it names the run's events file. |
| `written` | array of strings | Every result whose command writes a file, as project-relative POSIX paths in the order they were written. |

`init`, `check`, `storyboard`, `narrate`, `cue`, `record`, `score`, `assemble`, `build`,
`clip`, `config set` and `config unset` declare `written`. `doctor`, `install`, `status`, `words`,
`serve`, `verify`, `config list`, `config get` and `config explain` do not, because they write
nothing.

A result that carries an error and nothing else carries neither field, because a command that was
refused before it reached its own implementation opened no run and wrote no file.

## The one exemption

`decktalk schema` prints the contract document itself with no reserved keys around it. A JSON Schema
document inside a wrapper is not that document, and a key called `schema` set to `1` inside a
document about schemas is unreadable. Every other command under `--json` prints one flat object.

```console
decktalk schema finding     # the Finding model, with its fixes and its codes
decktalk schema error       # the error object
decktalk schema event       # every event line
decktalk schema setting     # every setting, its default, its range, its unit and its hazard
decktalk schema page        # every page attribute
decktalk schema cues        # the shape of cues.json
```

`next` is the whole command to run next, so an agent that has just read the project already knows
what to run. It is null once the film on disk is the one the last build measured. `runs` lists every
run of this project whose events file is still open. `unplayed` lists the takes on disk that no
section plays, and is null when no voice is named, because then no take can be matched to a section.
`take_state` is what the disk holds for each spoken section: `voiced`, `unchecked`, `stale`,
`placeholder` or `missing`, with `take_reason` saying why in words. narrate, check and watch read the
same rule.

`decktalk check --no-pages --json` judges the written files with no browser at all and says which
judgements it therefore could not reach. It makes no film and prices what a voiced build would
cost, so it is the one call an agent makes to learn the price of a run.

`pages` and `frames` say how far the judgement reached. Both are true on a plain `decktalk check`,

every code it could not reach. `dollars` is the price at the rate the voice publishes, and
`ceiling_dollars` is the most the run could cost. `--max-cost` is compared against `ceiling_dollars`
and never against `dollars`, because a provider charges one request at a time.

To add the `take.charged` and `sound.charged` lines yourself, add each `dollars` as the decimal it is
written as, settle the sum to the nearest billionth of a dollar, then round up to the cent: that is the
stage's charged `dollars`.

## A build that stopped

A build stops after the stage whose findings reach the threshold, and the stages after it are
`skipped`. It is still a result and not an error, so it exits 1, `error` is null, and `stopped_at`
names the stage. This is `decktalk build --no-spend --json` on a starter whose cue waits for a phrase
the script does not speak, cut to the keys a build adds.

{/* sample: decktalk build --no-spend --json, on a starter whose cue 3.1:idea waits for "a phrase nobody says", cut to the keys a build adds */}
```json
{
  "schema": 1,
  "ok": false,
  "error": null,
  "stages": [
    {"stage": "narrate", "outcome": "ran", "elapsed_seconds": 0.348},
    {"stage": "cue", "outcome": "ran", "elapsed_seconds": 0.005},
    {"stage": "record", "outcome": "skipped", "elapsed_seconds": 0.0},
    {"stage": "score", "outcome": "skipped", "elapsed_seconds": 0.0},
    {"stage": "assemble", "outcome": "skipped", "elapsed_seconds": 0.0},
    {"stage": "verify", "outcome": "skipped", "elapsed_seconds": 0.0}
  ],
  "spend": false,
  "film": null,
  "stopped_at": "cue"
}
```

`spend` is true when the caller let the run buy what is missing, which `--spend` does. A run that
may not plays every take on disk and reports each section whose take is missing as
[`TAKE_MISSING`](/reference/findings/TAKE_MISSING), a warning, so a draft build still
runs through under the default threshold.

`stopped_at` is null on a build that ran through, whatever it found. `--allow CODE` carries a build
past a code, and `--fail-on` moves the threshold, so both decide what stops a build exactly as they
decide what fails it.

## A result that could not run

`decktalk words --json` before anything has been narrated. `findings` is empty and `error` is
filled, because nothing was judged. This result carries neither `run` nor `written`, because the
command opened no run and wrote nothing.

{/* sample: decktalk words --json, on a fresh decktalk init my-lesson */}
```json
{
  "schema": 1,
  "ok": false,
  "findings": [],
  "error": {
    "code": "NOT_BUILT",
    "message": "takes.json has not been built.",
    "hint": "Run `decktalk narrate` first, or `decktalk narrate --no-spend` to spend nothing.",
    "location": null,
    "docs": "https://docs.decktalk.ai/reference/errors/NOT_BUILT"
  }
}
```

A bad command line is an error too, with the code `USAGE` and exit 2. Pass `--json` before the
command name to get the object rather than the text form, because a flag after an unknown flag is
never parsed.

{/* sample: decktalk --json check --nope, which exits 2 */}
```json
{
  "schema": 1,
  "ok": false,
  "findings": [],
  "error": {
    "code": "USAGE",
    "message": "decktalk check: --nope is not a flag of this command. Did you mean --no-pages?",
    "hint": "Run decktalk check --help for this command's flags, or decktalk schema for the whole contract.",
    "location": null,
    "docs": "https://docs.decktalk.ai/reference/errors/USAGE"
  }
}
```

## A finding

A finding is one judgement, in the same shape in every result, in the event stream and in the
library. `decktalk schema finding` prints the model, and `decktalk schema` prints every code with
its sentence, its severity and the settings keys that move it.

| Key | Type | Meaning |
|---|---|---|
| `code` | string | The stable code a caller dispatches on, such as `CUE_OFF`. [Finding codes](/reference/cli#finding-codes) lists every one. |
| `message` | string | One sentence, with every measured number and its limit written into it. |
| `severity` | `error` or `warning` | Whether this is wrong for sure or only probably wrong. |
| `location` | object | Where the finding is. |
| `stage` | stage name or null | The stage that raised it, or null when no stage did. |
| `fix` | object or null | A change that resolves it, or null when none is known. |
| `docs` | string | The docs page for this code. |

`severity` and `docs` are the code's own and are written into the object rather than left for a
reader to look up, so one line of JSON carries everything a decision needs.

`location` carries five keys. `where` is required and never null, because the object a finding
judges is what tells a reader which side of the spend it came from.

| Key | Type | Meaning |
|---|---|---|
| `where` | string | The object this finding judges, such as a cue's cue id, a slide or a file. |
| `file` | string or null | The file to open, project-relative. |
| `line` | integer or null | The line in that file, counting from one. |
| `section` | integer or null | The section number this is about. |
| `cue` | string or null | The cue id of the cue this is about. |

## The two fixes

A `fix` is one of two kinds, and `kind` is the discriminator. Every fix carries a `title`, which
is one sentence saying what applying it does, and an `applicability`, which decides whether it may
be applied without asking.

| `applicability` | Meaning |
|---|---|
| `safe` | Applying it cannot lose the author's work, so `--fix` applies it. |
| `unsafe` | Applying it can lose the author's work, so it is printed and never applied by a flag. |
| `display` | A change only a person can make, so it is printed and never applied. |

**`kind: "edit"`** changes files. Its `edits` array is applied together or not at all. Each edit
names one file and exactly one locator, so nothing has to be guessed: `pointer` is a JSON pointer
for a JSON file, `key` is a dotted TOML key for a TOML file, such as a settings key in `decktalk.toml`, and `line` is a line number for any
other text file. `old` is what is there now, or null when the edit only adds, and `new` is what goes
there instead, which is the empty string when the edit removes.

This one comes from a `CUE_UNLISTED` finding that `decktalk check --json` raised on a project whose
deck declares two moments `cues.json` does not list.

{/* sample: decktalk check --json, on a starter with the rows 3.1:again and 3.1:make deleted from cues.json */}
```json
{
  "kind": "edit",
  "title": "Add 2 rows to section 3 of cues.json, each waiting for the words you write in its `phrase`.",
  "applicability": "safe",
  "edits": [
    {
      "file": "cues.json",
      "pointer": null,
      "key": null,
      "line": 30,
      "old": null,
      "new": "        {\"id\": \"3.1:again\", \"phrase\": \"\"},\n        {\"id\": \"3.1:make\", \"phrase\": \"\"},"
    }
  ]
}
```

**`kind: "command"`** runs a command. Its `command` array is the whole argv, one argument per
element, so a caller hands it straight to a subprocess with no shell. This one comes from
`decktalk doctor --json` on a machine whose cache holds none of the tools, which raises one such
fix for each of Chromium, ffmpeg and ffprobe.

{/* sample: DECKTALK_TOOLS_CACHE_DIR=<an empty folder> decktalk doctor --json, the ffmpeg finding's fix */}
```json
{
  "kind": "command",
  "title": "Fetch ffmpeg into the cache.",
  "applicability": "safe",
  "command": ["decktalk", "install"]
}
```

`--fix` applies every safe fix a command found, `--no-fix` applies none, and an unsafe or display
fix is printed either way and never applied. It is on `doctor`, `check` and `build`. In the library
the same call is `Project.apply(finding)`, which takes `unsafe=True` to reach an unsafe fix and
never reaches a display one.

## Which findings fail a run

`--fail-on` names the least severe finding that fails a run, and `--allow` names an exception.

| Flag | Effect |
|---|---|
| `--fail-on error` | Exit 1 on an error. This is the default. |
| `--fail-on warning` | Exit 1 on any finding, error or warning. |
| `--fail-on never` | Exit 0 whatever was found. The findings are still in the result. |
| `--allow CODE` | Carry on past this one code. Repeats. |

Both are on `doctor`, `check`, `storyboard`, `narrate`, `cue`, `record`, `score`, `assemble`,
`verify` and `build`, which are the commands that can judge something.

## Errors and exit codes

An error means DeckTalk could not run, so nothing was judged. The error object carries `code`,
`message`, `hint`, `location` and `docs`. `hint` is the smallest next action, or null: the whole command that clears a refusal, or how to report a bug.
`location` is the same five-key object a finding carries, or null. `message` never carries the value
of a secret. [Error codes](/reference/cli#error-codes) lists every code with its exit, and each code
has a page of its own, such as [`NOT_BUILT`](/reference/errors/NOT_BUILT).
[Exit codes](/reference/cli#exit-codes) is the one table of what each exit means.

The rule an agent follows is one line. A non-zero exit with `error` null is a finding, so read
`findings`, change the project and run the command again. A non-null `error` is an error, so stop
and tell the person. Write the branch as `error == null` rather than as an exit number, because a
broken machine can exit non-zero for reasons that are not the project's fault.

## The event stream

A result arrives when the call is over. The event stream says what is happening while it runs.
`--events` prints one JSON line per event on stderr as it happens, and every run of a project also
appends the same lines to `build/events/<run>.jsonl`, named by the run id the result carries. A run
with no project behind it, such as `decktalk doctor` outside one, reports `events_file` as null and
appends nothing.

{/* sample: decktalk build --no-spend --events --json, the first six lines of stderr, on a fresh decktalk init my-lesson */}
```json
{"event":"run.start","time":"2026-10-02T07:36:49.958492Z","seq":0,"run":"d8244c090102","events_file":"build/events/d8244c090102.jsonl"}
{"event":"run.log","time":"2026-10-02T07:36:49.959299Z","seq":1,"run":"d8244c090102","level":"debug","message":"This run holds the build directory.","source":"project","stage":null,"section":null,"data":{"pid":15057,"lock":".lock"}}
{"event":"stage.start","time":"2026-10-02T07:36:49.971981Z","seq":2,"run":"d8244c090102","stage":"narrate","index":1,"count":6}
{"event":"run.log","time":"2026-10-02T07:36:49.973050Z","seq":3,"run":"d8244c090102","level":"debug","message":"3 takes are made on 2 workers.","source":"stages.narrate","stage":"narrate","section":null,"data":{"workers":2,"jobs":3,"requested":2}}
{"event":"section.start","time":"2026-10-02T07:36:49.973254Z","seq":4,"run":"d8244c090102","stage":"narrate","section":1}
{"event":"section.start","time":"2026-10-02T07:36:49.973403Z","seq":5,"run":"d8244c090102","stage":"narrate","section":2}
```

Under `--events` every line of stderr is one JSON object. The sentences DeckTalk would otherwise
print are `run.log` lines among them, the first line is `run.start`, which names the file the events are
appended to, and a refusal is written as the one object `{"ok": false, "error": {...}}`.

The discriminator key is `event`, and every line carries `event`, `time`, `seq` and `run`. `seq`
counts from zero inside its run, so a reader can order lines that arrived out of order.

| `event` | What it says | Its own fields |
|---|---|---|
| `run.start` | A run opened. | `events_file` |
| `run.done` | A run closed, and why when it did not finish. | `outcome`, `elapsed_seconds`, `error`, `dropped` |
| `stage.start` | A stage began, with its place in the run's plan. | `stage`, `index`, `count` |
| `stage.done` | A stage ended. | `stage`, `outcome`, `elapsed_seconds` |
| `section.start` | One section of a stage began. | `stage`, `section` |
| `section.done` | One section of a stage ended. | `stage`, `section`, `outcome`, `elapsed_seconds` |
| `stage.progress` | How far through its own work a stage is. | `stage`, `section`, `done`, `total`, `unit`, `label` |
| `finding.raised` | A judgement was made, carried as it was found. | `finding` |
| `cost.priced` | A cost was worked out. | `cost` |
| `take.charged` | The provider was paid for one take. A free voice writes none. | `section`, `digest`, `characters`, `dollars` |
| `sound.charged` | The sound provider was paid for one request. | `name`, `kind`, `digest`, `seconds`, `dollars` |
| `tool.fetch` | A tool is being downloaded. | `tool`, `bytes`, `total_bytes` |
| `run.log` | One sentence the library would have printed. | `level`, `message`, `source`, `stage`, `section`, `data` |

`outcome` is `ran`, `kept`, `skipped`, `stopped` or `failed`, and it is on `run.done`, `stage.done`
and `section.done`. `kept` is a stage the run planned and did not repeat, because nothing it reads had
changed since it last ran, or a section whose take narrate found on disk. `skipped` is a stage the
run did not plan or did not reach, and `stopped` is a run the caller cancelled or interrupted. One
field replaces four event names, so a caller reads one field rather than branching four ways to learn the
same fact. `unit` on a progress line is `take`, `section`, `asset`, `pass` or `probe`, because narrate
counts takes, record sections, score assets, assemble encoding passes and verify probes, and `level` on a log line is `debug`, `info`, `warning` or `error`.

`run.done` carries `error` in the shape a result's `error` takes when the run stopped or failed, and
null when it finished, so the events file of a failed run says why. A `run.log` line carries `source`,
the module that wrote it such as `media.ffmpeg`, or null for a stage's own sentence, and the `stage`
and `section` it was written in. Its `data` is a flat map of the measured values behind the
sentence, so a reader filters on a value rather than parsing English.

A `finding.raised` line carries the judgement in the same shape the result will carry, so an agent that
watches the stream can react before the call returns.

A `cost.priced` line carries `cost`, the object a result carries, whose `state` is `estimate` before
the run buys anything and `charged` after.
[How the price is worked out](/requirements#how-the-price-is-worked-out) gives each of its fields.

`build/events/` keeps the most recent `events.keep_runs` runs and deletes the oldest, and
that key defaults to 20. Run `decktalk config explain events.keep_runs` for its range. One
file stops taking progress, fetch, debug and info lines once it reaches `events.max_bytes`,
8 MiB by default, and keeps every line about the run, its stages and sections, its findings and its
costs. `run.done` says in `dropped` how many lines were left out, so a reader can tell a bounded
file from a quiet run.

## Watching from Python

Nothing in the library prints, so the stream is how a library caller learns what is happening.
`Machine.events` is the whole stream and `Project.events` is its filtered view.
`events.subscribe(listener, runs=None)` returns a `Subscription`, and the listener receives the same
objects `--events` prints.

```python
import decktalk

project = decktalk.open("my-lesson")
project.events.subscribe(lambda event: print(event.event, getattr(event, "stage", "")))
result = project.build()
for finding in result.findings:
    print(finding.code, finding.location.where, finding.message)
```
